## 작업

### 1. S-01 — 셀 탭 효과음

07-04-05가 만든 셀 탭 핸들러에 한 줄을 더한다. 외부 패키지는 쓰지 않는다(INV-11, N-05).

```dart
import 'package:flutter/services.dart';   // SystemSound, SystemSoundType

void _onCellTap(BuildContext context, PuzzleModel model, int row, int col) {
  HapticFeedback.selectionClick();                                   // H-01 (07-04-05)
  if (context.read<SettingsModel>().soundEnabled) {                  // S-01
    SystemSound.play(SystemSoundType.click);
  }
  model.selectCell(row, col);
}
```

07-04-05가 핸들러를 만들지 않았다면 `PuzzleGridView(onCellTap: …)`에 넘기는 콜백을 `_PuzzleBodyState`의 메서드로 먼저 뽑아낸다. 서명은 `PuzzleGridView.onCellTap`이 요구하는 그대로 둔다.

`soundEnabled`는 `watch`가 아니라 `read`로 읽는다 — 값이 바뀌었다고 퍼즐 화면을 다시 그릴 이유가 없다.

### 2. 라이선스 화면 (N-08 유지)

`SelectableText`를 다른 위젯으로 바꾸지 않는다. 감싸는 것과 `style`만 손댄다.

| 항목 | 값 | 근거 |
|---|---|---|
| 본문 스타일 | `Theme.of(context).textTheme.bodyLarge` | UI-GUIDE 2.4 `body` |
| 패딩 | `EdgeInsets.all(GameSpace.l)` | 2.5 화면 좌우 여백 16 |
| 최대 폭 | `ConstrainedBox(maxWidth: 560)` + 가운데 정렬 | 4절 "본문 최대 폭" |
| 로딩·오류 | 07-07-02의 `GameLoadingView`·`GameEmptyState` | E-11, 4절 |

`SelectableText.data`는 건드리지 않는다. 기존 테스트가 `assets/LICENSES.md` 원문과 글자 단위로 비교한다.
AppBar 제목 `'출처 및 라이선스'`도 그대로다(INV-06b, INV-09).

### 3. 벤치마크 화면

구조·문구는 그대로 두고 색과 스케일만 바꾼다(03-05 임시 화면).

| 지금 | 바꾼 뒤 |
|---|---|
| `TextStyle(color: Colors.red)` / 07-01이 바꾼 `colorScheme.error` | `GameColors.of(context).danger` + `textTheme.bodyLarge` |
| `LinearProgressIndicator(value: …)` | 그대로. 색은 `progressIndicatorTheme`(07-02-03)이 준다 |
| `Text('$_done / $_runsPerLevel')`, `Text(_summaryText(m))` | `textTheme.bodyLarge` |
| `ElevatedButton` | `FilledButton`(07-02-03 `filledButtonTheme`이 알약형 52) |
| `DropdownButton<LevelSpec>` | 그대로. `ColorScheme`이 톤을 준다 |

이 화면에는 `main.dart` 라우트도 진입 지점도 없다 — 코드가 남아 있을 뿐이라 화면 회귀 위험은 없다. 그래도 `lib/ui` 전체에서 옛 톤을 없애는 게 이 문서의 DoD다.

### 4. 스낵바 마감

호출 지점(`HomePage`의 `'이전 레벨을 클리어해야 열립니다'`, `SettingsPage`의 갱신 결과)은 **건드리지 않는다.** `app_theme.dart`에 한 줄만 더한다.

```dart
snackBarTheme: SnackBarThemeData(
  /* 07-02-03이 넣은 backgroundColor: c.ink, contentTextStyle, StadiumBorder, floating */
  insetPadding: const EdgeInsets.fromLTRB(GameSpace.l, GameSpace.s, GameSpace.l, GameSpace.l),
),
```

하단 여백 16 = `GameSpace.l`(UI-GUIDE 4절·2.5). `floating`이라 퍼즐 화면의 제출 버튼 위로 뜬다.

## 테스트 (`settings_screen_test.dart`에 그룹 추가)

`play_loop_test.dart`의 `wrapApp`/`buildScope`(빈 인메모리 DB + `InMemoryWordRepository` + 고정 seed)를 같은 모양으로 이 파일에 복사한다 — `shell_test`·`home_settings_test`·`play_loop_test`가 각자 복사본을 갖는 기존 관례다.

`SystemSound.play`와 `HapticFeedback`은 **같은 채널**(`SystemChannels.platform`)을 탄다. 목 핸들러에서 메서드 이름으로 걸러내고 `tearDown`에서 `null`로 되돌린다.

```dart
final calls = <String>[];
TestDefaultBinaryMessengerBinding.instance.defaultBinaryMessenger
    .setMockMethodCallHandler(SystemChannels.platform, (call) async {
  if (call.method == 'SystemSound.play') calls.add(call.arguments as String);
  return null;
});
addTearDown(() => TestDefaultBinaryMessengerBinding.instance.defaultBinaryMessenger
    .setMockMethodCallHandler(SystemChannels.platform, null));
```

| 테스트 | 기대 |
|---|---|
| S-01 켜짐: 셀 탭 → 소리 1회 | `soundEnabled = true` 후 격자 셀 탭 → `calls == ['SystemSoundType.click']` |
| S-01 꺼짐: 셀 탭 → 소리 0회 | 기본값(false)에서 같은 탭 → `calls`가 비어 있음 |
| S-01 기본값 | 새 `SettingsModel().load()`의 `soundEnabled == false` |

## 막히면

- **웹에서 `SystemSound`가 예외** → 보통 no-op이다. 예외가 나면 `kIsWeb` 분기로 감싼다(`foundation.dart`). try/catch로 삼키지 않는다 — 원인을 가린다.
- **소리가 안 남(실기기)** → Android `SystemSoundType.click`은 기기의 터치음 설정을 따른다. 그래서 설정 항목 subtitle이 `'기기의 터치음 설정을 따릅니다'`(07-07-03)다. 코드 문제가 아니다.
- **목 핸들러를 걸었더니 다른 테스트가 깨짐** → `SystemChannels.platform`은 `SystemChrome`·`Clipboard`·`HapticFeedback`도 쓴다. 핸들러가 `SystemSound.play`만 기록하고 나머지는 `null`을 돌려주는지, `tearDown`에서 해제하는지 확인한다.
- **라이선스 테스트가 문구 불일치로 실패** → `SelectableText`를 감싸면서 `data`에 `trim()`이나 문자열 보간이 끼었다. 원문을 그대로 넘긴다.
- **`ElevatedButton` → `FilledButton` 교체 후 벤치마크 레이아웃 깨짐** → 버튼 높이가 52로 커진 것이다. 임시 화면이라 세로 간격만 `GameSpace.m`으로 맞춘다.
