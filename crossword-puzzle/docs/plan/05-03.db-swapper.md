# 05-03. 통계 보존 · 원자 교체 (db_swapper)

담당: **AGENT**
선행: 05-02 · 다음: 05-04
상위: [05-sync.md](05-sync.md) 동작 흐름 뒷부분

## 목표

새 DB로 갈아끼우되 **유저 통계를 한 줄도 잃지 않는다.**
DESIGN 4절의 핵심 설계("`word_stat`은 건드리지 않음")가 여기서 실현된다.

> 사전사가 ID를 재발급해도 유저 기록 안 날아감

## 보존 대상

| 테이블 | 보존 | 이유 |
|---|---|---|
| `word_stat` | ✓ | 유저의 정답/오답 기록 |
| `puzzle_log` | ✓ | 첫 제출 판정(03-04). 안 지키면 재제출이 이중 집계 |
| `word`, `sense`, `word_char`, `meta` | ✗ | 새 DB 것을 쓴다 |

**`puzzle_log` 를 빠뜨리기 쉽다.** 03-04에서 추가한 테이블이므로 이 목록에 반드시 넣는다.

### 새 DB에 없는 단어의 통계

> `headword` 기준. 새 DB에 없는 단어의 stat도 보존

사전 갱신으로 표제어가 빠질 수 있다. 그 단어의 통계를 지우면
나중에 다시 등재됐을 때 기록이 사라진다. **`word` 에 없어도 `word_stat` 행은 남긴다.**

`word_stat.headword` 에 FK가 걸려 있지 않으므로(02-09 스키마) 그냥 들어간다.

## 흐름

```
1. 새 DB 파일(tmp)에 ATTACH로 기존 DB를 붙인다
2. 기존 DB의 word_stat, puzzle_log를 새 DB로 복사
3. DETACH
4. 앱의 기존 DB 연결을 닫는다
5. tmp → words.sqlite 로 rename (원자적)
6. 새 경로로 DB를 다시 연다
```

**복사를 새 DB 쪽에서 한다.** 기존 DB에 ATTACH해서 쓰면 기존 파일을 건드리게 되고,
중간에 실패하면 기존 DB가 손상된다.

## 구현

```dart
// app/lib/data/sync/db_swapper.dart
import 'dart:io';
import 'package:drift/drift.dart';
import 'package:drift/native.dart';

class DbSwapper {
  final AppDatabase Function(File) _open;   // 주입: 테스트 용이성
  final File currentFile;

  static const _preserved = ['word_stat', 'puzzle_log'];

  /// [newDb] 는 검증이 끝난 임시 파일 (05-02).
  /// 성공하면 새로 연 AppDatabase를 반환한다.
  Future<AppDatabase> swap(AppDatabase current, File newDb) async {
    // 1~3. 새 DB에 기존 것을 붙여 통계를 복사
    await _copyStats(newDb, currentFile);

    // 4. 기존 연결을 닫는다. 이걸 안 하면 rename이 실패할 수 있다
    await current.close();

    // 5. 원자 교체
    final backup = File('${currentFile.path}.bak');
    if (await backup.exists()) await backup.delete();
    if (await currentFile.exists()) {
      await currentFile.rename(backup.path);      // 기존 것을 백업으로
    }
    try {
      await newDb.rename(currentFile.path);
    } catch (e) {
      // 롤백: 백업을 되돌린다
      if (await backup.exists()) await backup.rename(currentFile.path);
      rethrow;
    }

    // 6. 새 DB를 연다
    final next = _open(currentFile);
    await next.wordCount;          // 열리는지 즉시 확인

    // 성공했으니 백업 삭제. 실패해도 무해하므로 예외를 삼킨다
    try { if (await backup.exists()) await backup.delete(); } catch (_) {}

    return next;
  }

  Future<void> _copyStats(File target, File source) async {
    final db = AppDatabase(NativeDatabase(target));
    try {
      await db.customStatement(
          "ATTACH DATABASE ? AS old", [source.path]);
      try {
        for (final t in _preserved) {
          // 기존 DB에 그 테이블이 없을 수도 있다 (구 버전에서 올라온 경우)
          final exists = await db.customSelect(
            "SELECT 1 FROM old.sqlite_master WHERE type='table' AND name=?",
            variables: [Variable.withString(t)]).getSingleOrNull();
          if (exists == null) continue;

          await db.customStatement('DELETE FROM main.$t');
          await db.customStatement(
              'INSERT INTO main.$t SELECT * FROM old.$t');
        }
      } finally {
        await db.customStatement('DETACH DATABASE old');
      }
    } finally {
      await db.close();
    }
  }
}
```

### `INSERT ... SELECT *` 의 위험

컬럼 순서가 두 DB에서 같아야 한다. 스키마 버전이 같다는 건 이미 확인했으므로(05-02)
안전하지만, **명시적 컬럼 목록**을 쓰는 게 더 견고하다:

```sql
INSERT INTO main.word_stat (headword, correct, wrong, last_seen)
SELECT headword, correct, wrong, last_seen FROM old.word_stat
```

컬럼을 추가할 때 이 코드도 고쳐야 하지만, 조용히 어긋나는 것보다 낫다.
**`tools/schema.sql` 을 고치면 여기 컬럼 목록도 고친다** (PLAN.md 3절 계약).

### `DELETE FROM main.word_stat` 먼저

새 DB의 `word_stat` 은 ETL이 만든 **빈 테이블**이다(02-09). 그래도 `DELETE` 를 먼저 하는 이유:
릴리스 스크립트의 `verify`(05-01)를 우회한 오염된 DB가 왔을 때를 대비한다.

### `rename` 이 원자적인 조건

같은 파일시스템 안이어야 한다. 임시 파일을 **앱 문서 디렉터리 안**에 만들면 보장된다(05-02).
`Directory.systemTemp` 를 쓰면 다른 파티션일 수 있어 `rename` 이 복사+삭제가 된다.

### 백업 파일

`rename` 사이에 앱이 죽으면 `words.sqlite` 가 없고 `.bak` 만 남는다.
**다음 실행의 부트스트랩(03-02)이 이걸 복구해야 한다:**

```dart
// open_native.dart에 추가
if (!await file.exists()) {
  final backup = File('${file.path}.bak');
  if (await backup.exists()) {
    await backup.rename(file.path);     // 교체 중 죽은 흔적 복구
  } else {
    await _copySeed(file);
  }
}
```

**03-02 문서에 이 내용을 역으로 반영한다.**

## 막히면

- **`rename` 이 "file in use" 로 실패** → 기존 DB 연결이 안 닫혔다. `current.close()` 를 `await` 했는지, 05-02의 sanity check probe도 닫았는지 확인.
- **`ATTACH` 가 실패** → 경로에 한글·공백이 있으면 따옴표 처리가 필요하다. 파라미터 바인딩(`?`)을 쓰면 해결된다. 위 코드가 그렇게 한다.
- **통계가 일부만 복사됨** → `DELETE` 후 `INSERT` 순서 확인. `INSERT OR IGNORE` 를 쓰면 PK 충돌로 조용히 버려진다. 쓰지 않는다.
- **교체 후 앱이 크래시** → 새 DB 연결 후 `wordCount` 를 확인하는 코드가 있는지 본다. 열자마자 검증해야 문제를 조기에 잡는다.
- **`.bak` 이 계속 쌓임** → 성공 후 삭제가 예외로 건너뛰어졌다. 무해하지만 용량을 먹는다. 부트스트랩에서 `words.sqlite` 가 정상이면 `.bak` 을 지우는 정리 코드를 넣는다.
