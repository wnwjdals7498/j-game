# 04-04. 단어 입력 (한국어 IME)

담당: **AGENT** (IME 검증은 04-07에서 HUMAN)
선행: 04-03 · 다음: 04-05
상위: [04-ui.md](04-ui.md) "입력", "기술 결정 — IME"

## 목표

한국어 IME로 단어를 입력받아 격자 셀에 분배한다.
**4단계의 주요 기술 리스크** (REVIEW 4.3: "한국어 IME 입력").

## 핵심 결정 — 격자에 직접 타이핑하지 않는다

> 격자 셀에 직접 타이핑하는 방식은 **하지 않는다.** 조합 중 상태(ㄱ→가→각) 처리가 까다롭고
> 기기별 편차가 크다. 화면 하단 텍스트 필드 1개로 단어 전체를 받는 방식이 안전.

이유를 구체적으로:

1. 한글 IME는 **조합 중(composing) 상태**를 가진다. `ㄱ` → `가` → `각` 이 한 글자 자리에서 변한다.
2. 셀마다 `TextField` 를 두면 조합이 끝나기 전에 다음 셀로 넘길 수 없다.
3. 삼성 키보드와 Gboard의 조합 커밋 타이밍이 다르다.
4. `maxLength` 가 조합 중 글자를 어떻게 세는지도 기기마다 다르다.

**하단 텍스트 필드 1개**에 단어 전체를 받고, 확정된 음절만 격자에 분배한다.

## 입력 흐름

```
단어 선택 (04-03)
  └→ 하단 입력 필드에 포커스, 기존 입력값 로드
  └→ 유저 타이핑 (IME 조합 진행)
  └→ onChanged: 확정된 음절만 격자에 반영
  └→ 길이 초과 입력 차단
  └→ 다음 단어 선택 시 현재 입력 확정
```

## 구현

```dart
// app/lib/ui/puzzle/word_input.dart
class WordInput extends StatefulWidget {
  final PlacedWord? selected;
  final String initialText;
  final void Function(String) onChanged;
  final VoidCallback onNext;      // "다음" 버튼
}

class _WordInputState extends State<WordInput> {
  final _controller = TextEditingController();

  @override
  void didUpdateWidget(WordInput old) {
    super.didUpdateWidget(old);
    if (widget.selected != old.selected) {
      // 선택이 바뀌면 필드를 새 단어의 현재 입력으로 교체
      _controller.text = widget.initialText;
      _controller.selection = TextSelection.collapsed(
          offset: _controller.text.length);
    }
  }

  @override
  Widget build(BuildContext context) {
    final len = widget.selected?.length ?? 0;
    return TextField(
      controller: _controller,
      enabled: widget.selected != null,
      autofocus: false,
      maxLength: len,
      // maxLengthEnforcement는 조합 중 글자 처리가 기기마다 다르다.
      // 우리가 직접 자른다.
      maxLengthEnforcement: MaxLengthEnforcement.none,
      textInputAction: TextInputAction.next,
      onChanged: _handle,
      onSubmitted: (_) => widget.onNext(),
      decoration: InputDecoration(
        counterText: '${_committed(_controller.text).length} / $len',
        hintText: widget.selected == null ? '칸을 눌러 단어를 고르세요' : null,
      ),
    );
  }

  void _handle(String raw) {
    final len = widget.selected?.length ?? 0;
    var s = _committed(raw);
    if (s.length > len) {
      s = s.substring(0, len);
      _controller.text = s;
      _controller.selection = TextSelection.collapsed(offset: s.length);
    }
    widget.onChanged(s);
  }
}
```

### `_committed` — 확정 음절만 남기기

```dart
/// 완성형 한글 음절만 남긴다. 조합 중인 자모(ㄱ, ㅏ 등)와 그 외 문자는 버린다.
String _committed(String raw) {
  final buf = StringBuffer();
  for (final ch in raw.characters) {
    final code = ch.runes.first;
    if (code >= 0xAC00 && code <= 0xD7A3) buf.write(ch);
  }
  return buf.toString();
}
```

**이게 IME 문제를 푸는 핵심이다.**

- 조합 중 자모(`ㄱ` U+3131, `ㅏ` U+314F)는 완성형 범위 밖 → 자동으로 걸러진다
- 영문·숫자·공백도 걸러진다
- 조합이 끝나 `각` 이 되면 그때 격자에 반영된다

`package:characters` 의 `.characters` 를 쓰는 이유: 이모지 등 서로게이트 페어를 안전하게 순회.

**주의**: 조합 중에도 마지막 글자가 완성형일 수 있다 (`가` 를 치는 중 → `가` 는 완성형).
그래서 격자에 `가` 가 보였다가 `각` 으로 바뀐다. **이건 정상이고 오히려 피드백이 좋다.**

### 길이 제한을 직접 자르는 이유

> 텍스트 필드 `maxLength` 가 조합 중 글자를 어떻게 세는지 기기별 확인 필요 (04-ui 리스크)

`MaxLengthEnforcement` 를 끄고 `_handle` 에서 확정 음절 기준으로 자른다.
조합 중 자모는 길이에 안 세므로 기기별 편차가 사라진다.

## 격자에 분배

```dart
// PuzzleModel
void setWordInput(PlacedWord w, String text) {
  final next = Map<(int, int), String>.of(answers);   // 새 맵 (04-02 shouldRepaint)
  var i = 0;
  for (final (r, c) in w.cells) {
    if (i < text.length) {
      next[(r, c)] = text[i];
    } else {
      next.remove((r, c));      // 지운 만큼 비운다
    }
    i++;
  }
  answers
    ..clear()
    ..addAll(next);
  notifyListeners();
}

/// 선택된 단어의 현재 입력을 텍스트로 복원 (선택 전환 시)
String textOf(PlacedWord w) {
  final buf = StringBuffer();
  for (final (r, c) in w.cells) {
    final s = answers[(r, c)];
    if (s == null || s.isEmpty) break;   // 중간이 비면 거기까지
    buf.write(s);
  }
  return buf.toString();
}
```

### 교차 셀 — 마지막 입력이 이긴다

> 교차 셀에 이미 다른 단어가 넣은 글자가 있으면 덮어쓴다(마지막 입력 우선).

위 `setWordInput` 이 그대로 덮어쓴다. 별도 처리 불필요.
다만 **덮어쓴 뒤 다른 단어를 선택하면** 그 단어의 텍스트가 바뀌어 보인다. 의도된 동작이다.

### 부분 입력 허용

> **부분 입력 허용**(일부 셀만 채움 → 그 단어는 채점 시 오답).

`textOf` 가 중간에서 끊는 이유: `사_과` 처럼 가운데가 빈 상태를 텍스트 필드로 표현할 수 없다.
앞에서부터 연속된 부분만 필드에 싣고, 나머지는 격자에만 남는다.

교차로 뒷부분이 채워진 경우(`__나무` 에서 `나`, `무` 가 교차로 채워짐)에는
필드가 비어 보이지만 격자에는 글자가 있다. **혼란스러울 수 있으므로** 대안:

```dart
/// 빈 칸을 공백으로 채워 전체 길이를 유지
String textOf(PlacedWord w) => [
  for (final (r, c) in w.cells) (answers[(r, c)] ?? ' ')
].join().trimRight();
```

공백이 섞이면 `_committed` 가 걸러 버려 입력이 꼬인다.
**1차는 "앞에서부터 연속" 방식(첫 번째)을 쓰고, 04-07 수동 테스트에서 혼란스러우면 재검토**한다.

## 다음 단어로 이동

입력 필드의 `TextInputAction.next` 와 "다음" 버튼:

```dart
void selectNextWord() {
  if (puzzle == null) return;
  final order = puzzle!.words;   // 번호 순 (04-03 numberCells 순서)
  final i = order.indexWhere((w) => _same(w, selected));
  selected = order[(i + 1) % order.length];
  notifyListeners();
}
```

빈 단어만 순회하는 옵션도 좋지만 1차는 단순 순환으로 한다.

## 막히면

- **조합 중 글자가 격자에 안 보임** → 정상이다. 완성형이 되면 나타난다. 답답하면 조합 중 자모도 **격자에만** 회색으로 표시하는 방법이 있지만, 상태가 복잡해지므로 1차는 하지 않는다.
- **글자를 지워도 격자가 안 비워짐** → `setWordInput` 의 `else { next.remove(...) }` 누락.
- **교차 단어를 오가면 글자가 사라짐** → `textOf` 가 중간 빈 칸에서 끊어서다. 위 "부분 입력 허용" 절의 대안을 검토.
- **커서가 맨 앞으로 튐** → `_controller.text = s` 직후 `selection` 을 설정하지 않았다. 항상 같이 설정한다.
- **기기에서 입력이 씹힘** → 04-07의 IME 수동 테스트에서 재현 조건을 기록하고, 필요하면 `onChanged` 대신 `TextEditingController.addListener` 로 바꿔 본다.
