## 목표

실행기가 "통과한다"가 아니라 "**위반을 실제로 잡는다**"를 증명한다. 규칙을 잘못 구현해 아무것도 못 잡는 스크립트는 통과 표시만 찍는 장식이 된다. 부모 문서 표의 8종을 fixture 파일 단위까지 확정한다.

## 컨텍스트 (시작 전 읽기)

- `app/tool/invariants/runner.dart` — `runInvariants(Directory root, {String? gitBase})`, `InvariantReport.byId`
- `app/test/domain/measure_test.dart` 1~7줄 — 이 저장소의 테스트 import 관례. `package:test/test.dart`를 쓰고 대상 로직은 `package:jgame/...`로 가져온다. **`tool/` 코드를 import하는 기존 테스트는 없다** — 이 문서가 첫 사례다
- `app/analysis_options.yaml` — `analyzer: exclude:`에 fixture 디렉터리를 추가해야 한다
- `app/pubspec.yaml` 68~80줄 — `dev_dependencies:`에 `test: ^1.25.0`이 이미 있다(추가 의존성 없음, INV-11 안전)

## 작업

### 1. fixture는 평평하게, 배치는 임시 디렉터리로

fixture 파일 이름은 위 목록처럼 **평평하고 구분되는 이름**으로 둔다. 규칙이 보는 경로(`lib/ui/x.dart`, `pubspec.yaml`)에는 테스트가 임시 디렉터리로 옮겨 놓는다. 저장소 안에 두 번째 `pubspec.yaml`을 만들지 않기 위해서다 — 중첩 `pubspec.yaml`은 분석기에 패키지 경계로 보인다.

```dart
/// fixture 내용을 root 기준 경로에 심은 임시 디렉터리를 만든다.
/// {'lib/ui/bad.dart': 'hardcoded_color.dart'} → <temp>/lib/ui/bad.dart
Directory stage(Map<String, String> layout) {
  final root = Directory.systemTemp.createTempSync('inv');
  addTearDown(() => root.deleteSync(recursive: true));
  layout.forEach((dest, fixture) {
    final f = File('${root.path}/$dest')..parent.createSync(recursive: true);
    f.writeAsStringSync(
        File('test/tool/fixtures/violations/$fixture').readAsStringSync());
  });
  return root;
}
```

경로에 없는 파일은 실행기가 건너뛰므로(07-01-02 작업 2), fixture 루트에는 **그 규칙이 보는 파일만** 두면 된다. 나머지 규칙은 needle을 못 찾아 FAIL이 나지만 테스트는 `report.byId('INV-05')`처럼 **해당 ID만** 단정한다.

### 2. `analysis_options.yaml`에 fixture 제외

```yaml
analyzer:
  exclude:
    - build/**
    - android/**
    - web/**
    - test/tool/fixtures/**
```

fixture는 일부러 잘못된 코드다(`width: 9`인 레벨 사본, 의존성이 빠진 pubspec). 분석기에 넣으면 `flutter analyze` 0을 못 맞춘다. 어디서도 import하지 않으므로 제외해도 컴파일에 영향이 없다.

### 3. fixture 내용

| 파일 | 내용 |
|---|---|
| `hardcoded_color.dart` | `const a = TextStyle(color: Colors.red);` + `const b = TextStyle(color: Color(0xFF00FF00));` (2줄 위반) |
| `transparent_ok.dart` | `const a = TextStyle(color: Colors.transparent);` 만 |
| `comment_only.dart` | `// const a = TextStyle(color: Colors.red);` 만 |
| `missing_test_name.dart` | `protectedTests` 24개 중 **`'완성형만: 조합 중 자모를 버린다'` 하나만 뺀** `testWidgets('...', (t) async {});` 나열 |
| `pubspec_extra_dep.yaml` | 실제 `pubspec.yaml` 사본 + `dependencies:` 안에 `  lottie: ^3.0.0` |
| `pubspec_missing_dep.yaml` | 실제 `pubspec.yaml` 사본 − `provider:` 2줄 |
| `levels_over_max.dart` | `width: 9`·`height: 9` 한 쌍을 포함하는 최소 사본 |

두 pubspec fixture는 실제 파일에서 복사한다. 손으로 쓰면 13개 이름이 어긋나 엉뚱한 이유로 통과·실패한다.

### 4. `test/tool/check_invariants_test.dart`

```dart
import 'dart:io';

import 'package:test/test.dart';

import '../../tool/invariants/runner.dart';
```

`tool/`은 `lib/` 밖이라 `package:jgame/...`로 못 가져온다. 테스트 파일도 `lib/` 밖이므로 **상대 경로 import가 허용된다.** 이 저장소에 전례가 없으니(`measure_test.dart`는 로직이 `lib/`에 있어 `package:` import를 쓴다) 이 import 한 줄이 컴파일되는지를 가장 먼저 확인한다.

| 테스트 이름 | 배치 | 단정 |
|---|---|---|
| `하드코딩 색 검출: 파일:줄이 전부 나온다` | `lib/ui/bad.dart` ← `hardcoded_color.dart` | `byId('INV-05').status == fail`, `findings.length == 2`, 첫 Finding의 `path`가 `lib/ui/bad.dart` |
| `Colors.transparent는 허용` | `lib/ui/ok.dart` ← `transparent_ok.dart` | `byId('INV-05').status == pass` |
| `주석 줄은 무시` | `lib/ui/ok.dart` ← `comment_only.dart` | `byId('INV-05').status == pass` |
| `보호 테스트 누락 검출` | `test/x_test.dart` ← `missing_test_name.dart` | `byId('INV-08').status == fail`, Finding `detail`에 `완성형만` 포함 |
| `의존성 추가 검출` | `pubspec.yaml` ← `pubspec_extra_dep.yaml` | `byId('INV-11').status == fail`, detail에 `lottie` |
| `의존성 제거 검출` | `pubspec.yaml` ← `pubspec_missing_dep.yaml` | `byId('INV-11').status == fail`, detail에 `provider` |
| `격자 상한 초과 검출` | `lib/domain/levels.dart` ← `levels_over_max.dart` | `byId('INV-10').status == fail`, detail에 `9` |
| `실제 저장소: 전부 PASS 또는 SKIP` | `Directory.current` | `report.ok == true`, `byId('INV-07').status == skip` |

마지막 테스트의 `Directory.current`는 `flutter test` 실행 시 패키지 루트(`app/`)다. `stage`의 `test/tool/fixtures/...` 상대 경로도 같은 기준이라 별도 처리가 필요 없다.

## 막히면

- **`import '../../tool/invariants/runner.dart'`가 컴파일 안 됨** → 부모 문서 "막히면"의 대안으로 넘어간다. 실행기만 `lib/tooling/invariants_runner.dart`로 옮기고(Flutter 의존 없이 `dart:io`만), `tool/check_invariants.dart`가 `package:jgame/tooling/invariants_runner.dart`를 import한다. 이 경우 `rules.dart`의 INV-05 `exclude`에 `lib/tooling/`을 넣고 07-01-01 산출물 경로를 함께 고친다. `measure.dart`(얇은 `main`) + `lib/domain/measure/measure_runner.dart`(로직)가 이 저장소의 실제 관례이기도 하다.
- **fixture 임시 디렉터리 삭제 실패(Windows)** → 파일 핸들이 열려 있다. `addTearDown`에서 `try { ... } catch (_) {}`로 감싼다. 임시 디렉터리 누수는 테스트를 깨지 않는다.
- **`실제 저장소` 테스트가 FAIL** → fixture 문제가 아니라 진짜 위반이다. `dart run tool/check_invariants.dart` 출력을 그대로 읽고 코드를 고친다. 규칙을 느슨하게 만들지 않는다.
- **`flutter analyze`가 fixture를 물고 늘어짐** → 작업 2의 `exclude`가 빠졌거나 경로가 틀렸다. `test/tool/fixtures/**`는 `app/` 기준 상대 경로다.
- **부모 문서 산출물이 "위반 예시 파일 4개"라고 함** → 같은 문서 DoD는 "위반 fixture 7종"이다. 표의 8행(마지막은 실제 저장소라 fixture 없음)을 기준으로 7개가 맞다.
