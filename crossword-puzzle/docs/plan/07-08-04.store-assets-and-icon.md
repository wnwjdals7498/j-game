## 작업

### 1. 현재 상태 — 저장소를 읽어 확인한 값

| 항목 | 현재 값 | 새 톤(UI-GUIDE)과의 관계 |
|---|---|---|
| 원본 | `asset/icon/Codex 이미지 2026년 9월 18일 오후 01_04_53.png` (1254×1254) | 격자 4칸 + "가나다" + 잎사귀, 파란 배경 |
| 가공본 | `app/assets/icon/icon.png` (1024×1024, 알파 없음) | — |
| 적응형 foreground | `app/assets/icon/icon_foreground.png` (원본 64% 축소, 투명 캔버스) | 안전 영역 중앙 66% 충족 |
| `adaptive_icon_background` | `#08A2FB` | **토큰에 없는 색.** UI-GUIDE 2.2 어디에도 파랑이 없다 |
| `flutter_native_splash.color` / `color_dark` | `#FFFFFF` / `#121212` | `surface` 라이트·다크와 **일치** |
| 스플래시 이미지 | `assets/icon/icon_foreground.png` 재사용 | 아이콘을 바꾸면 스플래시도 같이 바뀐다 |

스플래시 두 색은 이미 토큰과 맞다. **어긋나는 것은 아이콘 배경 `#08A2FB` 하나다.**

| # | 질문 | 재도색 쪽 근거 | 유지 쪽 근거 |
|---|---|---|---|
| 1 | 런처 아이콘과 앱 첫 화면이 같은 브랜드로 읽히는가 | 07-08-03에서 런처와 홈 화면을 나란히 본 인상 | — |
| 2 | 스토어 아이콘·피처 그래픽·스크린샷이 한 톤인가 | 스크린샷은 흑백+노랑, 아이콘만 파랑 | — |

판단 기준 한 줄: **"파랑 아이콘을 눌러 열었을 때 다른 앱이 열린 것 같으면 채택한다."**
채택이면 3~5절을 하고, 유지면 건너뛰어 6절부터 한다. 어느 쪽이든 결정을 리포트에 남긴다.


### 3. 채택 시 — 원본 생성·가공

프롬프트 원문은 [07-08-05.image-prompts.md](07-08-05.image-prompts.md) B절의 **IMG-01**·**IMG-01F**를 쓴다(스플래시용 **IMG-01S**는 아래 4절 참고). 이 문서에 옮겨 적지 않는다.

| 프롬프트 | 원본 → 가공본 | 검사 |
|---|---|---|
| IMG-01 | `asset/icon/` → `app/assets/icon/icon.png` | 1024×1024, **알파 없음**. Play는 투명 아이콘을 거부한다(06-01 D절) |
| IMG-01F | `asset/icon/` → `app/assets/icon/icon_foreground.png` | 1024×1024, **알파 있음**. 내용이 중앙 66% 안 |

원본은 `asset/icon/`에, 가공본은 `app/assets/icon/`에 둔다(UI-GUIDE 5절 관례). 가공본 **파일명은 바꾸지 않는다** — `pubspec.yaml`이 그 이름을 가리킨다.
생성 결과의 색이 UI-GUIDE 2.2와 어긋나면 **이미지를 손보지 말고 다시 생성한다**(UI-GUIDE 5절 마지막 줄). 확인할 색은 배경 `#F5F5F3`, 선·검은 칸 `#121212`, 강조 `#FFDA00`, 보조 `#A7D8FF` 넷이다. 나머지 검수는 07-08-05 E절 체크리스트를 쓴다.

### 4. 채택 시 — `pubspec.yaml`과 생성

한 줄만 바꾼다.

```diff
 flutter_launcher_icons:
-  adaptive_icon_background: "#08A2FB"
+  adaptive_icon_background: "#F5F5F3"      # UI-GUIDE 2.2 surfaceAlt
```

`flutter_native_splash`의 `color`·`color_dark`는 **건드리지 않는다.** 1절 표대로 이미 `surface` 라이트·다크와 같다.
스플래시 이미지는 기본적으로도 손댈 필요가 없다 — 지금 `icon_foreground.png`를 재사용하므로 새 foreground가 자동 반영된다. 07-08-05의 **IMG-01S**로 전용 이미지를 따로 만든 경우에만 `image`·`android_12.image` 두 곳을 `assets/icon/splash.png`로 바꾼다. 만들지 않았으면 06-01 E절의 재사용 결정을 그대로 둔다.

```powershell
cd app
dart run flutter_launcher_icons
dart run flutter_native_splash:create
```

- `dependencies:`에 아무것도 추가하지 않는다 — 두 생성기는 이미 `dev_dependencies`에 있다(INV-11).
- `assets/icon/`을 `flutter: assets:`에 **넣지 않는다**(06-01 D절). 지금 `pubspec.yaml`은 `assets/LICENSES.md`·`assets/words.sqlite`만 나열한다. 그대로 둔다.

### 5. 채택 시 — 확인과 문서 반영

```powershell
cd app
flutter build apk --debug
aapt dump badging build/app/outputs/flutter-apk/app-debug.apk | Select-String "application-icon"
```

`res/mipmap-anydpi-v26/ic_launcher.xml`(적응형 XML)을 가리켜야 한다. 그 뒤 실기기에 설치해 원형·사각·둥근사각 마스크에서 잘리지 않는지 본다.
06-01 D·E절 끝에 재도색 사실을 한 단락 덧붙인다 — **옛 구현 메모는 지우지 않는다.** 06-04 A절의 "앱 아이콘 512×512"를 새 원본에서 다시 축소해야 한다는 사실도 06-04에 한 줄 남긴다(작업 자체는 06-04 시점).

### 6. IMG-03 스크린샷 3장 (HUMAN)

**AI로 만들지 않는다**(UI-GUIDE 5절 IMG-03). 07-08-03의 기기 A에서 직접 찍는다.
조건: **릴리스 빌드**(06-04 A절 — 디버그 UI·벤치마크 화면이 보이면 안 된다), 라이트 테마, 9:16 세로, 최소 320px·최대 3840px.

```powershell

adb pull /sdcard/shot.png ./store/screenshots/01-puzzle.png
```

|---|---|---|

찍기 전 확인: 디버그 배너 없음, 벤치마크 화면 없음, 격자·힌트에 비속어 없음(06-04 "막히면").

### 7. IMG-02 피처 그래픽 — 여기서는 하지 않는다

1024×500 피처 그래픽은 **06-04 갱신 시점** 작업이다(UI-GUIDE 5절 "06-04 갱신 시"). 여기서는 [07-08-05.image-prompts.md](07-08-05.image-prompts.md)의 IMG-02 항목이 새 톤과 맞는지 읽어 보는 것까지만 한다 — 배경이 흰색인가, 강조가 `#FFDA00`·`#A7D8FF` 둘뿐인가, 앱 이름이 06-01에서 확정한 이름과 같은가.

### 8. APK 크기 기록

폰트 3종이 들어간 뒤 얼마나 커졌는지 남긴다. 06-03 C절의 예상 구성이 기준선이다.

| 항목 | 06-03 기준 | 7단계 후 |
|---|---|---|
| `assets/words.sqlite` / 엔진(ABI당) | ~10 MB / ~7 MB | 변화 없음(N-06: data 계층 무수정) |
| Dart 코드 (AOT) | ~3 MB | |
| 폰트 Pretendard 3종 | 없었음 | **+4~5 MB 까지만 허용** |
| 릴리스 APK 합계 | — | |

허용치를 넘으면 UI-GUIDE 2.4의 대안(Noto Sans KR 2종 400/700)을 07-02로 되돌려 검토한다. 이 문서에서 폰트를 임의로 빼지 않는다. 결과는 리포트 "APK 크기" 절에 적는다.

## 막히면

- **`--git-base master`가 INV-07 위반을 잡는다** → `git diff --name-only master -- app/lib/domain app/lib/data`로 파일을 찾아 그 변경을 `lib/ui/state/*Model`로 옮긴다. 예외를 만들지 않는다.
- **`flutter build apk --release`가 서명 때문에 실패** → 06-02(키스토어, HUMAN)가 아직이다. 디버그 서명으로 크기만 재고 리포트에 "서명 전 측정"이라고 적는다(`--debug`는 크기가 달라 기준이 안 된다). 06-02 후 다시 잰다.
- **빌드가 `IllegalArgumentException: ... different roots`로 죽는다** → 06-01 "구현 메모"의 환경 문제(프로젝트 `D:`, pub-cache `C:`)다. `android/gradle.properties`에 `kotlin.incremental=false`가 있는지 확인한다.
- **생성한 아이콘 색이 토큰과 미묘하게 다름** → 편집기로 칠하지 말고 다시 생성한다(UI-GUIDE 5절). 두 번 더 시도해도 어긋나면 **유지**로 결정을 뒤집고 리포트에 남긴다.
- **적응형 아이콘이 런처에서 잘림** → foreground가 안전 영역(중앙 66%)을 넘었다. 축소 비율을 06-01이 쓴 64%로 되돌린다.
- **APK가 기준선보다 훨씬 큼** → `flutter build apk --release --analyze-size --target-platform android-arm64`로 상위 항목을 본다. `assets/icon/`이 번들에 딸려 들어갔는지 먼저 의심한다(06-01이 명시적으로 금지한 것).
