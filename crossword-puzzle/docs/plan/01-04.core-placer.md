# 01-04. 코어 배치 (core_placer)

담당: **AGENT**
선행: 01-03 · 다음: 01-05
상위: [01-domain-map-generator.md](01-domain-map-generator.md) 알고리즘 1번

## 목표

레벨 스펙의 코어 단어 `coreCount` 개를 격자에 **서로 교차하도록** 배치한다.
코어는 "유저가 약한 단어"라 반드시 다 들어가야 한다. 채움과 달리 타협 없음.

## 컨텍스트

- 01-01 (`LevelSpec`, `PlacedWord`), 01-02 (`WordRepository.coreCandidates`), 01-03 (`GridRules`, `MutableGrid`)

## 알고리즘

```
coreCandidates(tier, count, seed) 로 후보 리스트 C 획득 (count*4개쯤)
C를 Random(seed)로 셔플하지 않는다 — 이미 통계순. 앞에서부터 쓴다.

1. 첫 코어: C[0]부터 시도.
   격자 중앙 근처 가로로 배치. 시작 열 = (width - len) ~/ 2, 행 = height ~/ 2.
   canPlace 실패하면 중앙에서 가까운 순으로 다른 (행,열) 시도.
   전부 실패 → C[1]로 교체.

2. 2번째 이후 코어: 이미 놓인 단어와 **공유 음절**이 있는 교차 위치를 우선.
   for 후보 w in C (아직 안 쓴 것):
     교차 후보 위치 목록 만들기:
       for 놓인 단어 p, p의 각 셀 (r,c)와 음절 s:
         for w에서 s가 나오는 index i:
           w를 p와 수직인 방향으로 놓되, i번째 음절이 (r,c)에 오도록 시작점 계산
           canPlace 확인
     위치 목록을 Random(seed)로 셔플 → 첫 번째로 되는 것 배치
     성공하면 다음 코어로

3. 교차 위치가 하나도 없는 코어:
   allowIsolated 이고 아직 고립 슬롯을 안 썼으면
     격자에서 canPlace 되는 아무 위치(셔플된 순서로)에 배치 → isolatedUsed = true
   아니면 다음 후보로 교체

4. 후보 C를 다 써도 coreCount를 못 채우면 실패 (null 반환)
```

**결정성**: 모든 셔플은 호출자가 넘긴 `Random` 인스턴스 하나만 쓴다. 새 `Random()` 을 만들지 않는다.

### 배치 확정 전 규칙 5 확인 (01-04 구현 중 발견)

2·3번의 "첫 번째로 되는 것 배치"에서 **되는 것**은 `canPlace` 통과만으로 부족하다.
고립 슬롯을 한 번만 쓰므로 연결 요소는 항상 2개 이하지만, **고립 단어에 뒤 코어가 교차하면**
연결 요소 2개 × 크기 2가 되어 규칙 5("2개면 둘 중 하나는 단어 1개")가 깨진다.

예) 후보 `[사과, 사자, 무기, 기차]`, `coreCount: 4` —
`사과`·`사자`는 `사`로 교차하고, `무기`는 공유 음절이 없어 고립 슬롯으로 들어간다.
`기차`는 `기`를 `무기`와만 공유하므로 거기 붙으면 `{사과,사자}`·`{무기,기차}` 두 덩어리가 된다.
`canPlace` 는 이걸 못 막는다(규칙 5는 격자가 아니라 단어 그래프 규칙이라 `validate` 담당).
가드 없이 돌리면 `place` 가 성공을 내고 `validate` 가 `['고립 요소 크기가 2 (1이어야 함)']` 를 낸다.

그래서 후보를 하나 놓을 때마다 `GridRules.components` 로 규칙 5를 확인하고,
깨지면 `unplace` 로 되돌려 다음 후보로 넘어간다. 끝까지 못 놓으면 그 코어는 실패 →
후보 교체 → 그래도 못 채우면 `null`(위 4번). 공개 시그니처는 그대로이므로 계약 변경 없음.

```dart
import 'dart:math';
import '../model/level_spec.dart';
import '../model/puzzle.dart';
import '../model/word_entry.dart';
import 'grid.dart';
import 'grid_rules.dart';

class CorePlaceResult {
  final bool isolatedUsed;
  const CorePlaceResult({required this.isolatedUsed});
}

class CorePlacer {
  /// [g]에 코어 [spec.coreCount]개를 배치한다.
  /// 성공하면 CorePlaceResult, 실패하면 null. 실패 시 [g]는 오염돼 있을 수 있으므로
  /// 호출자(01-07)가 새 MutableGrid로 재시작한다.
  static CorePlaceResult? place(
    MutableGrid g,
    LevelSpec spec,
    List<WordEntry> candidates,
    Random rnd,
  ) { ... }

  /// [w]를 [g]의 기존 단어와 교차시킬 수 있는 모든 배치 후보.
  static List<PlacedWord> crossingPlacements(
    MutableGrid g,
    WordEntry w,
  ) { ... }

  /// 교차 없이 놓을 수 있는 모든 배치 후보 (고립 슬롯용).
  static List<PlacedWord> freePlacements(MutableGrid g, WordEntry w) { ... }
}
```

### `crossingPlacements` 구현 노트

```dart
final out = <PlacedWord>[];
for (final p in g.placed) {
  final newDir = p.dir == Direction.across ? Direction.down : Direction.across;
  var idx = 0;
  for (final (r, c) in p.cells) {
    final s = p.syllableAt(idx++);
    for (var i = 0; i < w.length; i++) {
      if (w.syllableAt(i) != s) continue;
      // w의 i번째가 (r,c)에 오도록 시작점 역산
      final r0 = newDir == Direction.down ? r - i : r;
      final c0 = newDir == Direction.across ? c - i : c;
      if (!g.inBounds(r0, c0)) continue;
      if (!GridRules.canPlace(g, w.headword, r0, c0, newDir)) continue;
      out.add(PlacedWord(
        headword: w.headword, row: r0, col: c0,
        dir: newDir, isCore: true, tier: w.tier,
      ));
    }
  }
}
return out;
```

중복 배치(같은 r0,c0,dir가 여러 경로로 나옴)가 생길 수 있다. `Set` 으로 걸러도 되고
그냥 둬도 결과는 같다. **셔플 결정성을 위해** 중복 제거를 한다면 순서가 안정적이어야 한다
(`headword:row:col:dir` 문자열 키로 `LinkedHashSet`).

### `freePlacements` 구현 노트

모든 `(r, c, dir)` 을 훑어 `canPlace` 가 참인 것 전부. 8×8이면 최대 128칸×2방향이라 비용은 무시할 만하다.

### 첫 코어의 중앙 우선 배치

```dart
// 중앙에서 맨해튼 거리가 가까운 순으로 정렬한 좌표 리스트
final cr = g.height ~/ 2, cc = g.width ~/ 2;
final spots = freePlacements(g, w)
  ..sort((a, b) {
    final da = (a.row - cr).abs() + (a.col - cc).abs();
    final db = (b.row - cr).abs() + (b.col - cc).abs();
    if (da != db) return da.compareTo(db);
    // 동점은 안정적 순서로
    return '${a.row}:${a.col}:${a.dir.name}'
        .compareTo('${b.row}:${b.col}:${b.dir.name}');
  });
```

첫 코어는 **across 고정**이 아니라 정렬 결과 첫 번째를 쓴다. 다만 across를 앞에 오게 정렬 키를 잡으면
격자 모양이 예측 가능해져 디버깅이 쉽다.

## 테스트

`app/test/domain/core_placer_test.dart`

| 테스트 | 기대 |
|---|---|
| 코어 3개 배치 성공 (더미 사전) | `placed.length == 3`, 전부 `isCore == true` |
| 배치 후 `GridRules.validate` 통과 | errors 비어 있음 |
| 코어끼리 교차한다 | `components(placed).length <= 2` |
| 고립 1개 허용 | `allowIsolated: true` 에서 연결 요소 최대 2, 작은 쪽 크기 1 |
| 고립 불허 | `allowIsolated: false` 로 교차 불가능한 사전을 주면 null 반환 |
| 고립 단어에 뒤 코어가 안 붙는다 | `[사과,사자,무기,기차]` `coreCount: 4` → null, 격자는 `validate` 통과 (위 "규칙 5 확인") |
| 결정성 | 같은 `Random(seed)`, 같은 후보 → 같은 배치 결과 |
| 후보 부족 | 후보 2개인데 `coreCount: 5` → null |
| 격자 너무 작음 | 3×3에 5음절 코어 → null |
| `crossingPlacements` 가 canPlace 통과분만 낸다 | 모든 반환값에 대해 `canPlace` true |

```dart
test('같은 seed면 같은 코어 배치', () async {

  expect(run(), run());

```

## 막히면

- **코어가 3개 이상이면 항상 실패** → 더미 사전 음절 풀이 좁은데도 실패한다면 `crossingPlacements` 의 시작점 역산이 틀렸다. 손으로 2×2 케이스를 그려 확인.
- **`validate` 가 "배치되지 않은 연속" 을 냄** → `canPlace` 의 끝막음/수직이웃 검사 누락. 01-03으로 돌아간다.
- **교차 후보가 항상 0** → `p.syllableAt(idx)` 대신 격자 셀 값을 읽고 있는지 확인. 둘은 같아야 하지만 인덱스 증가 위치를 틀리기 쉽다.
- **결정성이 깨짐** → `Set`/`Map` 순회 순서, `DateTime.now()`, `Random()` 무인자 생성이 어딘가 섞였다. `grep -n "Random()" ` 로 확인.
