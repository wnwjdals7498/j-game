## 작업

### 0. 준비

| 항목 | 조건 |
|---|---|
| 기기 A (주력) | 6인치대, 최근 3년 내 출시 |
| 기기 B (저가형) | RAM 3~4GB, 2020년 이전 SoC |
| 안드로이드 버전 | 두 기기가 서로 다르면 좋다(06-03 D절과 같은 이유) |
| IME | 두 기기 모두에 **삼성 키보드**와 **Gboard**를 설치하고 전환 가능하게 |
| 빌드 | `flutter run --profile` (디버그는 느려서 성능 판정이 무의미하다) |

```powershell
cd app
flutter devices              # 기기 id 확인
flutter run --profile -d <deviceId>
```

실행 중 콘솔에서 **`P`** 를 누르면 Performance overlay가 켜진다.

- 위 막대 = UI(Dart) 스레드, 아래 막대 = Raster(GPU) 스레드
- 각 막대는 최근 프레임들. 가로선이 16ms(60fps) 기준선이다
- 선을 넘는 막대가 보이면 그 프레임이 늦은 것 = 드랍

`R` 핫 리로드는 성능 측정 중에 쓰지 않는다(JIT 상태가 섞인다).

### A-1. 가독성·레이아웃 (7항목)

| # | 확인 | 기대 |
|---|---|---|
| 1 | 레벨 10(8×8) 격자 음절 | 두 기기 모두 읽힘, 셀 ≥ 36dp |
| 2 | 키보드 올라온 상태의 8×8 | 격자가 잘리지 않음, ClueBar와 겹치지 않음 |
| 3 | 다크 모드 격자 | 격자선·코어 원·번호가 구분됨 |
| 4 | 노랑 커서 위 음절 | 검정으로 읽힘(라이트·다크 모두) |
| 5 | 홈 카드 2열 | 글자 잘림 없음, 잠금·해제·클리어 구분 |
| 6 | 결과 화면 12행 | 스크롤 부드러움, 행 순차 등장 완료 |
| 7 | 시스템 글꼴 크기 최대 | 텍스트 겹침·잘림 없음 |

1번의 셀 크기는 눈대중이 아니라 숫자로 남긴다. 개발자 옵션의 레이아웃 경계 표시나 07-03이 남긴 `debugPrint(cell)` 값 중 편한 쪽을 쓴다.

### A-2. 모션·성능 (7항목)

Performance overlay를 켠 상태에서 한다.

| # | 확인 | 기대 |
|---|---|---|
| 1 | 음절 입력 연속 10회(E-01) | 저가형에서 UI·Raster 막대가 16ms 선 아래 |
| 2 | 단어 선택 연속 전환(E-02·E-03) | 동일 |
| 3 | 결과 진입(E-06~E-08 동시) | 첫 1초 안 드랍 ≤ 2프레임 |
| 4 | 화면 전환 E-09 5회 | 끊김 없음 |
| 5 | 시스템 "애니메이션 제거"(개발자 옵션 배율 0 또는 접근성) | 모든 이펙트 즉시 상태, 햅틱은 유지 |
| 6 | 햅틱 H-01~H-03 | 셀 탭·단어 완성·제출에서 각각 다르게 느껴짐 |
| 7 | 효과음 on(설정 → 효과음) | 셀 탭 클릭음(기기 터치음 켜진 상태) |

5번은 **끄는 것만 확인하고 끝내지 않는다.** 이펙트가 즉시 상태로 가되 햅틱은 그대로 와야 한다(UI-GUIDE 3.4: 햅틱은 설정으로 끄지 않는다).

### A-3. IME 재검증 (15항목 × 2 IME × 2 기기 = 60칸)

04-07 B절의 15항목을 글자 하나 바꾸지 않고 다시 한다. 입력 필드가 ClueBar 안으로 들어갔으므로(07-04) 4단계 결과를 재활용하지 않는다.

| # | 동작 | 기대 |
|---|---|---|
| 1 | 2글자 단어에 `사과` 입력 | 격자 두 칸에 `사`, `과` |
| 2 | 입력 중 조합 상태 관찰 | `ㅅ`은 격자에 안 나옴, `사`부터 나옴 |
| 3 | 3글자 단어에 4글자 입력 시도 | 4번째가 안 들어감 |
| 4 | 백스페이스로 마지막 글자 삭제 | 격자 칸이 비워짐 |
| 5 | 백스페이스로 전부 삭제 | 격자 전부 비워짐 |
| 6 | 받침 있는 글자(`각`, `닭`) | 정상 입력 |
| 7 | 겹받침(`읽`, `닭`) | 정상 입력 |
| 8 | 이중모음(`과`, `웨`) | 정상 입력 |
| 9 | 입력 중 다른 단어 선택 | 조합이 확정되고 필드가 교체됨 |
| 10 | 교차 단어를 오가며 입력 | 마지막 입력이 이김, 글자 유실 없음 |
| 11 | 한/영 전환 후 영문 입력 | 격자에 안 들어감 |
| 12 | 숫자·특수문자 입력 | 격자에 안 들어감 |
| 13 | 길게 눌러 붙여넣기(`사과나무`) | 길이만큼만 들어감 |
| 14 | 키보드 내리고 다시 올리기 | 입력 유지 |
| 15 | 앱 백그라운드 → 복귀 | 입력 유지 |

**7단계에서 추가로 보는 것**: 15항목 내내 키보드가 올라온 동안 ClueBar(힌트 + 입력 필드)가 키보드에 가리지 않는지 함께 본다. 가리면 A-1의 2번과 같은 문제이므로 두 곳에 다 적는다.

기호는 4단계 리포트와 같이 쓴다: `✅` 통과 / `⚠` 동작은 하나 거슬림 / `❌` 실패.

## 막히면

- **저가형 기기가 없다** → 에뮬레이터로 대체하지 않는다(06-06 F절: "에뮬레이터는 느리고 불안정하다"). 기기를 구하기 전까지 7단계 DoD 6번은 열어 두고, 리포트에 "미확인 — 기기 없음"으로 명시한다. 감추지 않는다.
- **두 IME 중 하나를 못 설치한다** → 설치 가능한 IME로 15항목을 다 하고, 나머지는 미확인으로 남긴다. 4단계 리포트가 두 IME를 다 봤다면 그 결과를 참고로만 적는다(재활용하지 않는다).
- **Performance overlay가 `P`로 안 켜진다** → 터미널이 아니라 IDE에서 실행 중일 수 있다. `flutter run --profile`을 콘솔에서 직접 띄우거나, DevTools의 Performance 탭을 쓴다.
- **`--profile`이 안 붙는다** → 06-01 "구현 메모"의 환경 문제(프로젝트가 `D:`, pub-cache가 `C:`)일 수 있다. `android/gradle.properties`의 `kotlin.incremental=false`가 있는지 확인한다.
- **햅틱이 전부 안 느껴진다** → 기기 설정의 "터치 진동"이 꺼져 있는지 먼저 본다. 앱 문제로 단정하기 전에 다른 앱에서 진동을 확인한다.
- **15항목 중 일부가 4단계와 같은 실패를 반복한다** → 07-04가 아니라 4단계부터의 회귀다. `docs/reports/04-ime-check.md`와 대조해 "예전부터 그랬는가"를 리포트에 적는다. 새로 생긴 실패만 07-04로 되돌린다.
