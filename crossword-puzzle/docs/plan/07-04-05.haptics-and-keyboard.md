## 작업

### 1. 햅틱 호출 지점 3곳 — 전부 페이지 위젯에서

`PuzzleModel`은 플랫폼 서비스를 모른다(모델 단위 테스트가 바인딩 없이 돌아야 한다). `puzzle_page.dart`에 `import 'package:flutter/services.dart';`를 추가한다.

| ID | 자리 | 코드 |
|---|---|---|
| H-01 | `PuzzleGridView.onCellTap` | `onCellTap: (r, c) { final before = model.selected; model.selectCell(r, c); if (!identical(model.selected, before)) HapticFeedback.selectionClick(); }` |
| H-02 | `WordInput.onChanged` | `final w = model.selected; if (w == null) return; final wasFull = model.textOf(w).length == w.length; model.setWordInput(w, text); if (!wasFull && model.textOf(w).length == w.length) HapticFeedback.lightImpact();` |
| H-03 | `_handleSubmit` | `final before = model.result; await model.submit(context); if (!identical(model.result, before)) HapticFeedback.mediumImpact();` |

H-01이 `identical` 비교인 이유: `PlacedWord`는 `==`를 재정의하지 않는다(01-01). 교차 셀 재탭으로 방향이 토글되면 다른 인스턴스가 되므로 1회 울리고, 같은 단어의 다른 칸을 탭하면 인스턴스가 그대로라 울리지 않는다 — 이게 "단어 선택 변경"의 정의다.

H-03이 확인 버튼 탭이 아니라 `submit` 반환 직후인 이유: 제출 확인 시트는 `PuzzleModel.submit(context)` 안에서 뜬다(07-04-04, `submit_test.dart`의 보호 테스트가 그렇게 요구한다). 페이지는 확인 탭 순간을 볼 수 없으므로 "결과가 새로 생겼는가"로 판정한다. 재제출도 새 `SubmitResult` 인스턴스라 울리고, "계속 풀기"와 DB 오류 경로는 `result`가 그대로라 울리지 않는다 — 의도한 동작이다.

햅틱은 설정으로 끄지 않는다(UI-GUIDE 3.4). 효과음 S-01은 07-07-04 몫이다.

### 2. 키보드 대응

`Scaffold`의 `resizeToAvoidBottomInset`은 기본값 true를 그대로 쓴다. 키보드가 올라오면 `Expanded` 격자가 먼저 줄어든다(07-03의 `side = maxWidth.clamp(0, maxHeight)`).

```dart
final keyboardUp = MediaQuery.viewInsetsOf(context).bottom > 0;
```

| 상황 | 좌우 여백 | `hintMaxLines` |
|---|---|---|
| 기본 | `GameSpace.l` (16) | 3 |
| 키보드 올라옴 | `GameSpace.l` | 1 |
| 키보드 올라옴 **그리고** 추정 셀 < 36 | `GameSpace.s` (8) | 1 |

추정 셀 크기는 격자 영역을 감싼 `LayoutBuilder` 안에서 구한다.

```dart
// 04-02 "셀 크기 하한": 폰트를 줄이지 말고 여백을 줄인다.
double _estimatedCell(BuildContext context, Puzzle puzzle, double horizontalPadding) {
  final w = MediaQuery.sizeOf(context).width - horizontalPadding * 2;
  return w / max(puzzle.width, puzzle.height);
}
```

`GameSpace.s`까지 줄여도 36dp를 못 채우면 거기서 멈춘다. 스크롤·줌은 N-03이 금지하므로, 기기·격자·실측 셀 크기를 07-08-03 리포트에 남기고 넘어간다.

`hintMaxLines: keyboardUp ? 1 : 3` — 값 3은 기존 `HintPanel`의 `maxLines: 3`을 그대로 옮긴 것이고 1은 07-04 "막히면"이 정한 값이다. 새 값을 만들지 않았다.

### 3. 햅틱 테스트 방법

`HapticFeedback.*`는 `SystemChannels.platform`의 `HapticFeedback.vibrate` 메서드 호출이다. 세기(`selectionClick`/`lightImpact`/`mediumImpact`)는 인자로 들어간다.

```dart
final calls = <String?>[];
tester.binding.defaultBinaryMessenger.setMockMethodCallHandler(
  SystemChannels.platform,
  (call) async {
    if (call.method == 'HapticFeedback.vibrate') calls.add(call.arguments as String?);
    return null;
  },
);
addTearDown(() => tester.binding.defaultBinaryMessenger
    .setMockMethodCallHandler(SystemChannels.platform, null));
```

세기별 인자 문자열(`HapticFeedbackType.lightImpact` 등)이 플랫폼·버전에 따라 다르면 **횟수만** 센다. 부모 문서 표도 횟수만 요구한다.

## 막히면

- **햅틱 채널 호출이 안 잡힘** → 핸들러를 `pumpWidget` **전에** 걸었는지 확인한다. `setMockMethodCallHandler`는 등록 이후의 호출만 받는다.
- **H-02가 교차 단어에서 두 번 울림** → `setWordInput`이 교차 칸을 덮어써 다른 단어도 동시에 꽉 찰 수 있다. 판정 대상은 **현재 선택된 단어 하나**뿐이므로 `model.selected`만 본다.
- **H-03이 "계속 풀기"에서도 울림** → `identical(model.result, before)` 대신 `model.submitted`를 봤을 때 생긴다. 재제출에서는 `submitted`가 이미 true라 반대로 안 울린다. 반드시 `result` 인스턴스로 비교한다.
- **키보드가 올라오면 `SubmitButton`이 화면 밖으로 밀림** → 여백을 더 줄이지 말고 `Expanded` 격자가 먼저 줄어드는지 확인한다. 격자가 `Expanded` 밖에 있으면 밀린다.
- **`MediaQuery.viewInsetsOf`가 위젯 테스트에서 항상 0** → 정상이다. 테스트에서는 `MediaQuery(data: MediaQueryData(viewInsets: EdgeInsets.only(bottom: 300)), child: …)`로 감싸 확인한다. 13번 테스트는 키보드가 아니라 `disableAnimations`를 본다.
- **여백을 8로 줄여도 셀이 36dp 미만** → N-03(스크롤·줌 금지) 범위 밖이다. 기기·격자 크기·실측 셀 크기를 07-08-03 리포트에 적고 넘어간다.
