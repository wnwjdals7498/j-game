# 01-10. 실패율 · 성능 하네스

담당: **AGENT**
선행: 01-09 · 다음: 2단계(02-01) 또는 3단계(03-01)
상위: [01-domain-map-generator.md](01-domain-map-generator.md) DoD 2·3번

## 목표

"레벨 스펙 × 1000 seed" 를 돌려 **실패율·생성 시간·백트래킹 횟수**를 숫자로 낸다.
1단계 DoD의 정량 기준(실패율 1% 미만, 생성 200ms 미만)을 이 하네스가 판정한다.
3단계(03-05)가 같은 하네스를 실 DB로 재사용한다.

## "실패"의 정의 (REVIEW 4.2 (f) — 여기서 확정)

- **실패** = `GridGenerator.tryGenerate` 가 `maxAttempts`(20) 를 모두 소진하고 `puzzle == null` 을 반환.
- 시간 제한은 실패 조건이 **아니다.** 시간은 별도 지표(p50/p95)로 잰다.
- 단, 한 seed가 30초를 넘으면 `timeout` 으로 따로 집계한다 (무한 루프 감지용).

## 산출물

```
app/tool/measure.dart          실행 진입점
app/lib/domain/measure/
└─ measure_runner.dart         순수 Dart 측정 로직 (3단계가 재사용)

```

`tool/` 은 `lib/` 밖이라 `dart:io` 를 써도 된다. 측정 **로직**은 `lib/domain/measure/` 에 두어
3단계가 실 DB repository를 주입해 그대로 돌릴 수 있게 한다. 이 파일도 플랫폼 import 금지.

## `measure_runner.dart`

```dart
import '../generator/grid_generator.dart';
import '../model/level_spec.dart';
import '../repository/word_repository.dart';

class LevelMeasurement {
  final LevelSpec spec;
  final int runs;
  final int failures;
  final int timeouts;
  final List<int> elapsedMicros;   // 성공한 것만, 정렬됨
  final List<int> attempts;
  final List<int> backtracks;
  final List<int> queries;

  double get failureRate => failures / runs;
  int get p50 => _pct(50);
  int get p95 => _pct(95);
  int get maxMicros => elapsedMicros.isEmpty ? 0 : elapsedMicros.last;
  double get avgAttempts =>
      attempts.isEmpty ? 0 : attempts.reduce((a, b) => a + b) / attempts.length;
  double get avgBacktracks => backtracks.isEmpty
      ? 0
      : backtracks.reduce((a, b) => a + b) / backtracks.length;
  double get avgQueries =>
      queries.isEmpty ? 0 : queries.reduce((a, b) => a + b) / queries.length;

  int _pct(int p) {
    if (elapsedMicros.isEmpty) return 0;
    final i = ((elapsedMicros.length - 1) * p / 100).round();
    return elapsedMicros[i];
  }
  // 생성자 생략
}

class MeasureRunner {
  final WordRepository repo;
  const MeasureRunner(this.repo);

  /// [spec]을 seed [startSeed] .. [startSeed + runs - 1] 로 돌린다.
  /// [onProgress] 는 100회마다 호출 (진행 표시용).
  Future<LevelMeasurement> measureLevel(
    LevelSpec spec, {
    int runs = 1000,
    int startSeed = 1,
    void Function(int done, int total)? onProgress,
  }) async {
    final gen = GridGenerator(repo);
    final elapsed = <int>[];
    final attempts = <int>[];
    final backtracks = <int>[];
    final queries = <int>[];
    var failures = 0;
    var timeouts = 0;

    for (var i = 0; i < runs; i++) {
      // seed 간격을 maxAttempts보다 크게 둔다.
      // tryGenerate가 seed..seed+maxAttempts-1을 쓰므로 겹치면 표본이 중복된다.
      final seed = startSeed + i * 100;
      final o = await gen.tryGenerate(spec, seed);
      if (o.stats.elapsed.inSeconds >= 30) timeouts++;
      if (o.puzzle == null) {
        failures++;
      } else {
        elapsed.add(o.stats.elapsed.inMicroseconds);
        attempts.add(o.stats.attempts);
        backtracks.add(o.stats.totalBacktracks);
        queries.add(o.stats.totalQueries);
      }
      if (onProgress != null && (i + 1) % 100 == 0) onProgress(i + 1, runs);
    }
    elapsed.sort();
    return LevelMeasurement(/* ... */);
  }

  Future<List<LevelMeasurement>> measureAll(
    List<LevelSpec> specs, {
    int runs = 1000,
    void Function(LevelSpec, int, int)? onProgress,
  }) async { ... }
}
```

**seed 간격 100의 이유**: `tryGenerate(spec, s)` 는 내부에서 `s, s+1, ... s+19` 를 쓴다.
seed를 1씩 늘리면 표본이 겹쳐 실패율이 왜곡된다. 간격을 `maxAttempts` 보다 크게 잡는다.

## `tool/measure.dart`

```dart
import 'dart:io';
import 'package:jgame/domain/levels.dart';
import 'package:jgame/domain/measure/measure_runner.dart';
// 더미 사전은 test/ 에 있으므로, tool에서 쓰려면 lib/domain/fixtures/ 로 옮기거나
// tool 안에 같은 빌더를 두는 것 중 하나. 여기서는 lib/domain/fixtures/ 로 옮긴다.
import 'package:jgame/domain/fixtures/dummy_dictionary.dart';

/// 사용법:
///   dart run tool/measure.dart                 (전 레벨 1000회)
///   dart run tool/measure.dart --runs 200      (빠른 확인)
///   dart run tool/measure.dart --level 9       (특정 레벨만)
Future<void> main(List<String> args) async {
  final runs = _intArg(args, '--runs', 1000);
  final onlyLevel = _intArg(args, '--level', 0);

  final repo = InMemoryWordRepository(buildDummyDictionary(seed: 1));
  final runner = MeasureRunner(repo);
  final specs = onlyLevel == 0
      ? levels
      : levels.where((l) => l.id == onlyLevel).toList();

  final results = <LevelMeasurement>[];
  for (final spec in specs) {
    stdout.write('level ${spec.id} ${spec.name} ');
    final m = await runner.measureLevel(spec, runs: runs,
        onProgress: (d, t) => stdout.write('.'));
    stdout.writeln(' 실패 ${(m.failureRate * 100).toStringAsFixed(2)}% '
        'p50 ${(m.p50 / 1000).toStringAsFixed(1)}ms '
        'p95 ${(m.p95 / 1000).toStringAsFixed(1)}ms');
    results.add(m);
  }

  final md = renderMarkdown(results, runs: runs, source: '더미 사전 (seed 1, 4000단어)');
  final f = File('../docs/reports/01-dummy-failure.md');
  f.parent.createSync(recursive: true);
  f.writeAsStringSync(md);
  stdout.writeln('리포트: ${f.path}');

  // DoD 판정
  final bad = results.where((m) => m.failureRate >= 0.01 || m.p95 > 200 * 1000);
  if (bad.isNotEmpty) {
    stderr.writeln('DoD 미달 레벨: ${bad.map((m) => m.spec.id).join(", ")}');
    exit(1);
  }
}
```

`exit(1)` 로 끝내면 CI(06-06)에서도 게이트로 쓸 수 있다.

## 실제 적용값 (구현 결과)

문서의 코드 골격과 실제 구현이 다른 부분, 그리고 측정 결과다.

**`renderMarkdown` 과 DoD 판정은 `lib/domain/measure/measure_runner.dart` 에 있다.**
`tool/measure.dart` 골격은 두 이름을 바로 부르지만 어디에 두는지는 안 적혀 있었다.
리포트 렌더 테스트가 `test/domain/measure_test.dart` 라서(테스트는 `tool/` 을 import 할 수 없다)
`lib/domain/measure/` 에 두었다. 03-05도 렌더를 그대로 쓴다. 딸린 공개 API:

```dart
const double kMaxFailureRate = 0.01;   // 전 레벨 실패율 < 1%
const int kMaxP95Micros = 200 * 1000;  // p95 < 200ms
List<LevelMeasurement> failingMeasurements(List<LevelMeasurement> ms);

String renderMarkdown(
  List<LevelMeasurement> results, {
  required int runs,
  required String source,
  String title = '01단계 더미 사전 실패율 리포트',
  String environment = '(미기록)',   // OS · dart · CPU. tool이 dart:io로 채운다
  DateTime? measuredAt,             // 테스트가 측정일을 고정할 때만 넘긴다
});
```

`environment` / `measuredAt` 은 리포트 형식의 `환경:` · `측정일:` 줄을 채우려고 더한 것이다.
플랫폼 정보는 `dart:io` 로만 얻을 수 있어 `domain/` 이 직접 읽을 수 없으므로 주입받는다.
요약 표에는 문서의 두 줄에 더해 `| timeout | 30초 초과 0건 |` 행을 넣었다. 위 "실패의 정의"
절이 timeout을 따로 집계하라고 했는데 리포트 말고는 나갈 곳이 없기 때문이다.

**측정 결과 (1000 seed × 10레벨).** 전 레벨 실패율 < 1%(최대 0.70%), p95 < 200ms(최대 45.8ms),
timeout 0건으로 `exit 0`. 초안 12레벨 그대로는 7개 레벨이 1%를 넘어 01-09 "막히면" 사다리를
한 번 더 돌렸고, 사다리로도 안 되는 2개 레벨은 아래 "레벨을 빼도 된다" 에 따라 뺐다.
레벨별 값과 근거는 [01-09 "실제 적용값"](01-09.levels-table.md) 절에 있다.

**`--runs 100` 은 게이트가 아니다.** DoD를 판정하는 건 인자 없이 돌린 1000 seed 측정이다.
100 seed만 보면 실패 1건이 곧 1.00%라 `exit 1` 이 뜰 수 있다(레벨 6 깊은숲이 그렇다 —
1000 seed 기준으로는 0.70%). 빠른 확인용으로만 쓰고, 판정은 본 측정으로 한다.

## 막히면

- **실패율이 1%를 넘음** → 01-09의 "막히면" 절 순서대로 해당 레벨 스펙을 완화하고 재측정. 레벨을 빼도 된다(12→10개).
- **p95가 200ms를 넘음** → 먼저 `avgBacktracks` 를 본다. 되감기가 많으면 스펙 문제(01-09), 되감기가 적은데 느리면 `enumerate` 나 `findByPattern` 이 O(n²)다. `avgQueries` 가 크면 01-06의 캐시가 안 먹고 있다.
- **어떤 레벨이 30초 timeout** → 무한 루프다. `backtrackBudget` 이 실제로 감소하는지 확인(01-06의 `_budget--` 누락이 흔한 원인).
- **더미에서 통과했으니 끝** → 아니다. 실데이터는 음절 조합이 훨씬 성겨 실패율이 크게 오른다(03-05 리스크). 1단계 DoD는 "알고리즘이 맞다"까지만 증명한다.
