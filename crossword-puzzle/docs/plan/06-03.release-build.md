# 06-03. 릴리스 빌드 (AAB · APK)

담당: **MIXED** (빌드는 AGENT, 실기기 2대 테스트는 HUMAN)
선행: 06-02 · 다음: 06-04
상위: [06-release.md](06-release.md) C절

## 목표

서명된 AAB를 만들고, **릴리스 빌드에서만 깨지는 문제**를 잡는다.

> release 빌드로 실기기 설치 테스트. 디버그와 달리 tree-shaking·난독화로 깨지는 것 확인.

## A. 빌드 전 체크

```powershell
flutter clean
flutter pub get
dart run build_runner build --delete-conflicting-outputs
dart analyze
flutter test
```

전부 통과해야 한다. `dart analyze` 경고를 안고 릴리스하지 않는다.

DB가 최신인지 확인:

```powershell
tools\.venv\Scripts\python.exe -m tools check
Get-Item app/assets/words.sqlite | Select-Object Length, LastWriteTime
```

## B. AAB 빌드

```powershell
flutter build appbundle --release
```

산출: `app/build/app/outputs/bundle/release/app-release.aab`

## C. 크기 점검

> assets의 10MB sqlite 포함해 AAB 30MB 안팎 예상. 초과하면 원인 확인.

```powershell
Get-Item app/build/app/outputs/bundle/release/app-release.aab |
  Select-Object @{n='MB';e={[math]::Round($_.Length/1MB,1)}}
```

**AAB는 배포 크기가 아니다.** Play가 기기별로 쪼개 전달하므로 실제 다운로드는 더 작다.
Play Console의 "앱 크기" 에서 실제 전달 크기를 확인할 수 있다 (06-04 업로드 후).

크기 분석:

```powershell
flutter build apk --release --analyze-size --target-platform android-arm64
```

`build/` 에 크기 리포트 JSON이 생기고, 콘솔에 상위 항목이 출력된다.
DevTools로 열어 볼 수도 있다.

예상 구성:

| 항목 | 크기 |
|---|---|
| `assets/words.sqlite` | ~10 MB |
| Flutter 엔진 (ABI당) | ~7 MB |
| Dart 코드 (AOT) | ~3 MB |
| 리소스·아이콘 | ~1 MB |

30MB를 크게 넘으면 원인을 찾는다. 흔한 원인:

- `app/assets/` 에 불필요한 파일 (더미 사전 fixture, 테스트 자산)
- `assets/icon/` 이 실수로 번들에 포함됨 (06-01)
- ABI가 여러 개 포함 (AAB는 정상. APK는 `--split-per-abi` 로 나눈다)

## D. 릴리스 APK 실기기 테스트 — DoD 1번

> 서명된 AAB가 생성되고 release APK가 실기기 **2대 이상**에서 정상 동작

AAB는 직접 설치할 수 없다. 테스트용 APK를 따로 만든다:

```powershell
flutter build apk --release
adb install -r app/build/app/outputs/flutter-apk/app-release.apk
```

### 체크리스트 — **기기마다 전부**

| # | 확인 | 왜 릴리스에서만 깨지나 |
|---|---|---|
| 1 | 앱이 실행된다 | 난독화로 클래스 이름이 바뀜 |
| 2 | 첫 실행 DB 복사 성공 | asset 경로 문자열이 tree-shaking됨 |
| 3 | 퍼즐이 생성된다 | — |
| 4 | 힌트가 표시된다 | — |
| 5 | 입력·제출·결과 루프 | — |
| 6 | 통계가 저장된다 | — |
| 7 | 앱 재시작 후 통계 유지 | — |
| 8 | 설정 화면 · 라이선스 표시 | asset 로딩 |
| 9 | "지금 갱신" 동작 | `http`·`crypto` 난독화 |
| 10 | 퍼즐 생성 속도가 03-05 측정치와 비슷 | AOT 컴파일로 오히려 빨라야 정상 |
| 11 | 아이콘·스플래시 정상 | — |
| 12 | 앱 삭제 → 재설치 → 정상 동작 | — |

**기기 2대 이상.** 가능하면 안드로이드 버전이 다른 것으로 (예: Android 11과 14).

### 릴리스에서만 깨지면

```powershell
# 난독화를 끄고 빌드해 원인을 좁힌다
flutter build apk --release --no-shrink
```

- `--no-shrink` 로 되면 → ProGuard 문제. `proguard-rules.pro` 에 keep 규칙 추가
- `--no-shrink` 로도 깨지면 → tree-shaking 또는 AOT 문제. 보통 리플렉션이나 동적 문자열 참조

`app/android/app/proguard-rules.pro` 예:

```proguard
# drift / sqlite3
-keep class com.tekartik.** { *; }
-keep class io.flutter.plugins.** { *; }
# 필요한 것만 추가한다. 전체 keep은 크기 절감 효과를 없앤다
```

## E. 성능 비교

릴리스 빌드는 JIT가 아니라 AOT라 **디버그보다 빨라야** 한다.
04-06 설정 화면의 벤치마크(03-05)를 릴리스 APK에서 한 번 돌려 기록한다.

디버그보다 느리면 뭔가 잘못됐다 (보통 로깅이 남아 있거나 assert가 안 빠졌다).

`assert` 는 릴리스에서 자동 제거된다. `print` 는 **제거되지 않는다.**

```powershell
Select-String -Path app/lib -Include *.dart -Recurse -Pattern "print\(" |
  Where-Object { $_.Line -notmatch "// ignore" }
```

남은 `print` 를 정리하거나 `kDebugMode` 로 감싼다.

## F. 산출물 보관

빌드마다 다음을 남긴다:

```
build-artifacts/
└─ v1.0.0+1/
   ├─ app-release.aab
   ├─ app-release.apk
   ├─ mapping.txt          ← 난독화 해제용. 크래시 리포트 분석에 필수
   └─ size-report.json
```

`mapping.txt` 는 `app/build/app/outputs/mapping/release/mapping.txt` 에 있다.
**버전마다 보관한다.** 없으면 스택 트레이스를 읽을 수 없다.
Play Console에 업로드하면 구글이 자동으로 해제해 주지만, 사본을 갖는 게 안전하다.

`build-artifacts/` 는 `.gitignore` 에 넣는다 (바이너리).

## 검증

```powershell
# AAB 서명 확인
& "$env:ANDROID_HOME\build-tools\<버전>\bundletool.jar" ...
# 또는 간단히: Play Console 업로드 시 자동 검증된다
```

`bundletool` 이 없으면 APK 쪽 `apksigner verify`(06-02)로 갈음한다.
AAB의 최종 검증은 Play Console 업로드(06-04)에서 이뤄진다.

## 막히면

- **릴리스에서 DB 복사 실패** → asset 경로가 문자열 상수인지 확인. 동적으로 만든 경로는 tree-shaking에 걸릴 수 있다.
- **릴리스에서 drift 오류** → `proguard-rules.pro` 에 keep 규칙 추가. `--no-shrink` 로 재현 여부를 먼저 확인.
- **AAB가 50MB 초과** → `--analyze-size` 리포트를 본다. `assets/` 에 뭐가 들어갔는지 확인. 더미 사전(`lib/domain/fixtures/`)은 코드라 작지만, 실수로 들어간 대용량 자산이 있을 수 있다.
- **기기가 1대뿐** → 에뮬레이터를 다른 API 레벨로 추가해 보조 검증한다. DoD에 기기 1대 + 에뮬레이터 1개로 했음을 명시한다.
- **설치 시 "앱이 설치되지 않음"** → 같은 `applicationId` 의 디버그 빌드가 다른 서명으로 설치돼 있다. 먼저 삭제한다: `adb uninstall <applicationId>`.
