# 01-09. 레벨 스펙 테이블 (levels.dart)

담당: **AGENT**
선행: 01-08 · 다음: 01-10
상위: [../REVIEW.md](../REVIEW.md) 5절 (3) — 레벨 스펙은 Dart 상수 테이블

## 목표

플레이 가능한 레벨 목록의 **초안**을 만든다. 여기 값은 더미 사전 기준이고,
실데이터 측정 후 3단계(03-06)에서 v1으로 확정된다. **지금 완벽할 필요 없다.**

## 왜 DB가 아니라 코드인가 (REVIEW 4.2 (d))

레벨 튜닝마다 DB를 재빌드해야 하면 반복이 느려진다. `domain/` 은 `LevelSpec` 타입만 받으면 되므로
상수 테이블이면 충분하다.

## 설계 지침

| 항목 | 지침 |
|---|---|
| 레벨 수 | 12개 (초안). 실데이터 후 조정 |
| 격자 크기 | 5×5 → 8×8. **9×9 이상 금지** (연결성 유지 난이도 급증, 01-domain-map-generator 리스크) |
| 코어 티어 | 레벨이 올라갈수록 2 → 6 |
| 코어 개수 | 2 → 4 |
| 채움 티어 | 코어보다 **1~3티어 낮게** (쉬운 단어로 채워야 풀이가 가능) |
| 채움 할당량 | `min < max` 범위로 둔다. 정확 일치는 백트래킹을 폭발시킨다 |
| `maxAttempts` | 20 고정 |
| `backtrackBudget` | 격자가 클수록 크게: 5×5=150, 6×6=200, 7×7=300, 8×8=400 |
| `allowIsolated` | 전부 true (규칙상 최대 1개) |

**티어 1은 채움 전용**으로 둔다. 코어로 쓰면 너무 쉽다.

### `TierQuota` 를 const로 쓰려면

01-01의 `TierQuota` 생성자가 `const` 여야 하고, `LevelSpec.fillQuotas` 는 `const List<TierQuota>` 로 받아야 한다.
`const LevelSpec(...)` 안의 리스트 리터럴은 자동으로 const가 된다.
안 되면 01-01의 필드 타입을 `final List<TierQuota>` 로 두고 `const` 생성자를 유지하면 된다.

| 테스트 | 기대 |
|---|---|

```dart
test('더미 사전으로 전 레벨이 생성된다', () async {
  final gen = GridGenerator(
      InMemoryWordRepository(buildDummyDictionary(seed: 1)));
  for (final spec in levels) {
    for (var s = 1; s <= 20; s++) {
      final o = await gen.tryGenerate(spec, s * 1000);
      expect(o.puzzle, isNotNull,
          reason: 'level ${spec.id} seed ${s * 1000}: ${o.stats.failReason}');
    }
  }
}, timeout: const Timeout(Duration(minutes: 3)));
```

## 실제 적용값 (구현 시 "막히면" 절을 적용한 결과)

위 산출물 코드는 **초안**이고, 더미 사전으로 `전 레벨 × seed 1000..20000` 게이트를 돌린 결과
6개 레벨이 실패해 "막히면" 절 순서대로 완화했다. 최종값은 `app/lib/domain/levels.dart` 이고
각 레벨에 `// 완화:` 주석으로 초안 값을 함께 남겼다.

| 레벨 | 초안에서 바뀐 것 | 근거 |
|---|---|---|
| 2 | `fillQuotas` min -1 → `[TierQuota(1, 1, 4)]` | 5×5 + 코어 3개면 남는 슬롯이 적어 채움 2개를 강제할 수 없음 |
| 8 | `fillQuotas` min -1 → `[(1,2,5), (2,1,4), (3,0,3)]` | 채움 할당량 미달로 2개 seed 실패 |
| 9 | `fillQuotas` min -1 → `[(1,3,6), (2,2,5), (3,1,4)]` **+ `coreCount` 4→3** | min만 낮춰서는 2개 seed가 계속 실패. "8×8은 코어가 많을수록 교차 위치가 안 나온다"를 이 레벨에 적용 |
| 10 | `fillQuotas` min -1 → `[(1,3,6), (2,2,5), (3,1,4)]` | 채움 할당량 미달로 4개 seed 실패 |
| 11 | `fillQuotas` min -1 → `[(1,3,6), (2,2,5), (4,0,3)]` | 위와 같음 |
| 12 | `fillQuotas` min -1 → `[(1,3,6), (2,2,5), (4,1,4)]` | 위와 같음 |

`backtrackBudget` 은 **초안 표 그대로 유지**했다. (a) 1.5배를 먼저 시도했지만 실패 seed 수가
전혀 줄지 않았고(예: 레벨 9는 400→600→900 모두 동일), 효과 없는 변경으로 "격자가 클수록 크게"
지침을 깨지 않는 쪽을 택했다. 실패 원인은 예산 부족이 아니라 채움 할당량 자체였다.

레벨 9의 `coreCount` 3은 레벨 8(4)보다 작아 코어 개수가 한 번 내려간다. 코어 개수 단조 증가는
문서에 없는 요구사항이라 테스트하지 않으며, 레벨 9는 격자가 7×7→8×8로 커져 난이도는 유지된다.

이 값들은 전부 더미 사전 기준이다. 실데이터 기준은 03-05 측정 후 03-06에서 다시 잡는다.

## 막히면

- **특정 레벨이 계속 실패** → 그 레벨의 (a) `backtrackBudget` 을 1.5배, (b) `fillQuotas` 의 `min` 을 1씩 낮추기, (c) 채움 티어를 1 낮추기 순으로 완화한다. 격자 크기를 키우지 않는다.
- **8×8이 전부 실패** → 코어 개수를 4→3으로 줄인다. 큰 격자는 코어가 많을수록 교차 위치가 안 나온다.
- **더미로는 되는데 실데이터가 걱정됨** → 정상이다. 그게 03-05의 존재 이유다. 여기서 실데이터를 추측해 값을 비틀지 않는다.
- **`const` 로 안 만들어짐** → `TierQuota` 생성자에 `const` 키워드 확인. `TierQuota.exact` 같은 리다이렉트 생성자도 `const` 여야 한다.
