# 06-01. 앱 식별 · 버전 · 아이콘

담당: **AGENT** (아이콘 디자인 원본 제공은 HUMAN)
선행: 05-04 · 다음: 06-02
상위: [06-release.md](06-release.md) A절

## 목표

스토어에 올릴 앱의 신원을 확정한다. **`applicationId` 는 등록 후 변경 불가**다.

## A. applicationId

00-05에서 `flutter create --org <역도메인>` 으로 이미 정해졌다. 여기서 **최종 확인**한다.

```powershell
Select-String -Path app/android/app/build.gradle -Pattern "applicationId"
Select-String -Path app/android/app/src/main/AndroidManifest.xml -Pattern "package"
```

확인 사항:

- [ ] 소유한 도메인의 역순이거나 `io.github.<계정>` 형태
- [ ] `com.example.*` 이 **아님** (Play Console이 거부한다)
- [ ] Play Console에서 이미 쓰이지 않음

`com.example` 로 만들어졌으면 지금 바꾼다. 나중에는 못 바꾼다.

**구현 메모**: 00-05 스켈레톤 단계에서 이미 `io.github.wnwjdals7498.jgame`
로 확정돼 있었다. `com.example`이 아니고 Play Console 미사용 계정이라 재확인만
하고 넘어간다.

```
변경해야 할 곳:
  app/android/app/build.gradle          applicationId, namespace
  app/android/app/src/main/AndroidManifest.xml
  app/android/app/src/main/kotlin/<경로>/MainActivity.kt   (패키지 디렉터리 + package 선언)
```

가장 안전한 방법은 `flutter create --org <새 도메인> .` 을 `app/` 에서 다시 돌려
안드로이드 폴더를 재생성하는 것이다. **커스터마이즈한 것이 있으면 먼저 백업**한다.

## B. 앱 이름

| 위치 | 값 |
|---|---|
| `AndroidManifest.xml` 의 `android:label` | 한글 앱 이름 |
| `pubspec.yaml` 의 `name` | `jgame` (패키지명. 바꾸지 않는다) |
| `MaterialApp.title` | 한글 앱 이름 (04-01) |

앱 이름을 확정한다. 스토어 등록명(06-04)과 같아야 혼란이 없다.
"단어 연상 퀴즈" 는 일반명사 조합이라 스토어 검색에 묻힌다. **고유한 이름을 정한다.**

**구현 메모**: "**J Crossword Puzzle**"로 확정(2026-09-18, 사용자 지정). 이 문서가
가정한 "한글 앱 이름"이 아니라 영문명이다 — `android:label`, `MaterialApp.title`
두 곳 외에, 화면 안에서 브랜드명을 보여주던 `HomePage`의 `AppBar` 제목과
`settings_page.dart`의 오픈소스 라이선스 화면(`showLicensePage`
`applicationName`)에 남아 있던 옛 이름("단어 연상 퀴즈")도 전부 이 이름으로
바꿨다 — 이 문서가 명시한 범위(라벨·타이틀)보다 넓지만, "스토어 등록명과
같아야 혼란이 없다"는 취지상 앱 안에 남는 옛 이름도 같이 정리하는 게 맞다고
판단했다. `pubspec.yaml`의 `name: jgame`(패키지명)은 문서 지시대로 그대로 뒀다.

## C. 버전

```yaml
# app/pubspec.yaml
version: 1.0.0+1
```

`1.0.0` = versionName (사용자에게 보이는 것), `1` = versionCode (빌드 번호).

**규칙:**

- Play에 올리는 모든 빌드는 versionCode가 **이전보다 커야** 한다. 같은 번호는 거부된다.
- 실패한 업로드도 번호를 태운다. 재시도할 때 +1 한다.
- versionName은 사용자에게 의미 있을 때만 올린다 (1.0.0 → 1.0.1 → 1.1.0).

05-01의 `MIN_APP_VERSION` 이 이 versionName과 비교된다. 형식을 `X.Y.Z` 로 유지한다.

앱 버전을 코드에서 읽으려면:

```yaml
dependencies:
  package_info_plus: ^8.0.0
```

```dart
final info = await PackageInfo.fromPlatform();
info.version;      // "1.0.0"
info.buildNumber;  // "1"
```

04-06의 설정 화면과 05-02의 `min_app_version` 비교에 쓴다.

**구현 메모**: `package_info_plus: ^8.0.0` 추가. 04-06이 "1차 범위에서 안 넣는다"고
미뤄둔 두 곳을 실제 값으로 바꿨다:
- `settings_page.dart`: `_appVersionName`/`_appVersionBuildNumber` 상수를 지우고
  `_AppVersionSection`(`PackageInfo.fromPlatform()`을 한 번만 여는
  `FutureBuilder`, `_DbInfoSection`과 같은 패턴)으로 교체. "오픈소스 라이선스"
  탭의 `applicationVersion`도 이 값을 쓴다.
- `data/db/open_native.dart`의 `makeSyncService`: `PackageInfo.fromPlatform()`으로
  읽은 `info.version`을 `NativeSyncService(appVersion: ...)`에 넘긴다.
  `NativeSyncService.appVersion`의 `'1.0.0'` 기본값은 이 클래스를 직접 생성하는
  테스트용으로만 남겼다(`sync_service.dart` 주석 갱신).
- 위젯 테스트(`home_settings_test.dart`)는 플랫폼 채널이 없어
  `PackageInfo.fromPlatform()`이 `MissingPluginException`을 던지므로
  `setUpAll`에서 `PackageInfo.setMockInitialValues(...)`로 목값을 심었다.

## D. 아이콘

### 원본 준비 (HUMAN)

- **1024×1024 PNG**, 투명 배경 없이 (Play는 투명을 허용하지 않는다)
- 단순한 도형 + 글자 1~2자가 작은 크기에서 읽힌다
- 격자나 한글 음절을 모티브로

### 생성

```yaml
dev_dependencies:
  flutter_launcher_icons: ^0.14.0

flutter_launcher_icons:
  android: true
  ios: false
  image_path: "assets/icon/icon.png"
  adaptive_icon_background: "#FFFFFF"      # 또는 색상
  adaptive_icon_foreground: "assets/icon/icon_foreground.png"
  min_sdk_android: 21
```

```powershell
dart run flutter_launcher_icons
```

**적응형 아이콘(adaptive icon)** 이 중요하다. 안드로이드 8+ 에서 런처가 모양을 자른다.
foreground는 안전 영역(중앙 66%) 안에 내용을 두어야 잘리지 않는다.

`assets/icon/` 은 앱 번들에 들어갈 필요가 없다. `pubspec.yaml` 의 `assets:` 에 **넣지 않는다**
(아이콘은 생성 시점에만 쓰이고 네이티브 리소스로 복사된다).

**구현 메모**: 원본은 사용자가 `crossword-puzzle/asset/icon/`에 준비한 Codex
생성 이미지(격자 4칸 + 한글 음절 "가나다" + 잎사귀, 파란 배경, 2026-09-18)다.
1254×1254라 1024×1024로 리사이즈해 `app/assets/icon/icon.png`로 저장했다(투명
채널 없음 — Play 조건 충족). 원본에 이미 둥근 모서리·배경이 다 그려져 있어
별도 foreground 레이어가 없으므로, 안전 영역(중앙 66%) 요구를 지키기 위해
같은 이미지를 64%로 축소해 투명 1024×1024 캔버스 중앙에 얹은 것을
`icon_foreground.png`로 만들었다. `adaptive_icon_background`는 원본 배경에서
뽑은 파란색(`#08A2FB`, 좌측 가장자리 중앙 픽셀 평균 — 모서리 곡률 밖이라
안전하게 배경색만 나온다). 실제 생성/색 추출 스크립트는 이 커밋 메시지에는
안 남기고 결과 파일(`app/assets/icon/*.png`)만 커밋한다. `pubspec.yaml`의
`flutter: assets:`를 기존 `assets/`(디렉터리 전체) 대신
`assets/LICENSES.md`/`assets/words.sqlite` 개별 나열로 바꿨다 — 안 그러면
`assets/icon/`도 번들에 딸려 들어간다(이 절이 명시적으로 금지하는 것).
결과: `flutter build apk --debug` + `aapt dump badging`으로
`application-icon-*`이 `res/mipmap-anydpi-v26/ic_launcher.xml`(적응형)을
가리키는 것까지 확인했다. **런처에서 실제로 어떻게 보이는지(원형/사각/
둥근사각)는 이 환경에 연결된 안드로이드 기기·에뮬레이터가 없어 확인
못 했다** — 아래 "검증" 절 기기 항목은 HUMAN 몫으로 남는다.

## E. 스플래시

첫 실행에 10MB DB 복사가 있어 흰 화면이 보인다(04-01).
네이티브 스플래시로 가린다:

```yaml
dev_dependencies:
  flutter_native_splash: ^2.4.0

flutter_native_splash:
  color: "#FFFFFF"
  color_dark: "#121212"
  image: "assets/icon/splash.png"
  android_12:
    image: "assets/icon/splash.png"
    color: "#FFFFFF"
```

**구현 메모**: `splash.png`란 별도 파일을 새로 만들지 않고 D절의
`icon_foreground.png`(투명 배경, 아이콘 내용만 안전 영역 크기로 축소된 것)를
그대로 재사용했다 — `icon.png`(원본)를 쓰면 그 자체의 검은 둥근 모서리가
스플래시 배경(`#FFFFFF`/`#121212`) 위에 네모난 테두리로 그대로 보인다.
`color`는 `main.dart`의 `colorSchemeSeed: Colors.indigo`(Material 3 라이트
서피스가 흰색에 가깝다)에 맞춰 흰색으로 뒀다 — `BootstrapLoadingPage`와
정확히 같은 색은 기기에서 실측해야 확정할 수 있어(위젯 배경색은 테마가
런타임에 계산한다), 깜빡임 여부는 검증 절의 기기 확인 항목으로 남는다.

```powershell
dart run flutter_native_splash:create
```

안드로이드 12+ 는 스플래시 API가 달라 `android_12:` 블록이 따로 필요하다.

04-01의 `BootstrapLoadingPage` 가 네이티브 스플래시 뒤를 이어받는다.
**두 화면의 배경색을 맞춘다** — 안 그러면 전환에서 깜빡인다.

```powershell
# applicationId 최종 확인
aapt dump badging app/build/app/outputs/flutter-apk/app-debug.apk | Select-String "package"
```

(`aapt` 는 `$env:ANDROID_HOME\build-tools\<버전>\` 에 있다)

**구현 메모**: 처음엔 이 환경에 연결된 기기가 없어(`flutter devices`가
Windows/Chrome/Edge만 보여줌) 4개 다 HUMAN 대기로 남겼었다. 이후
`flutter emulators --launch Pixel_10_Pro`로 AVD를 띄우고
`adb install -r`로 디버그 APK를 직접 설치해 4개 다 확인했다: 앱 서랍 아이콘
스크린샷, 스플래시 스크린샷, 홈 화면 스크린샷, 설정 화면 스크린샷, "오픈소스
라이선스" 화면(`applicationName`/`applicationVersion`이 "J Crossword
Puzzle"/"1.0.0"으로 정확히 뜸)까지 캡처해 봤다. 다만 이건 **에뮬레이터(원형
마스크 launcher) 1종**일 뿐이라 삼성 One UI 같은 사각/둥근사각 런처에서의
렌더링은 여전히 미확인 — 실기기가 생기면 HUMAN이 마저 확인한다.
`flutter build apk --debug` 빌드 성공 + `aapt dump badging`으로
`package: name='io.github.wnwjdals7498.jgame' versionCode='1' versionName='1.0.0'`,
`application-label:'J Crossword Puzzle'`,
`application-icon-*:'res/mipmap-anydpi-v26/ic_launcher.xml'`(적응형 아이콘 XML)도
직접 확인했다. `flutter analyze`(0 issues), `flutter test`(273개 전부 통과),
`flutter build web`(05-04가 확인한 컴파일 유지)도 다시 돌렸다.

에뮬레이터 확인 중 설정 화면 좌표를 잘못 계산해 "오픈소스 라이선스" 대신
"지금 갱신"을 실수로 눌렀다 — 실제 `defaultManifestUrl`(진짜 GitHub
Releases 주소)로 네트워크 요청이 나갔지만 아직 릴리스가 없어 조용히 실패
(`마지막 갱신`이 `-`로 그대로, 단어 수·빌드 시각도 안 바뀜)했고 기존 DB는
무손상이었다 — 05-04가 의도한 "실패해도 안전"이 실제로도 동작함을 우연히
한 번 더 확인한 셈이다.

**빌드 중 발견한 별개 문제**: 프로젝트가 `D:` 드라이브, pub-cache가 `C:` 드라이브에
있으면 Kotlin 증분 컴파일러가 두 경로 사이 상대 경로를 계산하다
`IllegalArgumentException: this and base files have different roots`로 실패해
`flutter build apk`가 아예 안 됐다(이번에 새로 추가한 `package_info_plus`뿐
아니라 원래 있던 `shared_preferences_android`도 같은 이유로 실패 — 이번
작업이 원인이 아니라 이 환경의 사전 조건). `android/gradle.properties`에
`kotlin.incremental=false`를 추가해 우회했다(매번 전체 컴파일이라 조금
느려지지만 빌드는 된다) — 6단계 나머지 문서(06-03 릴리스 빌드 등)에서도
같은 환경을 쓴다면 필요하다.

## 막히면

- **`applicationId` 변경 후 빌드 실패** → `MainActivity.kt` 의 패키지 디렉터리 구조가 선언과 안 맞는다. `flutter clean` 후 재빌드. 그래도 안 되면 안드로이드 폴더 재생성.
- **아이콘이 잘림** → 적응형 foreground의 안전 영역을 벗어났다. 내용을 중앙 66% 안으로 줄인다.
- **안드로이드 12에서 스플래시가 이상함** → `android_12:` 블록을 설정했는지 확인. 12+는 아이콘이 원형으로 잘린다.
- **versionCode를 올렸는데 Play가 거부** → 이전에 올린 것 중 더 큰 번호가 있다. Play Console에서 최대 versionCode를 확인하고 그보다 크게 잡는다.
- **좋은 앱 이름이 떠오르지 않음** → 스토어에서 "단어 퀴즈" 로 검색해 겹치지 않는 이름을 고른다. 이건 사람이 정할 일이다.
