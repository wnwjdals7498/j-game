# 06-01. 앱 식별 · 버전 · 아이콘

담당: **AGENT** (아이콘 디자인 원본 제공은 HUMAN)
선행: 05-04 · 다음: 06-02
상위: [06-release.md](06-release.md) A절

## 목표

스토어에 올릴 앱의 신원을 확정한다. **`applicationId` 는 등록 후 변경 불가**다.

## A. applicationId

00-05에서 `flutter create --org <역도메인>` 으로 이미 정해졌다. 여기서 **최종 확인**한다.

```powershell
Select-String -Path app/android/app/build.gradle -Pattern "applicationId"
Select-String -Path app/android/app/src/main/AndroidManifest.xml -Pattern "package"
```

확인 사항:

- [ ] 소유한 도메인의 역순이거나 `io.github.<계정>` 형태
- [ ] `com.example.*` 이 **아님** (Play Console이 거부한다)
- [ ] Play Console에서 이미 쓰이지 않음

`com.example` 로 만들어졌으면 지금 바꾼다. 나중에는 못 바꾼다.

```
변경해야 할 곳:
  app/android/app/build.gradle          applicationId, namespace
  app/android/app/src/main/AndroidManifest.xml
  app/android/app/src/main/kotlin/<경로>/MainActivity.kt   (패키지 디렉터리 + package 선언)
```

가장 안전한 방법은 `flutter create --org <새 도메인> .` 을 `app/` 에서 다시 돌려
안드로이드 폴더를 재생성하는 것이다. **커스터마이즈한 것이 있으면 먼저 백업**한다.

## B. 앱 이름

| 위치 | 값 |
|---|---|
| `AndroidManifest.xml` 의 `android:label` | 한글 앱 이름 |
| `pubspec.yaml` 의 `name` | `jgame` (패키지명. 바꾸지 않는다) |
| `MaterialApp.title` | 한글 앱 이름 (04-01) |

앱 이름을 확정한다. 스토어 등록명(06-04)과 같아야 혼란이 없다.
"단어 연상 퀴즈" 는 일반명사 조합이라 스토어 검색에 묻힌다. **고유한 이름을 정한다.**

## C. 버전

```yaml
# app/pubspec.yaml
version: 1.0.0+1
```

`1.0.0` = versionName (사용자에게 보이는 것), `1` = versionCode (빌드 번호).

**규칙:**

- Play에 올리는 모든 빌드는 versionCode가 **이전보다 커야** 한다. 같은 번호는 거부된다.
- 실패한 업로드도 번호를 태운다. 재시도할 때 +1 한다.
- versionName은 사용자에게 의미 있을 때만 올린다 (1.0.0 → 1.0.1 → 1.1.0).

05-01의 `MIN_APP_VERSION` 이 이 versionName과 비교된다. 형식을 `X.Y.Z` 로 유지한다.

앱 버전을 코드에서 읽으려면:

```yaml
dependencies:
  package_info_plus: ^8.0.0
```

```dart
final info = await PackageInfo.fromPlatform();
info.version;      // "1.0.0"
info.buildNumber;  // "1"
```

04-06의 설정 화면과 05-02의 `min_app_version` 비교에 쓴다.

## D. 아이콘

### 원본 준비 (HUMAN)

- **1024×1024 PNG**, 투명 배경 없이 (Play는 투명을 허용하지 않는다)
- 단순한 도형 + 글자 1~2자가 작은 크기에서 읽힌다
- 격자나 한글 음절을 모티브로

### 생성

```yaml
dev_dependencies:
  flutter_launcher_icons: ^0.14.0

flutter_launcher_icons:
  android: true
  ios: false
  image_path: "assets/icon/icon.png"
  adaptive_icon_background: "#FFFFFF"      # 또는 색상
  adaptive_icon_foreground: "assets/icon/icon_foreground.png"
  min_sdk_android: 21
```

```powershell
dart run flutter_launcher_icons
```

**적응형 아이콘(adaptive icon)** 이 중요하다. 안드로이드 8+ 에서 런처가 모양을 자른다.
foreground는 안전 영역(중앙 66%) 안에 내용을 두어야 잘리지 않는다.

`assets/icon/` 은 앱 번들에 들어갈 필요가 없다. `pubspec.yaml` 의 `assets:` 에 **넣지 않는다**
(아이콘은 생성 시점에만 쓰이고 네이티브 리소스로 복사된다).

## E. 스플래시

첫 실행에 10MB DB 복사가 있어 흰 화면이 보인다(04-01).
네이티브 스플래시로 가린다:

```yaml
dev_dependencies:
  flutter_native_splash: ^2.4.0

flutter_native_splash:
  color: "#FFFFFF"
  color_dark: "#121212"
  image: "assets/icon/splash.png"
  android_12:
    image: "assets/icon/splash.png"
    color: "#FFFFFF"
```

```powershell
dart run flutter_native_splash:create
```

안드로이드 12+ 는 스플래시 API가 달라 `android_12:` 블록이 따로 필요하다.

04-01의 `BootstrapLoadingPage` 가 네이티브 스플래시 뒤를 이어받는다.
**두 화면의 배경색을 맞춘다** — 안 그러면 전환에서 깜빡인다.

## 검증

```powershell
flutter build apk --debug
adb install -r app/build/app/outputs/flutter-apk/app-debug.apk
```

기기에서:

- [ ] 런처에 아이콘이 제대로 보인다 (원형·사각·둥근사각 런처 모두)
- [ ] 앱 이름이 한글로 보인다
- [ ] 실행 시 스플래시 → 로딩 → 홈으로 깜빡임 없이 전환
- [ ] 설정 화면의 앱 버전이 `1.0.0 (1)`

```powershell
# applicationId 최종 확인
aapt dump badging app/build/app/outputs/flutter-apk/app-debug.apk | Select-String "package"
```

(`aapt` 는 `$env:ANDROID_HOME\build-tools\<버전>\` 에 있다)

## 막히면

- **`applicationId` 변경 후 빌드 실패** → `MainActivity.kt` 의 패키지 디렉터리 구조가 선언과 안 맞는다. `flutter clean` 후 재빌드. 그래도 안 되면 안드로이드 폴더 재생성.
- **아이콘이 잘림** → 적응형 foreground의 안전 영역을 벗어났다. 내용을 중앙 66% 안으로 줄인다.
- **안드로이드 12에서 스플래시가 이상함** → `android_12:` 블록을 설정했는지 확인. 12+는 아이콘이 원형으로 잘린다.
- **versionCode를 올렸는데 Play가 거부** → 이전에 올린 것 중 더 큰 번호가 있다. Play Console에서 최대 versionCode를 확인하고 그보다 크게 잡는다.
- **좋은 앱 이름이 떠오르지 않음** → 스토어에서 "단어 퀴즈" 로 검색해 겹치지 않는 이름을 고른다. 이건 사람이 정할 일이다.
