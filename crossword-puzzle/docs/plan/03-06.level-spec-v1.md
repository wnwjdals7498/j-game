## 조정 원칙

**측정 없이 고치지 않는다.** 한 번에 하나씩 바꾸고 재측정한다.

### 조정 손잡이 (완화 강도 순)

| # | 손잡이 | 효과 | 부작용 |
|---|---|---|---|
| 1 | `backtrackBudget` 증가 | 실패율 ↓ | 생성 시간 ↑ |
| 2 | 채움 `TierQuota` 를 `min` 낮추고 `max` 넓히기 | 실패율 ↓↓ | 난이도 일관성 ↓ |
| 3 | 채움 티어를 낮은 쪽으로 (쉬운 단어가 많다) | 실패율 ↓↓ | 퍼즐이 쉬워짐 |
| 4 | 채움 티어 **집합**을 넓히기 (`{1,2}` → `{1,2,3}`) | 실패율 ↓↓↓ | 난이도 편차 ↑ |
| 5 | `coreCount` 감소 | 실패율 ↓↓ | 코어(복습) 노출 ↓ |
| 6 | 격자 크기 감소 | 실패율 ↓↓↓ | 퍼즐이 작아짐 |
| 7 | `maxAttempts` 증가 | 실패율 ↓ | **생성 시간 ↑↑. 20 상한 유지** |

7번은 마지막 수단이다 (01-07: "실패율을 숫자로 가린 것뿐").

### 채움 티어를 집합으로

01-09의 `TierQuota(tier, min, max)` 는 티어 하나에 개수를 지정한다.
실데이터에서 특정 티어가 얇으면(02-10 리포트 확인) 이것만으로 부족할 수 있다.

필요하면 `LevelSpec` 에 필드를 추가한다:

```dart
/// 채움 단어가 쓸 수 있는 티어 범위. 할당량과 별개로 "이 안에서만 뽑아라".
final Set<int> fillTierPool;
```

`Filler`(01-06)가 `findByPattern(tiers: ...)` 에 넘기는 집합을 `fillQuotas` 의 티어 합집합 대신
`fillTierPool` 로 바꾼다. **바꾸면 01-01, 01-06 문서도 같이 고친다** (계약 변경).

## 레벨 수·곡선 재설계

실데이터 티어 분포(02-10)를 보고 곡선을 다시 그린다. 확인할 것:

1. **티어당 단어 수.** 6·7티어가 각 7%·4%라면 5만 단어 기준 3,500 / 2,000개다. 코어로 쓰기엔 충분.
2. **길이별 분포.** 5음절 단어가 극히 적으면 큰 격자에서 긴 슬롯을 못 채운다.
3. **음절 커버리지.** 티어 1~3의 고유 음절이 적으면 교차가 잘 맞는다(좋음). 많으면 반대(나쁨).

레벨 수는 12개를 고수하지 않는다. 실패율이 안 나오는 레벨은 **뺀다.**
게임은 10레벨이어도 되고, 나중에 늘리면 된다.

## 레벨 해제 규칙

4단계(04-06)가 쓸 규칙을 여기서 정한다.

> 레벨 해제 규칙: 이전 레벨 1회 클리어(점수 기준은 규칙 절에 기록)

초안: **`score >= 0`** 이면 클리어. (맞은 단어 ≥ 틀린 단어)

`LevelSpec` 에 필드로 넣는다:

```dart
final int clearScore;   // 이 점수 이상이면 클리어. 기본 0
```

`docs/DESIGN.md` 5절에 기록한다.

## 작업 순서

1. `docs/reports/03-real-failure.md` 를 열고 **실패한 레벨과 원인**(03-05 병목 판정 표)을 목록화한다.
2. 실패 레벨마다 손잡이를 **1번부터 순서대로** 하나씩 적용한다.

## 난이도 체감 확인 (HUMAN)

숫자가 통과해도 **재미없으면 의미가 없다.** 대표 레벨 3개(초·중·후반)의 퍼즐을
사람이 실제로 풀어 본다. 4단계 UI 전이므로 콘솔 출력으로 격자를 그린다:

```dart
// tool/print_puzzle.dart
// dart run tool/print_puzzle.dart --level 5 --seed 123
// 격자를 아스키로 출력 + 단어별 힌트(뜻풀이) 출력
```

확인 항목:

- [ ] 코어 단어가 "알 만한데 헷갈리는" 수준인가
- [ ] 채움 단어가 힌트만 보고 맞힐 수 있는가
- [ ] 격자가 너무 성기지 않은가 (단어 수가 격자 대비 적으면 심심하다)
- [ ] 레벨이 올라가며 난이도가 실제로 오르는가

체감이 나쁘면 숫자 DoD를 만족하더라도 스펙을 고친다.

## 막히면

- **손잡이를 다 써도 특정 레벨이 안 됨** → 그 레벨을 **뺀다.** 12개가 목표가 아니다.
- **전부 완화했더니 퍼즐이 너무 쉬움** → 코어 티어를 올린다(코어는 실패율에 덜 민감하다 — 교차 위치만 찾으면 되고 패턴 제약이 없다). 채움이 쉬운 건 괜찮다. 채움은 힌트로 푸는 것이고 난이도는 코어가 만든다.
- **격자가 너무 성겨 심심함** → 채움 할당량 `min` 을 올린다. 실패율이 오르면 채움 티어 풀을 넓혀 상쇄한다.
- **실기기마다 결과가 크게 다름** → 저가형 기준으로 맞춘다. 고성능 기기는 어차피 통과한다.
- **체감은 좋은데 숫자가 미달** → 숫자를 우선한다. 1% 실패율은 유저가 100판에 1번 "퍼즐 생성 실패" 를 본다는 뜻이고, 그건 앱 신뢰를 깬다.
