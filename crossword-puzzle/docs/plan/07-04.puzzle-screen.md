# 07-04. 퍼즐 화면 재구성 (힌트 바 + 입력 통합 · 진행 표시 · 바텀 시트 · 햅틱)

담당: **AGENT**
선행: 07-03 · 다음: 07-07 (07-05·07-06과 병렬)
상위: [07-ui-v2.md](07-ui-v2.md) · 계약: [../UI-GUIDE.md](../UI-GUIDE.md) 2.5(버튼), 3.3(E-04, E-05, E-12), 3.4(H-01~H-03), 4절(공통 규칙)

## 목표

퍼즐 화면을 NYT Crossword 모바일 레이아웃으로 바꾼다. **격자 아래에 힌트 바 하나**가 있고, 그 안에 방향·번호 배지, 힌트 본문, 이전·다음 화살표, 그리고 **입력 필드가 함께** 들어간다. 제출 버튼은 모든 칸이 채워지면 색이 바뀐다. 튜토리얼과 제출 확인은 다이얼로그가 아니라 바텀 시트다.

`WordInput` 위젯의 **내부는 바꾸지 않는다.** IME 안정성은 이 위젯이 책임지며(04-04), 이 문서는 그것을 감싸는 레이아웃과 스타일만 바꾼다.

## 작업

### 1. `PuzzleModel` 확장

```dart
/// 모든 셀이 채워진 단어 수 (진행 배지 "n / N").
int get filledWordCount => puzzle == null ? 0 : puzzle!.words.where((w) => textOf(w).length == w.length).length;
bool get allFilled => puzzle != null && Scorer.blankCellCount(puzzle!, answers) == 0;
void selectPrevWord() { /* selectNextWord의 역방향, 첫 번째 → 마지막 순환 */ }
```

`submit(BuildContext)`의 `showDialog<bool>`을 `puzzle_sheets.dart`의 `showSubmitConfirmSheet(context, blanks: n)`로 교체한다. **문구는 그대로**: 빈칸 있으면 기존 "빈 칸 N개…" 문구, 없으면 `'모든 칸을 채웠습니다.'`(INV-09, **마침표 포함** — `submit_test.dart`가 `find.text`로 정확히 찾는다). 버튼 라벨도 기존과 동일(`submit_test.dart`가 찾는 문구 확인 후 유지).

### 2. `ClueBar`

`HintPanel`을 대체한다. props: `selected`, `number`, `hintText`, `onPrev`, `onNext`, `child`(WordInput). 힌트 본문은 `AnimatedSwitcher(duration: motion.base)`로 E-04(페이드 + 4dp 상승, `SlideTransition` 오프셋 `(0, 0.1)` → 0). 헤더 문자열 형식 `'가로 3   3글자'`는 현재 `HintPanel._header`와 동일하게 유지한다(`play_loop_test` 2번이 이 문구로 단어를 확인한다). 배지는 방향+번호(`accentSoft` 배경, `label`), 길이는 `inkMuted` label.

### 3. `SubmitButton` (E-05)

`AnimatedContainer(duration: motion.base)` + `Material/InkWell`. `allFilled == false`면 보조 스타일(투명 + `line` 테두리 + `ink` 글자), true면 기본 스타일(`ink` 배경 + `surface` 글자). 두 상태 모두 **누를 수 있다**(빈칸이 있어도 제출 가능은 기존 규칙). 라벨 `'제출'` 고정.

### 4. 시트 (E-12)

`puzzle_sheets.dart`:
- `showTutorialSheet(context)`: 제목 `'이렇게 플레이해요'`(INV-09), 본문 4줄 기존 문구 그대로, 버튼 `'확인'`. 현재 `AlertDialog`를 대체.
- `showSubmitConfirmSheet(context, {required int blanks}) → Future<bool>`: 기존 다이얼로그 문구·버튼 라벨 그대로.

둘 다 `showModalBottomSheet(isScrollControlled: false, useSafeArea: true)`; 모양은 07-02 `bottomSheetTheme`이 준다.

### 5. 햅틱

| 위치 | 호출 |
|---|---|
| `onCellTap` → `model.selectCell` 후 `selected`가 바뀌었으면 | H-01 `HapticFeedback.selectionClick()` |
| `WordInput.onChanged` 후 그 단어가 방금 꽉 찼으면(`textOf(w).length == w.length`이고 직전엔 아니었음) | H-02 `HapticFeedback.lightImpact()` |
| 제출 확인 시트에서 확인 | H-03 `HapticFeedback.mediumImpact()` |

햅틱은 `PuzzleModel`이 아니라 **페이지 위젯**에서 부른다(모델은 플랫폼 서비스를 몰라야 테스트가 단순하다). 테스트에서는 `TestDefaultBinaryMessengerBinding`의 `SystemChannels.platform` 모의 핸들러로 `HapticFeedback.*` 호출 횟수를 센다.

### 6. 진행 배지

AppBar `actions`에 `'${model.filledWordCount} / ${puzzle.words.length}'`(label). `allFilled`면 배지 뒤에 체크 아이콘(`success`). 배지 값 변화는 `AnimatedSwitcher(motion.fast)`.

### 7. 튜토리얼 호출 지점

`_maybeShowTutorial`의 `showDialog` → `showTutorialSheet`. `tutorialSeenPrefsKey` 로직은 그대로. `tutorial_test.dart` 2종이 `find.text('이렇게 플레이해요')`로 찾는다면 통과한다. 다이얼로그 타입으로 찾는다면 셀렉터만 수정.

## 막히면

- **키보드가 올라오면 격자가 너무 작아짐(8×8)** → 키보드 표시 중에는 ClueBar의 힌트 본문을 `maxLines: 1`로 접어 높이를 확보한다. 그래도 셀 < 36dp면 04-02 규칙대로 좌우 여백 8. 그 이상은 N-03(스크롤·줌 금지) 범위 밖이므로 07-08 리포트에 기기·수치를 기록하고 넘어간다.
- **`showModalBottomSheet`가 `TextField` 포커스를 뺏음** → 시트가 닫힐 때 `FocusScope.of(context).unfocus()` 후 필요한 경우만 `WordInput` 내부 `FocusNode`로 복귀. `WordInput`을 수정하지 않고 하려면 시트 반환 후 `model.selected`를 재할당해 `didUpdateWidget` 경로를 태운다.
- **햅틱 테스트에서 채널 호출이 안 잡힘** → `HapticFeedback`은 `SystemChannels.platform`의 `HapticFeedback.vibrate` 메서드다. `tester.binding.defaultBinaryMessenger.setMockMethodCallHandler(SystemChannels.platform, ...)`로 잡고 `method == 'HapticFeedback.vibrate'`를 센다.
- **`AnimatedSwitcher`가 텍스트를 교체하지 않음** → 자식 `Key`가 같아서다. 힌트 텍스트 위젯에 `ValueKey(selected)`를 준다.
- **`Scorer.blankCellCount` import가 domain 계층 수정으로 오해될까** → 읽기 import는 허용이다. INV-07은 `lib/domain` 파일의 diff만 본다.
