## 목표

`PuzzleGridView`를 `StatefulWidget`으로 바꾸고 컨트롤러 3개를 붙여 07-03-01이 만들어 둔
정지 인자(`pop`·`selectionRect`·`cursorOpacity`)를 실제로 움직인다.
시간·곡선은 전부 `GameMotion.of(context)`에서만 얻는다(INV-12).
감소 모션에서는 컨트롤러를 아예 돌리지 않고 최종 상태를 즉시 반영한다.

## 컨텍스트 (시작 전 읽기)

- `app/lib/ui/puzzle/grid_view.dart` — 07-03-01이 고친 직후 상태. `LayoutBuilder` 안에서 `cell`이 정해진다
- `app/lib/ui/theme/motion.dart` (07-02) — `GameMotion.of(context)`, `instant`/`fast`, `curvePop`/`curveStandard`. 감소 모션이면 `GameMotion.none`(전부 `Duration.zero`)
- `app/lib/ui/state/puzzle_model.dart` — `setWordInput`이 `answers`를 **새 맵으로 교체**한다, `retry()`가 `answers = {}`·`focusedCell = null`로 되돌린다, `selectCell`이 `selected`와 `focusedCell`을 함께 바꾼다

- `app/test/ui/play_loop_test.dart` 253줄 — `tester.widget<PuzzleGridView>(...).answers`를 읽는다. `answers`는 계속 **위젯 필드**여야 한다

## 작업

### 1. 상태 클래스를 공개로 둔다

위젯 필드는 07-03-01 그대로 두고, `createState()`가 **공개** 상태를 돌려준다:
`class PuzzleGridViewState extends State<PuzzleGridView> with TickerProviderStateMixin`.

`_PuzzleGridViewState`(비공개)로 두면 07-03-03이 `tester.state<...>()`로 getter를 읽을 수 없다.
`FormState`·`ScaffoldState`와 같은 관례를 따른다.

### 2. 필드와 수명

| 필드 | 용도 |
|---|---|
| `_pop`, `_selection`, `_cursor` | `AnimationController(vsync: this)`. `initState`에서는 **duration 없이** 만들고 `_cursor.value = 1` |
| `_popCells` | `Set<(int, int)>`. 비어 있으면 팝 없음 |
| `_popCurve`, `_selectionCurve` | `Curve?`. `null`이면 해당 모션이 멈춘 상태 |
| `_prevBounds`, `_nextBounds` | `Rect?`, **셀 단위**(열·행). E-02 보간의 양 끝 |
| `_cell` | `double`. `LayoutBuilder` 본문에서 갱신되는 마지막 셀 크기 |

`initState`에서 세 컨트롤러에 `addListener(() => setState(() {}))`를, `_pop`·`_selection`에는
`addStatusListener`를 달아 `completed`면 각각 `_popCells = {}`, `_prevBounds = _nextBounds = null`로 되돌린다.
`dispose`에서 셋 다 `dispose()`.

`Duration`은 `initState`에서 정할 수 없다(`GameMotion.of`가 `context`를 쓴다).
`didUpdateWidget` 안에서 `forward` 직전에 `controller.duration = ...`을 넣는다.

### 3. `didUpdateWidget` 트리거

`didUpdateWidget(old)`은 `final m = GameMotion.of(context);` 한 줄 뒤에 `_syncPop`·`_syncSelection`·`_syncCursor`를 차례로 부른다.

| 이펙트 | 조건 | 지속/곡선 | 정상 동작 | `Duration.zero`일 때 |
|---|---|---|---|---|
| E-01 `_pop` | `widget.answers`에서 **이전이 null/빈 문자열이고 지금은 비어 있지 않은** 셀 집합 `newly`가 비지 않음 | `m.fast` / `m.curvePop` | `_popCells = newly`, `_popCurve = m.curvePop`, `_pop.forward(from: 0)` | `_popCells = {}`, `_popCurve = null`, `_pop.stop()` |
| E-02 `_selection` | `old.selected`와 `widget.selected`가 **서로 다른 인스턴스**이고 **둘 다 non-null** | `m.fast` / `m.curveStandard` | 양 끝 바운딩을 셀 단위로 저장하고 `_selection.forward(from: 0)` | `_prevBounds = _nextBounds = null` |
| E-03 `_cursor` | `widget.focusedCell != old.focusedCell`이고 `widget.focusedCell != null` | `m.instant` | `_cursor.forward(from: 0)` | `_cursor.value = 1` |

`focusedCell`이 `null`이 되는 경우(다시 풀기)는 `_cursor.value = 1`만 하고 애니메이션은 돌리지 않는다.
페인터가 `focusedCell == null`이면 층 3을 건너뛰므로 알파는 의미가 없다.

E-01 diff:

```dart
final newly = <(int, int)>{};
for (final e in widget.answers.entries) {
  if (e.value.isEmpty) continue;
  final before = old.answers[e.key];
  if (before == null || before.isEmpty) newly.add(e.key);
}
```

**지우기는 발동하지 않는다** — 사라진 키는 `widget.answers`를 도는 이 루프에 나타나지 않는다.
`initState`는 `didUpdateWidget`을 부르지 않으므로 첫 빌드도, 다시 풀기(`answers = {}`)도 조용하다.

### 4. 바운딩과 `@visibleForTesting` getter

`PlacedWord.cells`는 시작→끝 순서이므로 바운딩은 양 끝 셀만으로 구한다 —
`Rect.fromLTWH(first.$2, first.$1, last.$2 - first.$2 + 1, last.$1 - first.$1 + 1)`(전부 `toDouble()`).

```dart
@visibleForTesting
Map<(int, int), double> get pop {
  final curve = _popCurve;
  if (_popCells.isEmpty || curve == null) return const {};
  final v = curve.transform(_pop.value);
  return {for (final c in _popCells) c: v};
}

@visibleForTesting
Rect? get selectionRect {
  final a = _prevBounds, b = _nextBounds, curve = _selectionCurve;
  if (a == null || b == null || curve == null) return null;
  final r = Rect.lerp(a, b, curve.transform(_selection.value))!;
  return Rect.fromLTWH(r.left * _cell, r.top * _cell, r.width * _cell, r.height * _cell);
}

@visibleForTesting
double get cursorOpacity => _cursor.value;
```

바운딩을 셀 단위로 들고 있는 이유: `cell`은 `LayoutBuilder` 안에서만 정해지는데 트리거는 `didUpdateWidget`에서 일어난다.
`build`가 `_cell = cell;`을 먼저 실행하고 그 뒤 `selectionRect`를 읽어 `GridPainter`에 넘긴다 —
`setState` 없이 필드만 쓰므로 빌드 중 부작용이 아니다.

### 5. `build`

`LayoutBuilder` · `side = constraints.maxWidth.clamp(0.0, constraints.maxHeight)` · `SizedBox` · `GestureDetector` ·
`cellForOffset` · `_handleTap`은 **그대로 둔다.** 바뀌는 곳은 두 줄이다.

1. `LayoutBuilder` 본문 첫 줄에 `_cell = cell;`
2. `GridPainter(...)` 인자에 `selectionRect: selectionRect, cursorOpacity: cursorOpacity, pop: pop` 추가
   (나머지 인자는 `widget.` 접두사만 붙는다)

`pop`은 정지 상태에서 `const {}`를 돌려주므로 `mapEquals`가 매번 true → `shouldRepaint`가 false다(상위 문서 "정지 규율").

## 막히면

- **`didUpdateWidget`에서 이전 `answers`와 비교가 안 됨** → `PuzzleModel.setWordInput`과 `retry()`가 매번 **새 맵**을 대입한다(필드 주석에 이유가 적혀 있다). 같은 인스턴스가 오면 모델 쪽 버그다.
- **선택을 바꿔도 E-02가 안 돈다** → `PlacedWord`는 `==`를 재정의하지 않는다. `old.selected != widget.selected`는 인스턴스 비교이고, `PuzzleModel.selectCell`은 `puzzle.words`의 다른 원소를 대입하므로 정상 동작한다. 같은 단어를 다시 탭하면 인스턴스가 같아 아무 일도 없다 — 의도한 동작이다.
- **`initState`에서 `GameMotion.of(context)`를 부르고 싶다** → 부르지 않는다. `MediaQuery` 의존이 생겨 `initState`에서는 금지다. duration은 `forward` 직전에 넣는다.
- **팝이 끝나도 계속 재그리기됨** → `_pop`의 `addStatusListener`가 `_popCells`를 비우지 않은 것이다. `pop`이 `const {}`를 돌려주는지 먼저 확인한다.
- **보간 사각형이 검은 칸까지 덮음** → 층 2는 페인터 몫이다(07-03-01). `rect.overlaps(cellRect) && !blocked` 조건을 확인한다.
- **감소 모션인데 한 프레임 깜빡임** → `Duration.zero` 분기에서 `forward`를 부르지 않았는지 본다. `duration = Duration.zero`로 `forward`하면 한 프레임 0값이 그려진다.
- **`_cell`이 0이라 `selectionRect`가 0 크기** → 첫 레이아웃 전에 getter를 읽은 경우다. 테스트는 `pumpWidget` 뒤에 읽으므로 문제되지 않는다.
