## 목표

`tools/schema.sql`(02-09)과 **1:1 대응하는** drift 스키마를 만들고, 실제 `words.sqlite` 를
열어 스키마가 맞는지 검증한다. 이게 1·2단계를 잇는 계약 검증이다.

## 컨텍스트

- `tools/schema.sql` — **단일 진실.** 이 파일이 기준이고 drift가 따라간다
- [03-data-layer.md](03-data-layer.md) A절 — raw SQL 기반 판단 근거

## 설계 결정: raw SQL 중심

> 패턴 질의가 동적(고정 자리 수가 가변)이므로 `customSelect`가 편하다.
> 테이블 클래스는 타입 안정성 정도로만 쓴다.

- `findByPattern`(03-03)은 `WHERE` 절이 호출마다 달라진다 → drift 쿼리 빌더보다 `customSelect` 가 단순하다.
- 테이블 클래스는 정의하되, **마이그레이션은 쓰지 않는다.** 시드 DB가 이미 완성된 스키마로 온다.
- `schema_version` 불일치 시 정책은 "시드로 덮어쓰기 + `word_stat` 보존" 한 가지뿐 (03-02).

## `app_database.dart`

```dart
import 'package:drift/drift.dart';

part 'app_database.g.dart';

@DataClassName('WordRow')
class Words extends Table {
  @override String get tableName => 'word';

  TextColumn get headword => text()();
  IntColumn get len => integer()();
  TextColumn get c1 => text()();
  TextColumn get c2 => text()();
  TextColumn get c3 => text().nullable()();
  TextColumn get c4 => text().nullable()();
  TextColumn get c5 => text().nullable()();
  IntColumn get tier => integer()();
  TextColumn get pos => text()();
  IntColumn get freqRank => integer().named('freq_rank').nullable()();
  IntColumn get source => integer()();

  @override Set<Column> get primaryKey => {headword};
}

@DataClassName('SenseRow')
class Senses extends Table {
  @override String get tableName => 'sense';

  TextColumn get senseId => text().named('sense_id')();
  TextColumn get headword => text()();
  TextColumn get definition => text()();
  TextColumn get synonyms => text().nullable()();
  IntColumn get source => integer()();

  @override Set<Column> get primaryKey => {senseId};
}

@DataClassName('WordCharRow')
class WordChars extends Table {
  @override String get tableName => 'word_char';

  TextColumn get ch => text()();
  TextColumn get headword => text()();

  @override Set<Column> get primaryKey => {ch, headword};
}

@DataClassName('WordStatRow')
class WordStats extends Table {
  @override String get tableName => 'word_stat';

  TextColumn get headword => text()();
  IntColumn get correct => integer().withDefault(const Constant(0))();
  IntColumn get wrong => integer().withDefault(const Constant(0))();
  IntColumn get lastSeen => integer().named('last_seen').nullable()();

  @override Set<Column> get primaryKey => {headword};
}

@DataClassName('MetaRow')
class Metas extends Table {
  @override String get tableName => 'meta';

  TextColumn get key => text()();
  TextColumn get value => text()();

  @override Set<Column> get primaryKey => {key};
}

@DriftDatabase(tables: [Words, Senses, WordChars, WordStats, Metas])
class AppDatabase extends _$AppDatabase {
  AppDatabase(super.e);

  /// 시드 DB가 완성된 스키마로 오므로 drift 마이그레이션을 쓰지 않는다.
  /// 버전 불일치 처리는 db_bootstrap(03-02)이 담당한다.
  @override
  int get schemaVersion => 1;

  @override
  MigrationStrategy get migration => MigrationStrategy(
        onCreate: (m) async {
          // 아무것도 하지 않는다. 시드 DB에 이미 테이블이 있다.
        },
      );

  Future<String?> metaValue(String key) async {
    final row = await (select(metas)..where((t) => t.key.equals(key)))
        .getSingleOrNull();
    return row?.value;
  }

  Future<int> get wordCount async {
    final r = await customSelect('SELECT COUNT(*) AS n FROM word')
        .getSingle();
    return r.read<int>('n');
  }
}
```

### 컬럼명 매핑 주의

Dart는 camelCase, SQL은 snake_case다. `.named('freq_rank')`, `.named('sense_id')`,
`.named('last_seen')` 를 빠뜨리면 **컴파일은 되는데 런타임에 "no such column"** 이 난다.

`@override String get tableName` 도 마찬가지다. drift 기본값은 `words`(복수형)라
실제 테이블 `word` 와 안 맞는다.

## 스키마 계약 검증 테스트

**2단계 DoD 5번**("3단계 drift가 이 파일을 열어 스키마 검증 테스트를 통과")이 여기서 충족된다.

`app/test/data/schema_contract_test.dart` — 실제 `assets/words.sqlite` 를 데스크톱에서 직접 연다.

```dart
// sqlite3 패키지로 파일을 직접 열어 스키마만 비교 (Flutter 런타임 불필요)
import 'dart:convert';

import 'package:sqlite3/sqlite3.dart';
import 'package:test/test.dart';

void main() {
  late Database db;
  late bool isFixture;

  setUpAll(() {
    db = sqlite3.open('assets/words.sqlite', mode: OpenMode.readOnly);
    // tools/report.py `_is_fixture()` 와 같은 판정: meta.source_versions.origin
    // 이 "fixtures" 면 이 DB 는 00-01(실사전 데이터) 승인 대기 중 만든 샘플이라
    // 데이터 규모(단어 수) 검사가 산술적으로 통과 불가능하다 (tools/README.md 02-10 참조).
    final rows =
        db.select("SELECT value FROM meta WHERE key = 'source_versions'");
    isFixture = false;
    if (rows.isNotEmpty) {
      try {
        final parsed = jsonDecode(rows.first['value'] as String);
        isFixture = parsed is Map && parsed['origin'] == 'fixtures';
      } catch (_) {
        isFixture = false;
      }
    }
  });
  tearDownAll(() => db.close());

  test('필수 테이블이 전부 있다', () {
    final names = db
        .select("SELECT name FROM sqlite_master WHERE type='table'")
        .map((r) => r['name'] as String)
        .toSet();
    expect(names, containsAll(
        ['word', 'sense', 'word_char', 'word_stat', 'meta']));
  });

  test('word 컬럼이 schema.sql과 일치', () {
    final cols = db.select('PRAGMA table_info(word)')
        .map((r) => r['name'] as String).toList();
    expect(cols, [
      'headword', 'len', 'c1', 'c2', 'c3', 'c4', 'c5',
      'tier', 'pos', 'freq_rank', 'source',
    ]);
  });

  test('패턴 질의 인덱스가 있다', () {
    final idx = db
        .select("SELECT name FROM sqlite_master WHERE type='index'")
        .map((r) => r['name'] as String).toSet();
    expect(idx, containsAll(
        ['idx_word_c1', 'idx_word_c2', 'idx_word_c3',
         'idx_word_c4', 'idx_word_c5', 'idx_sense_headword']));
  });

  test('meta 필수 키가 있다', () {
    final keys = db.select('SELECT key FROM meta')
        .map((r) => r['key'] as String).toSet();
    expect(keys, containsAll([
      'schema_version', 'db_version', 'built_at',
      'word_count', 'source_versions', 'license_notice',
    ]));
  });

  test('word_stat은 비어 있다', () {
    expect(db.select('SELECT COUNT(*) AS n FROM word_stat').first['n'], 0);
  });

  test('패턴 질의가 인덱스를 탄다', () {
    final plan = db.select(
      'EXPLAIN QUERY PLAN SELECT headword FROM word '
      'WHERE len=? AND tier IN (1,2) AND c2=?', [3, '가']);
    final text = plan.map((r) => r.values.join(' ')).join(' ');
    expect(text, contains('idx_word_c'), reason: '인덱스 미사용: $text');
  });

  test('데이터 sanity', () {
    final n = db.select('SELECT COUNT(*) AS n FROM word').first['n'] as int;
    if (isFixture) {
      // tools/report.py check() 와 동일한 근거로 규모 검사만 건너뛴다 — 티어·길이
      // 범위 검사는 규모와 무관하므로 fixtures 에서도 그대로 돌린다. 여기서
      // return 하지 않고 계속 진행해 아래 두 expect 는 그대로 돈다.
      markTestSkipped(
          '샘플 빌드(origin=fixtures): 단어 수 규모 검사 건너뜀 ― tools/README.md 02-10 참조');
    } else {
      expect(n, greaterThan(1000));
    }
    expect(db.select(
        'SELECT COUNT(*) AS n FROM word WHERE tier < 1 OR tier > 7')
        .first['n'], 0);
    expect(db.select(
        'SELECT COUNT(*) AS n FROM word WHERE len < 2 OR len > 5')
        .first['n'], 0);
  });
}
```

'데이터 sanity' 의 단어 수 검사는 **규모에 딸린 검사**라 02-08·02-09·02-10(`tools/report.py
check()`)이 이미 쓴 방식을 그대로 따른다 — `meta.source_versions.origin == "fixtures"`
(00-01 실사전 데이터 미승인으로 샘플 빌드된 상태)면 단어 수 검사만 건너뛰고, 티어·길이
범위 검사는 규모와 무관하므로 그대로 돌린다. 00-01 실데이터가 도착해 `--fixtures` 없이
다시 빌드되면 이 분기 없이도 자동으로 전체 검사가 돈다.

`sqlite3` 패키지를 `dev_dependencies` 에 추가한다 (`sqlite3: ^2.4.0`).
데스크톱 테스트에는 네이티브 라이브러리가 필요하므로, Windows에서 안 되면
이 테스트를 `flutter test` 대신 `dart test` 로 돌리고 `sqlite3.dll` 경로를 지정한다.

## 막히면

- **`no such column: freq_rank`** → `.named()` 누락. 전 컬럼을 schema.sql과 나란히 놓고 대조한다.
- **`no such table: words`** → `tableName` 오버라이드 누락. drift는 클래스명 복수형을 기본 테이블명으로 쓴다.
- **build_runner가 실패** → `dart run build_runner clean` 후 재시도. `part` 선언 파일명이 실제 파일명과 같은지 확인.
- **`sqlite3` 네이티브 라이브러리 없음(Windows)** → `sqlite3_flutter_libs` 는 Flutter 런타임용이다. 순수 Dart 테스트에는 `sqlite3.dll` 이 필요하다. `winget install SQLite.SQLite` 로 설치하거나, 이 테스트를 Flutter 통합 테스트로 옮긴다.
- **`EXPLAIN QUERY PLAN` 에 인덱스가 안 나옴** → 02-09의 "막히면" 절대로 `schema.sql` 의 인덱스 컬럼 순서를 `(len, cN, tier)` 로 바꾸고 **2단계를 재빌드**한다. drift 쪽을 고쳐서 될 문제가 아니다.
