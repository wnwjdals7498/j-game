선행: 02-03 · 다음: 02-05
상위: [02-tools-etl.md](02-tools-etl.md)

> **정정 (02-01 재조사, 2026-09-17)**: 실제로는 **XML 이 아니라 JSON**이고, 구조도
> 기초사전과 전혀 다른 평평한 `{"channel": {"item": [...]}}` 형태다. `iterparse`/`lxml`
> 관련 절은 **해당 없음**이다 — 파일당 최대 10.1MB 라 `json.load` 로 88개 파일을 전부
> 읽어도 6.7초다. **가장 중요한 정정**: 아래 "표준 고유 필터" 표의 방언/옛말/북한어
> 행은 **실데이터에 판정 근거가 없어(전수 스캔 436,587건으로 확인) 삭제됐다** — 구현은
> 구·속담·관용구(`word_unit`) 제외만 한다. 유의어 관계값도 "비슷한말" 이 아니라
> "동의어"(다수)+"비슷한말"(소수) 다. 근거는
> [tools/README.md](../../tools/README.md) "2. 표준국어대사전" 절 참조.

## 목표

표준국어대사전 XML → `build/entries.stdict.jsonl`. **02-03과 완전히 같은 출력 스키마.**

## 역할은 "보충"뿐 (DESIGN 2절)

> 기초사전은 학습자용이라 뜻풀이 짧고 깔끔. 표준은 방언·옛말·전문어 범벅이라 필터 비용 큼

- 표제어가 기초사전에 있으면 **기초사전 것을 쓴다** (02-07 merge에서 처리).
- 표준 보충분은 대부분 최하위 티어라 채움용으로 못 쓴다 (DESIGN 5절).
  **3단계 실패율 측정 후 투입 여부를 결정**한다. 지금은 일단 파싱해 둔다.

## 핵심 리스크: 파일 크기

> 표준국어대사전 전체 XML은 수백 MB → `iterparse` 스트리밍 필수. 메모리에 한 번에 올리지 않는다.

02-03과 같은 `iterparse` + `el.clear()` 패턴. 여기서는 **반드시** 지켜야 한다.

메모리가 계속 증가하면 `lxml` 도입:

```powershell
# tools/requirements.txt 에 lxml 추가 후
tools\.venv\Scripts\python.exe -m pip install -r tools/requirements.txt
```

```python
from lxml import etree as ET   # API가 거의 호환

for ev, el in ET.iterparse(path, events=("end",), tag=ITEM):
    ...
    el.clear()
    while el.getprevious() is not None:
        del el.getparent()[0]      # 부모에 쌓인 빈 껍데기 제거
```

`lxml` 은 `tag=` 필터를 지원해 관심 없는 요소를 아예 건너뛴다. 속도도 2~3배 빠르다.
**도입하면 `tools/requirements.txt` 와 `tools/README.md` 에 이유를 기록한다.**

## 표준 고유 필터 (02-06에 넘기기 전)

표준에는 게임에 쓸 수 없는 항목이 대량으로 섞여 있다. **파싱 단계에서 미리 버리면** 뒤 단계가 가벼워진다.

> **정정 (02-01 재조사, 2026-09-17)**: 아래 표는 원래 방언/옛말/북한어 행도 있었다.
> 실데이터 436,587건을 전수 스캔한 결과 **그 판정 근거 자체가 없다** — `dialect_info`/
> `region_info` 필드가 없고, `word_type` 은 어원 유형(고유어/한자어/외래어/혼종어)일
> 뿐 방언/옛말/북한어 값이 없으며, `sense_info.type` 은 전 항목이 `"일반어"` 로 고정돼
> 있고, 정의문 텍스트의 `'OO'의 방언`/`'OO'의 옛말` 패턴도 0건이다. 그래서 그 두 행을
> **제거했다** — 구·속담·관용구 제외(`word_unit`, 신뢰 가능)만 남는다. 근거는
> [tools/README.md](../../tools/README.md) "2. 표준국어대사전" 절.

| 버릴 것 | 판단 근거 필드 |
|---|---|
| 전문어 | `sense_info.cat_info` 가 있음 — **sense 레벨**이고 46%에 붙어 있어(2026-09-17 실측) `DROP_TECHNICAL = False` 로 기본 꺼둔다. 과도하게 버리지 않도록 02-10 눈 검수에서 확인 |
| 구·속담·관용구 | `word_info.word_unit in {"구", "속담", "관용구"}` |

버린 개수를 단계 로그에 찍는다. 나중에 "채움 풀 부족"이면 이 필터를 완화하는 게 첫 번째 손잡이다.

```python
def run(use_fixtures: bool = False) -> int:
    stats = {"total": 0, "kept": 0, "drop_phrase": 0, "drop_technical": 0}
    ...
    print(f"    stdict: {stats}")
    return stats["kept"]
```

## 출력 스키마

02-03과 동일. `source` 만 `"stdict"`, `sense_id` 접두어는 `"stdict:"`.

```json
{
  "source": "stdict",
  "sense_id": "stdict:98765",
  "raw_headword": "가게^주인",
  "homonym": null,
  "pos": "명사",
  "word_type": "구",
  "definition": "...",
  "synonyms": []
}
```

**주의**: 표준 표제어에는 `^`(띄어쓰기 표시), `-`(접사), `ㆍ` 등이 섞인다.
**여기서 고치지 않는다.** `raw_headword` 에 원문 그대로 넣고 02-06이 판정한다.

## 라이선스

02-03과 동일. 예문·발음·음성·이미지 **파싱하지 않는다.** 같은 테스트를 표준 샘플로도 돌린다.

## 구현 골격

```python
# tools/parse_stdict.py
from pathlib import Path
from . import config, io_util

OUT = "entries.stdict.jsonl"

DROP_WORD_TYPES = {"방언", "옛말", "북한어"}
DROP_WORD_UNITS = {"구", "속담", "관용구"}

def run(use_fixtures: bool = False) -> int:
    files = _src_files(use_fixtures)
    if not files:
        # 표준은 선택 자료다. 없으면 빈 파일을 내고 경고만 남긴다.
        print("    stdict: 원본 없음 → 빈 파일 생성 (기초사전만으로 진행)")
        return io_util.write_jsonl(config.BUILD / OUT, [])
    ...
```

**기초사전과 달리 표준은 없어도 파이프라인이 돌아야 한다.** 승인이 늦거나 거부될 수 있고,
DESIGN상 보충 역할이기 때문이다 (00-01 "막히면" 절).
