# 04-05. 제출 · 결과 화면

## 목표

제출 → 일괄 채점 → 결과 화면. 플레이 루프의 끝을 닫는다.

## 제출 흐름

> 확인 다이얼로그(빈칸 N개 있음 안내) → 일괄 채점 → 결과 화면.
> 첫 제출만 통계 반영(3단계 stat_repository).

```dart
Future<void> submit(BuildContext context) async {
  final blanks = Scorer.blankCellCount(puzzle!, answers);   // 01-08

  final ok = await showDialog<bool>(
    context: context,
    builder: (c) => AlertDialog(
      title: const Text('제출하시겠습니까?'),
      content: Text(blanks > 0
          ? '빈 칸이 $blanks개 있습니다. 빈 칸은 오답으로 처리됩니다.'
          : '모든 칸을 채웠습니다.'),
      actions: [
        TextButton(onPressed: () => Navigator.pop(c, false),
            child: const Text('계속 풀기')),
        FilledButton(onPressed: () => Navigator.pop(c, true),
            child: const Text('제출')),
      ],
    ),
  );
  if (ok != true) return;

  final isFirst = await scope.stats.isFirstSubmit(puzzle!.levelId, puzzle!.seed);
  final r = Scorer.score(puzzle!, answers, isFirstSubmit: isFirst);
  await scope.stats.recordSubmit(
      levelId: puzzle!.levelId, seed: puzzle!.seed, result: r);

  submitted = true;
  result = r;
  notifyListeners();
}
```

**`isFirstSubmit` 를 먼저 조회해 `SubmitResult` 에 담는다.** `recordSubmit` 도 내부에서
다시 확인하지만(03-04), 결과 화면이 "이번 제출은 통계에 반영되지 않았습니다" 를 표시하려면
값이 필요하다.

### 제출 후 격자

격자가 O/X 를 표시한다 (04-02의 `result` 파라미터). 결과 화면으로 넘어가기 전에
**격자 상태를 한 번 보여줄지**는 선택이다. 1차는 바로 결과 화면으로 넘어간다.

## 결과 화면

> 단어별 정답/오답/빈칸, 뜻풀이 노출, "다시 풀기" / "다음 레벨". 재제출은 통계 미반영 안내

```
┌─────────────────────────────┐
│  레벨 5 · 들머리             │
│  8 / 12 정답    점수 +4      │
│  ⓘ 재제출이라 기록에 반영되지 않았습니다  ← isFirstSubmit == false일 때만
├─────────────────────────────┤
│ ✓ 가로1  사과                │
│    사과나무의 열매.           │
│ ✗ 세로2  나무    입력: 나물   │
│    줄기가 목질로 된 식물.      │
│ ○ 가로4  과일    입력: (빈칸) │
│    나무에서 나는 먹을 수 있는… │
├─────────────────────────────┤
│  [다시 풀기]   [다음 레벨]    │
└─────────────────────────────┘
```

| 요소 | 내용 |
|---|---|
| 헤더 | 레벨 이름, `correctCount / total`, `score` |
| 재제출 안내 | `isFirstSubmit == false` 일 때만 표시 |
| 단어 목록 | 번호(04-03) + 표제어 + 상태 아이콘 |
| 상태 | `✓` 정답 / `✗` 오답(입력 표시) / `○` 빈칸 |
| 뜻풀이 | **마스킹하지 않은 원문.** 답을 이미 알았으므로 |
| 유의어 | 있으면 함께 표시 |
| 버튼 | 다시 풀기 / 다음 레벨 |

**`blank` 와 `wrong` 을 구분해 표시한다** (01-08이 구분해 둔 이유).
점수상으로는 둘 다 오답이지만, 유저에게는 "몰라서 안 썼다"와 "틀렸다"가 다르다.

### 정렬

번호 순(격자 위→아래, 왼→오른쪽). 오답을 위로 모으는 방식도 있지만,
격자와 순서가 달라 헷갈린다. **번호 순을 유지**한다.

### 버튼 동작

| 버튼 | 동작 |
|---|---|
| 다시 풀기 | **같은 seed**로 같은 퍼즐 재도전. `answers` 초기화, `submitted = false`. 통계 미반영 |
| 다음 레벨 | 다음 레벨을 **새 seed**로 생성. 마지막 레벨이면 홈으로 |

"새 퍼즐" (같은 레벨, 다른 seed) 버튼도 유용하지만 1차는 생략한다.

seed 생성 규칙:

```dart
int newSeed() => DateTime.now().millisecondsSinceEpoch & 0x7FFFFFFF;
```

`Puzzle.seed` 가 `word_stat` 의 첫 제출 판정 키(03-04)이므로 매번 달라야 한다.

## 레벨 해제

> 레벨 해제 규칙: 이전 레벨 1회 클리어. `clearScore` 기준 (03-06)

결과 화면에서 `score >= spec.clearScore` 면 다음 레벨이 해제된다.
해제 여부는 `word_stat` 이 아니라 `puzzle_log` 의 `first_score` 로 판정한다(03-04의 `bestScore`).

해제 순간에 짧은 안내를 띄운다: "레벨 6이 열렸습니다".

## 상태 유지

> 앱이 백그라운드로 가도 입력 내용 유지(메모리 상태로 충분, 1차는 영구 저장 안 함).

`PuzzleModel` 이 `ChangeNotifier` 로 살아 있으면 유지된다.
**안드로이드가 프로세스를 죽이면 사라진다.** 1차 범위상 허용 (04-ui "범위 밖: 진행 상태 영구 저장").

## 막히면

- **재제출인데 `word_stat` 이 또 바뀜** → `puzzle_log` PK가 `(level_id, seed)` 인지, "다시 풀기" 가 같은 seed를 쓰는지 확인. 새 seed면 당연히 첫 제출이다.
- **"다시 풀기" 후에도 이전 입력이 남음** → `answers.clear()` + `submitted = false` + `result = null` 셋 다 필요하다.
- **다음 레벨이 안 열림** → `clearScore` 기본값이 0인지, `bestScore` 가 `puzzle_log` 를 보는지 확인.
- **백그라운드 복귀 후 입력이 사라짐** → 프로세스가 죽은 것이다. 1차 범위 밖. 필요하면 `answers` 를 `puzzle_log` 옆 테이블에 저장하는 기능을 v2로 미룬다.
- **결과 화면이 길어 스크롤이 불편** → 단어 20~30개면 긴 게 맞다. 접기/펼치기보다 `ListView` 로 두는 쪽이 단순하다.
