## 목표

퍼즐 화면에 남은 `AlertDialog` 셋을 전부 바텀 시트(E-12)로 바꾼다. UI-GUIDE 4절이 "`AlertDialog`는 남기지 않는다"고 못 박았다.

**문구와 버튼 라벨은 글자 하나도 바꾸지 않는다**(INV-09, N-09). 표현만 바뀐다.

## 컨텍스트 (시작 전 읽기)

- `app/lib/ui/puzzle/puzzle_page.dart` 69~83줄 — 튜토리얼 `showDialog`. 문구 4줄의 실제 값
- `app/lib/ui/state/puzzle_model.dart` 158~208줄 — `submit(BuildContext)`. **`showDialog`가 두 군데**다(제출 확인 + 오류 안내)
- `app/lib/domain/scoring/scorer.dart` — `blankCellCount`. 시트에 넘길 `blanks`
- `app/test/ui/submit_test.dart` 135~175줄 — `_openSubmitDialog`/`_confirmDialog`/`_cancelDialog` 헬퍼가 `find.text('제출').last`로 확인 버튼을 고른다
- `app/test/ui/tutorial_test.dart` — `find.text('이렇게 플레이해요')`와 `find.text('확인')`으로 찾는다. 타입으로 찾지 않으므로 셀렉터 수정이 필요 없다
- `app/lib/ui/theme/tokens.dart` — 07-02-03의 `bottomSheetTheme`이 상단 반지름 `GameRadius.panel`과 배경 `surface`를 이미 준다

INV-09 목록의 `모든 칸을 채웠습니다`는 부분 문자열이고, 코드의 실제 값에는 마침표가 있다. `submit_test.dart`가 `find.text('모든 칸을 채웠습니다.')`로 **정확히** 찾으므로 마침표를 떼면 테스트가 깨진다.

**버튼 순서도 유지한다**(취소 → 확인). `submit_test.dart`·`play_loop_test.dart`가 `find.text('제출').last`로 확인 버튼을 고르는데, 시트가 오버레이 위에 있으므로 `.last`는 여전히 시트 쪽을 가리킨다. 시트 안에 `'제출'`이 두 번 나오면 안 된다.

## 작업

### 1. `puzzle_sheets.dart`

```dart
Future<void> showTutorialSheet(BuildContext context) => showModalBottomSheet<void>(
      context: context,
      isScrollControlled: false,
      useSafeArea: true,
      builder: (c) => _SheetBody(
        title: '이렇게 플레이해요',
        body: '• 칸을 누르면 …',                       // 위 표 그대로
        actions: [_SheetAction(label: '확인', primary: true, onTap: () => Navigator.pop(c))],
      ),
    );

/// 제출 확인. 취소·바깥 탭·뒤로가기는 전부 false.
Future<bool> showSubmitConfirmSheet(BuildContext context, {required int blanks}) async {
  final ok = await showModalBottomSheet<bool>(
    context: context,
    isScrollControlled: false,
    useSafeArea: true,
    builder: (c) => _SheetBody(
      title: '제출하시겠습니까?',
      body: blanks > 0
          ? '빈 칸이 $blanks개 있습니다. 빈 칸은 오답으로 처리됩니다.'
          : '모든 칸을 채웠습니다.',
      actions: [
        _SheetAction(label: '계속 풀기', primary: false, onTap: () => Navigator.pop(c, false)),
        _SheetAction(label: '제출',     primary: true,  onTap: () => Navigator.pop(c, true)),
      ],
    ),
  );
  return ok ?? false;
}

Future<void> showSubmitErrorSheet(BuildContext context) => /* '제출할 수 없습니다' */;
```

`_SheetBody`: `Padding(GameSpace.l)` → `Column(mainAxisSize: min, crossAxisAlignment: start)` — 제목 `GameType.title`, `SizedBox(GameSpace.m)`, 본문 `GameType.body` (`color: ink`), `SizedBox(GameSpace.xl)`, 액션 `Row`(보조가 왼쪽, `Expanded` 2개 사이 `SizedBox(GameSpace.m)`; 액션이 하나면 폭 전체).

`_SheetAction`: 07-04-03의 `SubmitButton`과 같은 규격(높이 52, `GameRadius.pill`, 기본 = `ink`/`surface` 700, 보조 = 투명/`line` 1.5/`ink` 600)이지만 **상태 전환이 없다**. `SubmitButton`을 재사용하지 않는다 — 그쪽은 `active` 애니메이션이 본질이고 라벨이 `'제출'`로 고정이다.

E-12(하단에서 상승, `base`/`curveEmphasized`)와 상단 반지름은 `showModalBottomSheet` 기본 동작 + 07-02-03 `bottomSheetTheme`이 준다. 이 파일에서 `Duration`을 만들지 않는다(INV-12).

### 2. 호출부 교체 3곳

| 파일 | 현재 | 교체 |
|---|---|---|
| `puzzle_page.dart` `_maybeShowTutorial` | `await showDialog<void>(… AlertDialog …)` | `await showTutorialSheet(context);` |
| `puzzle_model.dart` `submit` 앞부분 | `final ok = await showDialog<bool>(… AlertDialog …); if (ok != true) return;` | `final ok = await showSubmitConfirmSheet(context, blanks: blanks); if (!ok) return;` |
| `puzzle_model.dart` `submit`의 `catch` | `await showDialog<void>(… AlertDialog …)` | `await showSubmitErrorSheet(context);` |

`puzzle_model.dart`에 `import '../puzzle/puzzle_sheets.dart';`를 추가한다. 모델이 UI 파일을 import하는 건 이미 `submit(BuildContext)`가 `material.dart`를 쓰는 구조의 연장이다 — 제출 확인을 페이지로 끌어올리지 **않는** 이유는 `submit_test.dart`의 보호 테스트("빈칸 있음: 빈칸 개수 문구 표시", "재제출: isFirstSubmit == false, word_stat 불변")가 `model.submit(context)`를 직접 불러 확인 UI를 검증하기 때문이다. 시그니처를 바꾸면 INV-08 테스트가 깨진다.

`if (!context.mounted) return;` 가드는 `catch` 절에 있던 그대로 둔다.

## 막히면

- **`find.text('제출').last`가 페이지 버튼을 가리킴** → 시트 안에서 `'제출'`이 액션보다 먼저 나오는 위치(제목·본문)에 들어갔다. 본문에 `"제출"`이 포함된 튜토리얼 문구는 제출 확인 시트와 함께 뜨지 않으므로 무관하다.
- **시트가 닫힌 뒤 `WordInput` 포커스가 죽음** → `FocusScope.of(context).unfocus()` 후 필요할 때만 `model.selected`를 재할당해 `WordInput.didUpdateWidget` 경로를 태운다(07-04 "막히면"). `WordInput` 내부는 고치지 않는다.
- **`showModalBottomSheet`가 `Future<bool>`을 null로 돌려줌** → 바깥을 탭하거나 뒤로가기로 닫힌 경우다. `?? false`가 이미 처리한다. `isDismissible: false`로 막지 않는다 — 제출은 파괴적 동작이 아니다.
- **`pumpAndSettle`이 시트에서 멈추지 않음** → 시트 진입 애니메이션은 `base`(240ms)로 끝난다. 안 끝나면 화면 어딘가에 무한 애니메이션이 있다는 뜻이므로 E-04·E-05 쪽을 확인한다.
- **`BottomSheet` 타입을 못 찾음** → `showModalBottomSheet`는 `BottomSheet` 위젯을 만든다. 버전 차이로 안 잡히면 `find.byType(BottomSheet)` 대신 시트 안 고유 문구(`'계속 풀기'`)로 단언하고, `find.byType(AlertDialog)`가 0인지만 확인한다.
