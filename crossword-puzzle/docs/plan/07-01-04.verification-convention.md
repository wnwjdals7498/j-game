## 작업

### 1. `app/README.md`에 "검증 3종"

기본 템플릿 아래에 절을 덧붙인다. 순서가 중요하다 — **가장 싼 검사가 먼저**다. 불변 조건은 수 초, `analyze`는 수십 초, `flutter test`는 분 단위다.

````markdown
## 검증 3종

`app/` 에서 아래 셋을 순서대로 돌린다. 하나라도 실패하면 작업이 끝나지 않은 것이다.

```powershell
cd app
dart run tool/check_invariants.dart   # UI-GUIDE 7절 불변 조건 (INV-01~11)
flutter analyze                       # 정적 분석 0건
flutter test                          # 전체 테스트
```

- `check_invariants.dart` 는 규칙을 어기면 `PASS/FAIL/SKIP` 목록과 위반 위치를
  찍고 exit 1을 낸다. 규칙의 원본은 `docs/UI-GUIDE.md` 7절 표다.
- `--git-base <ref>` 를 주면 INV-07(`lib/domain`·`lib/data` 무수정)까지 검사한다.
  인자가 없으면 그 규칙만 SKIP으로 표시된다.
- 규칙을 추가·수정할 때는 `tool/invariants/rules.dart` 와 UI-GUIDE 7절 표를
  **같은 커밋에서** 고친다.
````

### 2. 06-06 CI 문서에 스텝 추가

`.github/workflows/`가 없으므로 **워크플로 파일을 새로 만들지 않는다.** 06-06이 "선택"으로 남겨 둔 결정을 이 문서가 뒤집지 않는다. 06-06 A절 YAML 예시의 `dart analyze` **앞**에 한 줄만 넣는다.

```yaml
      # 07-01: UI-GUIDE 7절 불변 조건. PR에서는 base와의 diff로 INV-07까지 본다.
      - run: dart run tool/check_invariants.dart --git-base origin/${{ github.base_ref || 'main' }}

      - run: dart analyze --fatal-infos
```

06-06이 나중에 실제로 실행될 때 이 줄이 그대로 들어간다. `--git-base`는 PR에서만 의미가 있고, push 이벤트에서는 `github.base_ref`가 비어 `main`으로 폴백한다.

### 3. UI-GUIDE 7절 표 ↔ `rules.dart` 1:1 대조

표 14행과 `rules` 15항목을 손으로 맞춘다. 결과는 아래여야 한다.

| UI-GUIDE 7절 | `rules.dart` | 상태 |
|---|---|---|
| INV-01 | `INV-01` | 1:1 |
| INV-02 | `INV-02a` + `INV-02b` | 표 1행이 규칙 2개로 분할 |
| INV-03 | `INV-03` | 1:1 |
| INV-04 | `INV-04a` + `INV-04b` | 분할 |
| INV-05 | `INV-05` | 1:1. 범위는 `lib/ui` + `lib/main.dart`, `lib/ui/theme/` 제외 |
| INV-06 | `INV-06a` + `INV-06b` + `INV-06c` | 분할 |
| INV-07~INV-11 | 같은 ID | 1:1 |
| INV-12, 13, 14 | 없음 | **정상.** 12는 07-02-02가, 13·14는 07-02의 `theme_test.dart`가 도입 |

`a/b/c` 분할은 표를 위반하지 않는다 — 표의 "검사 방법" 칸이 이미 조건 2~3개를 `,`로 나열하고 있고, 실행기가 위반 위치를 정확히 찍으려면 규칙을 쪼개야 한다. 대신 **표에 없는 ID가 생기면 안 된다.** 대조에서 어긋나는 게 나오면 코드가 아니라 어느 쪽이 맞는지 판단해 한쪽을 고치고, 이 문서의 표를 갱신한다.

### 4. 07-02 이후를 위한 인계 메모

이 묶음이 끝난 뒤 규칙을 건드릴 문서는 정해져 있다.

| 문서 | `rules.dart`에 할 일 |
|---|---|
| 07-02-01 | INV-05 `exclude`에 `lib/ui/theme/`가 이미 있다. 변경 없음 |
| 07-02-02 | **INV-12 추가** (`lib/ui`에 `Duration(milliseconds` 없음, `exclude: ['lib/ui/theme/']`) |
| 07-02-03 | 규칙 변경 없음. 07-01-01이 지운 `colorSchemeSeed` 자리를 `buildLightTheme()`/`buildDarkTheme()`로 채운다. `pubspec.yaml` 151~152줄의 `colorSchemeSeed` 언급 주석도 여기서 고친다 |
| 07-03~07-07 | 규칙 변경 없음. 검증 절에서 실행만 한다 |
| 07-08 | 골든 테스트 이름은 `protectedTests`에 넣지 않는다(기존 테스트 보호가 목적) |
