## 작업

### 1. `tool/invariants/runner.dart` — 결과 타입

```dart
import 'dart:io';
import 'rules.dart';

enum Status { pass, fail, skip }

/// 위반 1건. [line]이 0이면 줄 개념이 없는 검사(depsExact, gitClean, testNamesExist).
class Finding {
  final String path;    // root 기준 상대 경로, 구분자는 항상 '/'
  final int line;       // 1-based
  final String detail;  // 예: '"Colors.amber"' / '누락: 제출'
  const Finding(this.path, this.line, this.detail);
  @override
  String toString() => line > 0 ? '$path:$line $detail' : '$path $detail';
}

class RuleResult {
  final Rule rule;
  final Status status;
  final List<Finding> findings;
  final String? note;   // SKIP 사유
  const RuleResult(this.rule, this.status, {this.findings = const [], this.note});
}

class InvariantReport {
  final List<RuleResult> results;
  const InvariantReport(this.results);

  RuleResult byId(String id) => results.firstWhere((r) => r.rule.id == id);
  int get passed => results.where((r) => r.status == Status.pass).length;
  int get failed => results.where((r) => r.status == Status.fail).length;
  int get skipped => results.where((r) => r.status == Status.skip).length;
  bool get ok => failed == 0;
  String render() { /* 작업 4 "출력 형식" */ }
}

/// [root]는 app/ 또는 fixture를 심은 임시 디렉터리. [gitBase]가 null이면
/// Kind.gitClean 규칙은 SKIP.
InvariantReport runInvariants(Directory root, {String? gitBase}) { ... }
```

`byId`는 07-01-03의 fixture 테스트가 "이 규칙만 FAIL"을 단정하는 데 쓴다.

### 2. 파일 수집과 줄 필터 (모든 Kind 공통)

| 규칙 | 동작 |
|---|---|
| `paths` 항목이 파일 | 그 파일 하나 |
| `paths` 항목이 디렉터리 | 재귀, `.dart`만 |
| `exclude` | `root` 기준 상대 경로가 그 접두로 시작하면 제외 |
| 경로 없음 | 그 항목을 건너뛴다(빈 fixture에서 크래시 금지) |
| 인코딩 | `readAsStringSync()`. 선두 `﻿`(BOM)는 잘라낸다 |
| 주석 줄 | `trimLeft()`가 `//`로 시작하면 **모든 검사에서 무시** |

블록 주석(`/* */`)은 이 저장소에 없으므로 다루지 않는다. 생기면 규칙이 아니라 코드를 고친다.

### 3. `Kind` 6종 구현

| Kind | 판정 | Finding |
|---|---|---|
| `mustContain` | `paths`가 파일이면 **그 파일 안에** 모든 `needles`가 1회 이상. 디렉터리면 **디렉터리 전체에서** 각 needle이 1회 이상(INV-09) | `Finding(경로, 0, '누락: <needle>')` |
| `mustNotContain` | 어떤 needle도 나오면 안 됨. **모든 위반 줄을 다 모은다** | `Finding(경로, 줄번호, '"<needle>"')` |
| `testNamesExist` | `paths`(`test`) 아래 `.dart` 전체 텍스트를 이어 붙여 각 needle이 부분 문자열로 존재 | `Finding('test', 0, '누락: <이름>')` |
| `levelsMax` | `RegExp(r'(?:width\|height):\s*(\d+)')`로 전부 뽑아 `max` 초과 검사 | `Finding(경로, 줄번호, 'width: 9 > 8')` |
| `depsExact` | `dependencies:` 다음 줄부터 **들여쓰기 0인 줄**을 만날 때까지, 정확히 2칸 들여쓴 `키:` 이름을 모아 `allowedDeps`와 집합 동일성 | `Finding('pubspec.yaml', 0, '추가됨: lottie')` / `'빠짐: provider'` |
| `gitClean` | `gitBase == null` → SKIP. 아니면 `git diff --name-only <base> -- <paths>` 출력이 비어야 PASS | `Finding(출력 줄, 0, '수정됨')` |

INV-05 예외: `mustNotContain`이 needle `Colors.`를 찾았을 때 그 위치에서 `Colors.transparent`가 시작하면 위반이 아니다. 한 줄에 여러 번 나오면 각각 판정한다.

`depsExact` 파서 주의 — 빈 줄과 `#`로 시작하는 줄은 건너뛴다(`pubspec.yaml` `dependencies:` 블록에 주석이 6개 있다). `flutter:` 같은 하위 키(`    sdk: flutter`, 4칸)는 들여쓰기가 2칸이 아니므로 자동으로 걸러진다.

`gitClean`은 `Process.runSync('git', [...], workingDirectory: root.path, runInShell: true)`로 부른다 — Windows에서 `runInShell` 없이 실패한 전례가 있다.

### 4. 출력 형식과 exit code

```
PASS INV-01 세로 고정
SKIP INV-07 domain/data 무수정 (--git-base 없음)
FAIL INV-05 하드코딩 색 금지 — lib/ui/home/home_page.dart:200 "Colors.amber"
     lib/ui/debug/benchmark_page.dart:177 "Colors.red"
14 passed, 1 failed, 1 skipped
```

- 규칙마다 한 줄, 순서는 `rules` 선언 순서 그대로. 마지막 줄은 `N passed, M failed, K skipped`.
- FAIL은 첫 Finding을 ` — ` 뒤에 붙이고, 2번째부터는 5칸 들여쓴 줄로 **전부** 나열한다(첫 건만 보여주면 고치는 사람이 여러 번 돌린다).
- `render()`가 이 문자열 전체를 만든다. 테스트는 stdout이 아니라 `render()`를 본다.

### 5. `tool/check_invariants.dart`

```dart
// UI-GUIDE.md 7절 불변 조건(INV-xx) 감시. app/ 에서 실행한다.
// 위반이 하나라도 있으면 exit code 1.
//
//   --git-base <ref>   INV-07(domain/data 무수정)을 이 ref와의 diff로 검사한다.
//                      없으면 INV-07은 SKIP.
import 'dart:io';

import 'invariants/runner.dart';

void main(List<String> args) {
  final report = runInvariants(Directory.current, gitBase: _arg(args, '--git-base'));
  stdout.writeln(report.render());
  if (!report.ok) exit(1);
}

String? _arg(List<String> args, String name) {
  final i = args.indexOf(name);
  if (i < 0 || i + 1 >= args.length) return null;
  return args[i + 1];
}
```

`_arg`는 `tool/measure.dart`의 `_intArg`와 같은 모양이다. 로직은 전부 `runner.dart`에 있고 이 파일은 `main`만 둔다 — 07-01-03의 테스트가 `runner.dart`를 상대 경로로 import한다.

## 막히면

- **INV-05가 `lib/main.dart`에서 FAIL** → 07-01-01 작업 1의 세 번째 행(`colorSchemeSeed: Colors.indigo` 줄 삭제)이 빠졌다. 시드를 되살리는 게 아니라 지운 상태를 유지한다(작업 2의 근거).
- **INV-11이 `dev_dependencies`까지 잡음** → 블록 경계 파싱 오류. `dependencies:` 다음 줄부터 읽다가 **들여쓰기 0인 줄**에서 멈춘다. 반대로 13개보다 적게 세면 주석·빈 줄을 건너뛰지 않았거나 `flutter:`처럼 값이 비고 하위 키만 있는 항목을 놓친 것이다.
- **INV-06a가 FAIL** → 주석 무시 규칙 때문이다. `license_page.dart`는 3·4·8·10줄 주석에도 `assets/LICENSES.md`가 있지만 50줄 코드에도 있으므로 PASS여야 한다. FAIL이면 주석 판정이 `//`보다 넓게 잡고 있다.
- **Windows에서 `git` 실패 / `exclude`가 안 먹음** → 각각 `runInShell: true`, 경로 비교 전 `\` → `/` 치환.
