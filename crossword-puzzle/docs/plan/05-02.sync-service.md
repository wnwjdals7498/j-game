# 05-02. SyncService

## 목표

6개월마다 새 DB를 내려받는 흐름을 구현한다. 실패는 **조용히 중단**하고 기존 DB를 그대로 쓴다.

> 실패는 어느 단계든 **조용히 중단, 기존 DB 그대로 사용**. 사용자 흐름을 막지 않는다.

## 범위

**네이티브만.** 웹은 1차 범위 밖 (REVIEW 4.2 (a)).
조건부 import로 웹에서는 아무것도 안 하는 구현을 넣는다.

## 흐름 (05-sync.md 그대로)

```
앱 시작 (또는 설정의 "지금 갱신")
 └→ last_sync_at 이 180일 이상 전 AND 네트워크 있음?       아니면 종료
 └→ manifest 다운로드
 └→ db_version > 현재? schema_version 호환? min_app_version 만족?  아니면 종료
 └→ 새 DB를 임시 파일로 다운로드
 └→ sha256 검증 실패 → 삭제, 종료
 └→ 새 DB 열어 sanity check (word 행 수 > 0, meta.db_version 일치, 필수 테이블)
 └→ ATTACH 기존 DB → word_stat 복사                    ← 05-03
 └→ 기존 DB 닫기 → 원자 교체 (rename) → 새 DB 열기       ← 05-03
 └→ last_sync_at 기록, "단어 N개 갱신" 한 줄 안내
```

## `manifest.dart`

```dart
class Manifest {
  final int dbVersion;
  final int schemaVersion;
  final String url;
  final String sha256;
  final int sizeBytes;
  final String minAppVersion;
  final String publishedAt;
  final int wordCount;
  final String notes;

  /// 모르는 필드는 **무시한다.** (05-01 계약)
  factory Manifest.fromJson(Map<String, dynamic> j) {
    int req(String k) => j[k] is int ? j[k] as int
        : throw ManifestError('필드 누락/타입 오류: $k');
    String reqs(String k) => j[k] is String ? j[k] as String
        : throw ManifestError('필드 누락/타입 오류: $k');

    return Manifest(
      dbVersion: req('db_version'),
      schemaVersion: req('schema_version'),
      url: reqs('url'),
      sha256: reqs('sha256'),
      sizeBytes: req('size_bytes'),
      minAppVersion: reqs('min_app_version'),
      publishedAt: reqs('published_at'),
      wordCount: j['word_count'] as int? ?? 0,
      notes: j['notes'] as String? ?? '',
    );
  }
}
```

### 버전 비교

```dart
/// "1.2.3" 형식 비교. a >= b 면 true
bool versionAtLeast(String a, String b) {
  final pa = a.split('.').map(int.parse).toList();
  final pb = b.split('.').map(int.parse).toList();
  for (var i = 0; i < 3; i++) {
    final x = i < pa.length ? pa[i] : 0;
    final y = i < pb.length ? pb[i] : 0;
    if (x != y) return x > y;
  }
  return true;
}
```

문자열 비교(`"1.10.0" < "1.9.0"`)를 쓰지 않는다. 흔한 버그다.

## `sync_service.dart`

```dart
enum SyncOutcome {
  skippedNotDue, skippedOffline, skippedUpToDate,
  skippedSchemaIncompatible, skippedAppTooOld,
  failedDownload, failedChecksum, failedSanity, failedSwap,
  success,
}

class SyncResult {
  final SyncOutcome outcome;
  final int? newDbVersion;
  final int? wordCount;
  final Object? error;
}

class SyncService {
  static const _manifestUrl =
      'https://github.com/<owner>/<repo>/releases/latest/download/manifest.json';
  static const _intervalDays = 180;

  /// [force] 는 설정의 "지금 갱신" 버튼용. 주기·Wi-Fi 조건을 건너뛴다.
  Future<SyncResult> sync({bool force = false}) async {
    try {
      if (!force && !await _isDue()) {
        return const SyncResult(SyncOutcome.skippedNotDue);
      }
      if (!await _hasNetwork(requireWifi: !force && settings.wifiOnly)) {
        return const SyncResult(SyncOutcome.skippedOffline);
      }

      final m = await _fetchManifest();
      final currentVersion = int.parse(await db.metaValue('db_version') ?? '0');
      if (m.dbVersion <= currentVersion) {
        await _recordSyncAttempt();     // 확인은 했으므로 주기를 리셋
        return const SyncResult(SyncOutcome.skippedUpToDate);
      }
      if (m.schemaVersion != AppDatabase.expectedSchemaVersion) {
        return const SyncResult(SyncOutcome.skippedSchemaIncompatible);
      }
      if (!versionAtLeast(appVersion, m.minAppVersion)) {
        return const SyncResult(SyncOutcome.skippedAppTooOld);
      }

      final tmp = await _download(m);
      if (tmp == null) return const SyncResult(SyncOutcome.failedDownload);

      if (!await _verifyChecksum(tmp, m.sha256)) {
        await tmp.delete();
        return const SyncResult(SyncOutcome.failedChecksum);
      }
      if (!await _sanityCheck(tmp, m)) {
        await tmp.delete();
        return const SyncResult(SyncOutcome.failedSanity);
      }

      await DbSwapper(db).swap(tmp);      // 05-03
      await _recordSyncAttempt();
      return SyncResult(SyncOutcome.success,
          newDbVersion: m.dbVersion, wordCount: m.wordCount);
    } catch (e) {
      // 어떤 실패도 게임을 막지 않는다
      return SyncResult(SyncOutcome.failedDownload, error: e);
    }
  }
}
```

**구현은 위 골격에서 여섯 가지를 벗어난다** (전부 테스트 가능성·정합성을 위한 것이고,
계약(`SyncOutcome`/`SyncResult`/`Manifest`/`versionAtLeast`)은 그대로다):

1. **`_manifestUrl`을 처음부터 생성자 인자로 받는다** (기본값은 실제 URL).
   05-04 "막히면"이 "상수라 테스트 불가 → 05-02로 돌아가 생성자 인자로 받게
   고친다"고 이미 예고한 것을 여기서 선반영했다.
2. **`settings`/`appVersion`/`db` 를 암묵적 전역으로 참조하지 않는다.** 이
   서비스는 `data/` 계층이라 `ui/state`의 `SettingsModel`을 몰라야 한다 —
   `wifiOnly`는 `sync({bool wifiOnly = true})`처럼 **호출 시점 인자**로 받고
   (05-04에서 `settings.wifiOnlySync`를 넘겨준다), `appVersion`·`db`·`prefs`·
   `httpClient`·연결 확인·다운로드 디렉터리는 전부 생성자 주입이다. 05-02
   문서 자체가 "테스트에서 실제 네트워크를 탐 → `http.Client`를 주입 가능하게"
   라고 이미 요구한 것의 연장이다.
3. **`DbSwap` 타입**(`Future<AppDatabase> Function(AppDatabase current, File newDb)`)
   **을 05-03의 `DbSwapper.swap` 시그니처에 맞춰 먼저 정의했다.** `db_swapper.dart`가
   아직 없어 `DbSwapper(db).swap(tmp)`를 그대로 쓰면 컴파일이 안 된다 — 05-03은
   이 타입과 일치하는 `swap(AppDatabase, File)` 메서드를 만들고, 실제 연결은
   `swapDb: DbSwapper(...).swap` 티어오프 한 줄로 끝난다.
4. **`failedSwap`을 실제로 만든다.** 골격은 이 값을 선언만 하고 쓰지
   않는다(교체도 바깥 `catch`가 잡아 `failedDownload`로 뭉갠다) — `swapDb`
   호출만 따로 `try/catch`해 `failedSwap`을 반환한다. 또한 교체가 **성공한
   뒤** `_recordSyncAttempt()`가 실패해도 `success`를 `failedDownload`로
   덮어쓰지 않도록 그 실패를 안에서 삼킨다.
5. **sanity check 대상 테이블에 `puzzle_log`를 추가했다.** 이 골격은 02-09
   시절 테이블 5개 기준이라 03-04가 추가한 `puzzle_log`가 빠져 있다 — 05-01
   `verify()`에서 잡은 것과 같은 종류의 누락이다.
6. **체크섬은 스트리밍하지 않는다.** `crypto`의 청크 변환 API(`AccumulatorSink`
   등) import 경로가 불확실해 안전하게 `readAsBytes()` 후 `sha256.convert()`로
   바꿨다 — 이미 다운로드가 끝난(≤50MB, 05-01 `MAX_SIZE_BYTES`) 파일이라 메모리
   부담이 적다. "스트리밍으로 받는다"는 요구는 **다운로드 단계**(네트워크
   수신 중 버퍼링 방지)에 대한 것이고 그대로 지켰다.

`main.dart`(자동 갱신 호출)·`settings_page.dart`(수동 "지금 갱신" 버튼) 연결은
**05-02에서 하지 않는다.** `DbSwapper`가 없어 아직 실제 동작하는 `swapDb`를 만들 수
없고, 05-04 "D. 설정 화면 연결"이 명시적으로 그 배선을 담당한다 — 웹 조건부 import
스텁도 호출부가 생기기 전까지는(지금 아무도 이 클래스를 안 쓴다) 미룬다.

**독립 코드 리뷰(별도 세션)에서 잡힌 것을 추가로 반영했다** — 전부 위 여섯 가지와
같은 "골격을 그대로 베끼면 안 되는 자리"였다:

7. **`_deleteIfExists`가 자기 실패를 삼킨다.** 정리(임시 파일 삭제)가 실패해도
   (일시적 파일 잠금 등) 방금 판정한 `SyncResult`를 예외로 뒤엎으면 안 된다 —
   바깥 `catch` 안에서 또 정리를 시도하다 두 번째 예외가 `sync()` 밖으로 새어
   나가는 경로가 실제로 있었다.
8. **다운로드 스트림이 중간에 끊겨도 `IOSink`를 반드시 닫는다** (`try/finally`).
   안 닫으면 Windows에서 파일이 잠긴 채로 남아, 그 다음 정리(삭제)가 공유 위반으로
   실패하고 → 원래 원인(네트워크 끊김)이 아니라 그 정리 실패가 결과를 뒤덮는다.
   05-04 통합 테스트 #2("다운로드 중단")가 바로 이 경로를 태운다.
9. **`swapDb`가 반환한 새 `AppDatabase`를 `db` 필드에 다시 대입한다.** 버리면
   교체 후 같은 `SyncService` 인스턴스로 두 번째 `sync()`를 호출했을 때 이미 닫힌
   DB에 질의하게 된다(05-04 시나리오 13 "갱신 2회 연속"이 바로 이 경로). 그래서
   `db`는 `final`이 아니다.
10. **manifest 응답 바이트를 `utf8.decode(res.bodyBytes)`로 명시적으로 디코드한다.**
    `package:http`는 콘텐츠 타입이 없거나 `application/octet-stream`(GitHub
    Releases 자산이 실제로 이렇게 옴)이면 `res.body`를 latin1로 디코드한다 —
    `notes`의 한글이 깨진다.
11. **다운로드에 상한을 둔다.** `size_bytes`가 05-01 `MAX_SIZE_BYTES`(50MB)를
    넘거나 0 이하면 시작하지 않고, 받는 도중 `size_bytes`를 넘으면 즉시 중단한다 —
    `size_bytes`는 서버(또는 하이재킹된 리다이렉트)의 주장일 뿐이라 그대로 믿고
    기기 저장공간을 무제한으로 쓰면 안 된다.
12. **`skippedSchemaIncompatible`/`skippedAppTooOld`에서도 `_recordSyncAttempt()`를
    부른다.** 이 문서의 "막히면"이 "`skippedUpToDate`에서도 기록하는지 확인"이라고
    적은 것과 같은 이유(안 그러면 그 상태로 있는 한 실행마다 manifest를 다시
    받는다)가 이 두 갈래에도 똑같이 적용된다 — "지금 갱신"(force)은 이 주기를
    무시하므로 사용자가 원인이 풀렸는지 즉시 재확인할 수 있다.
13. **sanity check 프로브를 drift `AppDatabase`가 아니라 `package:sqlite3`로 직접
    연다.** 같은 파일이 아닌 두 `AppDatabase` 인스턴스를 만들면 drift가 "여러 DB
    인스턴스" 경고를 매 갱신마다 찍는다(서로 다른 파일이라 실제로는 오탐이지만,
    DB 손상이 리스크인 기능에서 그런 경고가 반복 출력되는 건 나쁘다). `sqlite3`를
    `dev_dependencies`에서 `dependencies`로 옮겼다 — 이제 런타임 코드가 쓴다.

`SyncService.dispose()`(주입하지 않은 기본 `http.Client`만 정리, 05-04가 앱 종료 시
호출)도 골격에 없던 것을 추가했다 — 정식 "일곱 번째 벗어남"으로 세지는 않았지만
기록해 둔다.

### `last_sync_at` 저장 위치

`meta` 테이블에 넣으면 **DB 교체 시 사라진다.** 새 DB의 `meta` 는 ETL이 만든 것이다.
`shared_preferences` 에 저장한다 (04-06의 설정과 같은 곳).

```dart
Future<bool> _isDue() async {
  final last = prefs.getInt('last_sync_at') ?? 0;
  final days = (DateTime.now().millisecondsSinceEpoch - last) / 86400000;
  return days >= _intervalDays;
}
```

**확인만 하고 갱신이 없어도 `last_sync_at` 을 기록한다.** 안 그러면 매 실행마다 manifest를 받는다.

**`last_sync_at`은 `shared_preferences`에 epoch milliseconds(`int`)로 저장한다** —
`_isDue()`가 그대로 쓰는 형식이라 문자열로 바꾸지 않았다. **05-04가 주의할 것**:
지금 `settings_page.dart`(04-06)의 `_DbInfo.lastSyncAt`은 `db.metaValue('last_sync_at')`
—즉 **`meta` 테이블**—를 읽는다. ETL이 그 키를 채운 적이 없어 항상 "-"로만 보이던
자리이고, 05-04 문서 "D. 설정 화면 연결" 표는 이미 올바르게 "`shared_preferences`의
`last_sync_at`"이라고 적어 뒀다 — 05-04에서 `settings_page.dart`를 고칠 때 `meta` 조회를
`prefs.getInt('last_sync_at')` 읽기 + 날짜 포맷 변환(현재 `_formatDate`는 ISO 문자열
앞 10자를 자르는 방식이라 `int`를 받도록 바꾸거나 별도 포맷터가 필요하다)으로 바꿔야
한다.

### 다운로드

```dart
Future<File?> _download(Manifest m) async {
  final dir = await getApplicationDocumentsDirectory();
  final tmp = File('${dir.path}/words.sqlite.download');
  if (await tmp.exists()) await tmp.delete();

  final client = http.Client();
  try {
    final req = http.Request('GET', Uri.parse(m.url));
    final res = await client.send(req).timeout(const Duration(minutes: 5));
    if (res.statusCode != 200) return null;

    final sink = tmp.openWrite();
    var received = 0;
    await res.stream.forEach((chunk) {
      received += chunk.length;
      sink.add(chunk);
      onProgress?.call(received, m.sizeBytes);
    });
    await sink.close();

    if (received != m.sizeBytes) { await tmp.delete(); return null; }
    return tmp;
  } catch (_) {
    if (await tmp.exists()) await tmp.delete();
    return null;
  } finally {
    client.close();
  }
}
```

**스트리밍으로 받는다.** 10MB를 메모리에 다 올리지 않는다.
재개(resume)는 1차 범위 밖 (05-sync: "재개 가능하면 좋고, 아니면 실패 시 삭제 후 다음 기회").

### sanity check

```dart
Future<bool> _sanityCheck(File f, Manifest m) async {
  final probe = AppDatabase(NativeDatabase(f));
  try {
    if (await probe.wordCount <= 0) return false;
    if (await probe.metaValue('db_version') != '${m.dbVersion}') return false;
    for (final t in ['word', 'sense', 'word_char', 'word_stat', 'meta']) {
      final r = await probe.customSelect(
        "SELECT 1 FROM sqlite_master WHERE type='table' AND name=?",
        variables: [Variable.withString(t)]).getSingleOrNull();
      if (r == null) return false;
    }
    return true;
  } catch (_) {
    return false;
  } finally {
    await probe.close();
  }
}
```

**반드시 `close()` 한다.** 열린 채로 두면 05-03의 파일 교체가 Windows/일부 안드로이드에서 실패한다.

> 10MB 다운로드를 모바일 데이터에서 → **Wi-Fi 전용 옵션 기본 켬** (설정에서 해제 가능). 규칙 절에 기록.

## 사용자 안내

성공 시 한 줄 스낵바: "단어 45,678개로 갱신했습니다".
실패는 **조용히** 넘어간다. 단, "지금 갱신"(force)은 사용자가 결과를 기다리므로 실패도 알린다.

| `SyncOutcome` | 자동 갱신 | 수동 갱신 |
|---|---|---|
| `success` | 스낵바 | 스낵바 |
| `skippedUpToDate` | 무음 | "이미 최신입니다" |
| `skippedOffline` | 무음 | "네트워크에 연결할 수 없습니다" |
| `skippedAppTooOld` | 무음 | "앱을 업데이트해 주세요" |
| `failed*` | 무음 | "갱신에 실패했습니다. 나중에 다시 시도해 주세요" |

## 앱 시작 시 호출

**시작을 막지 않는다.** `await` 하지 않고 백그라운드로 던진다.

```dart
// main.dart 또는 HomePage.initState
unawaited(syncService.sync().then((r) {
  if (r.outcome == SyncOutcome.success) showSnackbar(...);
}));
```

## 막히면

- **`connectivity_plus` 가 Wi-Fi/모바일을 구분 못 함** → 플랫폼에 따라 `ConnectivityResult.other` 가 올 수 있다. 확실히 Wi-Fi일 때만 진행하고 나머지는 스킵하는 보수적 판단을 쓴다.
  **알려진 사례**: iOS/macOS는 VPN이 켜져 있으면(Wi-Fi 위에서도) `other`만 돌려준다 —
  그런 기기는 Wi-Fi 전용 자동 갱신이 계속 조용히 스킵된다. "지금 갱신"(`force: true`)은
  이 검사를 건너뛰므로 수동 갱신으로 우회할 수 있다. 자동 갱신을 강제로 살리려면 이
  판단 자체를 완화해야 하는데, 지금은 안 한다(보수적 판단을 우선한다).
- **다운로드가 백그라운드에서 끊김** → 안드로이드가 앱을 백그라운드로 보내면 소켓이 끊길 수 있다. 실패로 처리하고 다음 기회에 재시도한다. 1차 범위상 허용.
- **매 실행마다 manifest를 받음** → `skippedUpToDate` 에서도 `last_sync_at` 을 기록하는지 확인.
- **테스트에서 실제 네트워크를 탐** → `http.Client` 를 주입 가능하게 만들고 테스트에서 `MockClient` 를 넣는다.
- **GitHub 접근이 막힌 네트워크** → 갱신만 실패하고 게임은 정상이어야 한다. 그게 이 설계의 전제다 (05-sync 리스크).
