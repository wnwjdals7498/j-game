## 작업

### 1. 진행 배지 (AppBar `actions`)

`puzzle_page.dart` 안의 private 위젯으로 둔다. 재사용할 곳이 없다.

```dart
class _ProgressBadge extends StatelessWidget {
  final int filled;      // model.filledWordCount
  final int total;       // puzzle.words.length
  final bool allFilled;  // model.allFilled — filled == total과 다를 수 있다

  @override
  Widget build(BuildContext context) {
    final c = GameColors.of(context);
    return Padding(
      padding: const EdgeInsets.only(right: GameSpace.l),
      child: AnimatedSwitcher(
        duration: GameMotion.of(context).fast,      // 배지 교체: fast (UI-GUIDE 3.1)
        child: Row(
          key: ValueKey('$filled/$total/$allFilled'),
          mainAxisSize: MainAxisSize.min,
          children: [
            Text('$filled / $total', style: GameType.label.copyWith(color: c.inkMuted)),
            if (allFilled) ...[
              const SizedBox(width: GameSpace.xs),
              Icon(Icons.check, size: GameSpace.l, color: c.success),  // 16 = GameSpace.l
            ],
          ],
        ),
      ),
    );
  }
}
```

`AppBar(title: Text(model.spec.name), actions: [_ProgressBadge(...)])`. AppBar 자체 스타일(배경 `surface`, elevation 0, 왼쪽 정렬)은 07-02-03의 `appBarTheme`이 준다 — 화면에서 다시 지정하지 않는다. `loading`·`error` 분기의 AppBar에는 배지를 넣지 않는다(`total`을 모른다).

### 2. `SubmitButton` (E-05) — UI-GUIDE 2.5 버튼 규격 그대로. 값을 새로 만들지 않는다

| 상태 | 배경 | 테두리 | 글자 |
|---|---|---|---|
| `active == false` (보조) | `Colors.transparent`(INV-05 허용) | `line` 1.5 | `ink`, 굵기 600 |
| `active == true` (기본) | `ink` | `ink` 1.5 | `surface`, 굵기 700 |

```dart
class SubmitButton extends StatelessWidget {
  final bool active;            // model.allFilled
  final VoidCallback onPressed; // active와 무관하게 항상 non-null

  @override
  Widget build(BuildContext context) {
    final c = GameColors.of(context);
    final m = GameMotion.of(context);
    final radius = BorderRadius.circular(GameRadius.pill);
    return SizedBox(
      width: double.infinity,
      height: 52,                                   // UI-GUIDE 2.5 버튼 높이
      child: AnimatedContainer(
        duration: m.base, curve: m.curveStandard,   // E-05
        decoration: BoxDecoration(
          color: active ? c.ink : Colors.transparent,
          border: Border.all(color: active ? c.ink : c.line, width: 1.5),
          borderRadius: radius,
        ),
        // Material(transparent) → InkWell(onTap: onPressed, borderRadius: radius)
        // → Center → AnimatedDefaultTextStyle(duration: m.base, style: …)
        //   → const Text('제출')   ← INV-09, 빈칸이 있어도 눌린다(04-05 규칙)
        // 글자 스타일: GameType.body.copyWith(
        //   fontWeight: active ? w700 : w600, color: active ? c.surface : c.ink)
        //   — 크기는 2.4 `body`(16), 굵기·색은 2.5 버튼 규격
        child: …,
      ),
    );
  }
}
```

`puzzle_page.dart`의 `SizedBox(width: double.infinity, child: FilledButton(...))`를 `SubmitButton(active: model.allFilled, onPressed: () => _handleSubmit(context, model))`로 바꾼다.

### 3. 텍스트 셀렉터 충돌 — 반드시 확인

`'n / N'` 형식이 셋 있다. 새 테스트는 항상 조상을 좁혀서 찾는다.

| 출처 | 형식 | 예 |
|---|---|---|
| 진행 배지 (이 문서) | `'$filled / $total'` | `0 / 4` |
| `WordInput`의 `counterText` | `'${committed.length} / $len'` | `0 / 3` |
| `ResultPage` 헤더 | `'$correctCount / $total 정답'` | `4 / 4 정답` |

- 배지 단언: `find.descendant(of: find.byType(AppBar), matching: find.text('0 / 4'))`
- `submit_test.dart` 통합 테스트의 `find.textContaining('4 / 4')`는 **결과 화면 진입 뒤**에 실행된다. `ResultPage`는 불투명 `MaterialPageRoute`라 그 아래 퍼즐 화면이 오프스테이지가 되고 기본 `Finder`가 건너뛴다 — 배지와 충돌하지 않는다. 이 테스트가 깨지면 라우트가 불투명이 아닌 것이므로 전환 방식을 먼저 의심한다(E-09는 07-07-01).

## 테스트 `test/ui/puzzle_screen_test.dart` (3종 추가 — 누적 6/13)

| 테스트 이름 | 기대 |
|---|---|
| `진행 배지 초기값: 0 / N` | 로드 직후 AppBar 하위에 `'0 / ${puzzle.words.length}'`, 체크 아이콘 없음 |
| `진행 배지 갱신: 한 단어 완성 → 1 / N` | 첫 단어 셀 탭 → 정답 문자열 `enterText` → `pump(motion.fast)` → `'1 / N'` |
| `제출 버튼 보조 → 기본` | `allFilled` 전 배경이 `Colors.transparent`, `model.answers = Scorer.solutionOf(puzzle)` 후 `pump(motion.base)` → `GameColors.light.ink` |

`AnimatedContainer`는 위젯 값이 즉시 목표색이다. 보간 중간값을 보려면 `find.descendant(of: find.byType(SubmitButton), matching: find.byType(Container))`로 내부 `Container`를 읽는다. 중간값 검증이 까다로우면 시작·끝 두 상태만 단언하고 보간은 07-08 골든에 맡긴다.

## 막히면

- **`find.text('0 / 4')`가 2개 잡힘** → `WordInput`의 `counterText`와 숫자가 겹쳤다. 3절대로 `find.descendant(of: find.byType(AppBar), ...)`로 좁힌다.
- **배지가 갱신되지 않음 / 매 입력마다 깜빡임** → 앞은 `_PuzzleBodyState.build`가 `context.watch<PuzzleModel>()`로 구독 중인지(게터는 재빌드에서만 바뀐다), 뒤는 `ValueKey`가 `filled`·`total`·`allFilled` 세 값으로만 만들어졌는지 확인한다.
- **`AnimatedContainer` 색을 테스트에서 못 읽음** → `find.byType(AnimatedContainer)`로 잡으면 목표값이, 그 하위 `find.byType(Container)`로 잡으면 현재 보간값이 나온다. 필요한 쪽을 고른다.
- **버튼 높이 52가 키보드와 함께 화면을 넘침** → 07-04-05의 여백 축소가 처리한다. 여기서 높이를 줄이지 않는다(UI-GUIDE 2.5 고정값).
