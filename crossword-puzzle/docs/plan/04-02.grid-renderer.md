# 04-02. 격자 렌더링 (CustomPaint)

담당: **AGENT**
선행: 04-01 · 다음: 04-03
상위: [04-ui.md](04-ui.md) "퍼즐 화면 동작 — 격자", "기술 결정"

## 목표

8×8 격자를 **한 위젯으로** 그린다. 폰 세로 화면에서 글자가 읽혀야 한다.

> 격자 렌더링: `CustomPaint` 단일 위젯 (셀 수십 개를 위젯으로 만들면 무겁고 탭 처리도 복잡).
> 탭 좌표 → 셀 변환은 직접 계산.

## 산출물

```
app/lib/ui/puzzle/
├─ grid_view.dart        GestureDetector + CustomPaint 래퍼
└─ grid_painter.dart     CustomPainter 구현
```

## 레이아웃 계산

격자는 **정사각형**이고 가용 폭에 맞춘다.

```dart
// grid_view.dart
LayoutBuilder(builder: (context, constraints) {
  final side = constraints.maxWidth.clamp(0.0, constraints.maxHeight);
  final cell = side / max(puzzle.width, puzzle.height);
  return SizedBox(
    width: cell * puzzle.width,
    height: cell * puzzle.height,
    child: GestureDetector(
      onTapDown: (d) => _handleTap(d.localPosition, cell),
      child: CustomPaint(
        painter: GridPainter(...),
        size: Size(cell * puzzle.width, cell * puzzle.height),
      ),
    ),
  );
})
```

### 탭 좌표 → 셀

```dart
void _handleTap(Offset p, double cell) {
  final c = (p.dx / cell).floor();
  final r = (p.dy / cell).floor();
  if (r < 0 || r >= puzzle.height || c < 0 || c >= puzzle.width) return;
  if (puzzle.cellAt(r, c).blocked) return;
  onCellTap(r, c);     // 04-03이 처리
}
```

### 셀 크기 하한

> 8×8 격자가 6인치대 폰에서 글자가 읽힌다 (DoD 2번)

6인치 폰 세로 폭은 약 360~400dp. 좌우 여백 16dp씩 빼면 328~368dp.
8칸이면 **셀 41~46dp**. 글자는 셀의 55% 정도 → 22~25dp.
Material 본문이 14~16dp이므로 충분히 읽힌다.

폭이 부족하면(작은 기기) 폰트를 줄이지 말고 **여백을 줄인다.** 셀이 36dp 아래로 내려가면
4단계 리스크대로 레벨 격자 상한을 낮춘다(03-06 피드백).

## `GridPainter`

### 그려야 하는 것 (아래→위 순서)

| 층 | 내용 |
|---|---|
| 1 | 검은 칸 배경 (`blocked` 셀) |
| 2 | 일반 칸 배경 |
| 3 | **선택된 단어** 하이라이트 배경 |
| 4 | 셀 테두리 |
| 5 | **코어 단어** 테두리 강조 |
| 6 | 유저가 입력한 음절 |
| 7 | 제출 후: 정답/오답 표시 |

```dart
class GridPainter extends CustomPainter {
  final Puzzle puzzle;
  final Map<(int, int), String> answers;
  final PlacedWord? selected;
  final SubmitResult? result;     // 제출 후에만 non-null
  final ColorScheme colors;
  final double cell;

  @override
  void paint(Canvas canvas, Size size) { ... }

  @override
  bool shouldRepaint(GridPainter old) =>
      old.puzzle != puzzle ||
      old.selected != selected ||
      old.result != result ||
      !mapEquals(old.answers, answers);
}
```

**`shouldRepaint` 를 정확히 쓴다.** `answers` 는 가변 맵이라 `!=` 로는 변화를 못 잡는다.
`mapEquals`(`package:flutter/foundation.dart`)로 내용 비교하거나,
입력마다 `answers` 를 새 맵으로 교체한다. **후자가 단순하고 빠르다** (셀 64개 복사는 무시할 만하다).

### 색 (Material 3 `ColorScheme` 사용)

| 요소 | 색 | 이유 |
|---|---|---|
| 검은 칸 | `colors.surfaceContainerHighest` | 진짜 검정은 다크 모드에서 안 보인다 |
| 일반 칸 | `colors.surface` | |
| 선택 단어 배경 | `colors.primaryContainer` | |
| 선택 셀(탭한 칸) | `colors.primary` 20% | 단어 안에서 현재 칸 구분 |
| 코어 테두리 | `colors.tertiary`, 두께 2 | |
| 일반 테두리 | `colors.outlineVariant`, 두께 1 | |
| 입력 글자 | `colors.onSurface` | |
| 정답(제출 후) | `colors.primary` | |
| 오답(제출 후) | `colors.error` | |

**하드코딩한 색을 쓰지 않는다.** 다크 모드에서 안 보인다 (범위 밖이지만 기본은 따라간다).

### 정답/오답을 색으로만 표시하지 않기

색각 이상 사용자를 위해 **아이콘이나 테두리 패턴**을 함께 쓴다.
셀 우상단에 작은 점(정답) / 사선(오답)을 그리는 정도면 충분하다.

### 텍스트 그리기

```dart
void _drawSyllable(Canvas canvas, String s, Rect rect, Color color) {
  final tp = TextPainter(
    text: TextSpan(text: s, style: TextStyle(
      fontSize: cell * 0.55,
      color: color,
      fontWeight: FontWeight.w500,
      height: 1.0,
    )),
    textDirection: TextDirection.ltr,
  )..layout();
  tp.paint(canvas, rect.center - Offset(tp.width / 2, tp.height / 2));
}
```

`TextPainter` 는 매 프레임 `layout()` 이 필요하다. 64칸이면 비용이 있지만
입력할 때만 다시 그리므로 문제없다. 느리면 음절별 `TextPainter` 를 캐시한다.

## 제출 전/후 모드

같은 위젯이 두 상태를 그린다.

- **제출 전**: 유저 입력만 표시. 정답 미노출.
- **제출 후**: 정답/오답 표시. 틀린 칸에 **정답을 함께** 보여줄지는 결과 화면(04-05)에서 결정.
  격자에는 O/X만 표시하고 정답은 결과 화면에서 보여주는 쪽이 깔끔하다.

## 테스트

위젯 테스트로 픽셀을 검증하긴 어렵다. **구조와 탭 변환**을 테스트한다.

`app/test/ui/grid_view_test.dart`

| 테스트 | 기대 |
|---|---|
| 탭 → 셀 변환 | (cell*2.5, cell*1.5) 탭 → (row 1, col 2) |
| 검은 칸 탭 무시 | `onCellTap` 미호출 |
| 범위 밖 탭 무시 | 미호출 |
| 격자 크기 | 5×5 퍼즐 → 위젯 크기가 정사각형 |
| `shouldRepaint` | 같은 입력 → false, 입력 변경 → true |
| 선택 변경 시 repaint | true |
| 제출 결과 반영 | `result` 설정 시 repaint |

`shouldRepaint` 테스트가 성능의 핵심이다. 매번 true면 입력할 때마다 전체 재그리기가 난다.

골든 테스트는 생략한다 (04-ui.md: "골든 테스트는 생략(1차)").

## 막히면

- **작은 기기에서 격자가 잘림** → `LayoutBuilder` 의 `maxHeight` 도 고려해 `side` 를 정하는지 확인. 힌트 패널·입력 필드가 차지하는 높이를 빼고 계산해야 한다.
- **입력할 때마다 버벅임** → `shouldRepaint` 가 항상 true다. `answers` 를 새 맵으로 교체하는 방식으로 바꾼다.
- **글자가 셀 밖으로 나감** → `height: 1.0` 을 TextStyle에 넣었는지 확인. 한글은 기본 line height가 크다.
- **다크 모드에서 안 보임** → 하드코딩 색이 남아 있다. `Theme.of(context).colorScheme` 만 쓴다.
- **9×9 이상이 필요해짐** → 03-06에서 격자 상한을 8로 정했다. 넘기려면 스크롤/줌이 필요하고 이는 범위 밖이다(04-ui 리스크).
