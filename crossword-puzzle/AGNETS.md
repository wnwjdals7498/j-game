# 커밋 메시지 작성 규칙

## 0. 절대 규칙

**`Co-Authored-By:` 트레일러를 커밋 메시지에 절대 추가하지 않는다.**

- AI 도구가 자동으로 붙이려 해도 제거하고 커밋한다.
- 사람 공동 작업자에 대해서도 붙이지 않는다. 기여 기록은 PR과 리뷰로 남긴다.
- 이유: 커밋 메시지는 커밋 해시의 일부라, 한 번 푸시되면 히스토리 재작성 없이는 제거할 수 없다.

같은 이유로 아래 트레일러도 붙이지 않는다.

```
Co-Authored-By:
Generated-by:
Signed-off-by:   (프로젝트가 DCO를 요구하는 경우에만 예외)
```

---

## 1. 무엇을 적는가

커밋 메시지는 **diff를 다시 설명하는 곳이 아니다.** diff는 `git show`로 언제든 볼 수 있다.

메시지에는 **diff가 말해주지 않는 것**만 남긴다.

| 적는다 | 적지 않는다 |
|---|---|
| 왜 이 방향을 택했는가 | 어떤 함수/변수를 고쳤는가 |
| 무엇을 포기했는가 | 파일 목록, 줄 수 |
| 임시 조치인가 최종안인가 | 코드 동작의 단계별 설명 |
| 다음에 이어질 작업 | 라이브러리 사용법 설명 |

---

## 2. 형식

```
<타입>: <한 줄 요약 — 방향성>

(선택) 판단 근거 또는 남은 과제 1~3줄
```

- 제목은 50자 내외, 명령형 현재 시제.
- 본문은 **필요할 때만.** 제목만으로 충분하면 본문 없이 끝낸다.
- 본문이 5줄을 넘어가면 커밋을 쪼갤 때가 된 것이다.

### 타입

| 타입 | 용도 |
|---|---|
| `feat` | 기능 추가 |
| `fix` | 버그 수정 |
| `refactor` | 동작 변화 없는 구조 변경 |
| `chore` | 빌드·설정·의존성 |
| `docs` | 문서 |

---

## 3. 예시

### ✅ 좋은 예

```
refactor: 인증 로직을 미들웨어로 분리

라우터마다 중복되던 토큰 검증을 한 곳으로 모음.
세션 방식 전환 가능성을 고려해 인터페이스만 남겨둠.
```

```
fix: 결제 타임아웃을 30초로 완화

외부 PG 응답이 평균 12초라 기존 10초 설정으로는 실패가 잦았음.
근본 해결은 비동기 전환이며 이번 커밋은 임시 조치.
```

```
chore: 린트 규칙 정리
```

### ❌ 나쁜 예

```
fix: AuthMiddleware.ts의 verifyToken 함수에서 jwt.verify 호출부를
try-catch로 감싸고, catch 블록에서 401을 반환하도록 수정.
또한 authRouter.ts 3곳의 중복 호출을 제거하고 index.ts에서
app.use()로 등록하도록 변경. 총 4개 파일 수정.

Co-Authored-By: Someone <someone@example.com>
```

> 문제점: diff를 그대로 옮겨 적었고, **왜** 그렇게 했는지가 없다. 트레일러도 붙어 있다.

```
update
```

> 문제점: 방향성이 없다. 3개월 뒤 아무 정보도 주지 못한다.

---

## 4. 커밋 전 체크리스트

- [ ] `Co-Authored-By` 를 비롯한 불필요한 트레일러가 없는가
- [ ] 제목만 읽어도 이 커밋의 **의도**를 알 수 있는가
- [ ] 본문이 diff의 재서술이 아니라 판단 근거인가
- [ ] 한 커밋이 하나의 방향성만 담고 있는가

확인 명령:

```bash
# 직전 커밋에 트레일러가 섞여 들어갔는지 검사
git log -1 --format='%B' | grep -i 'co-authored-by' && echo "!! 제거 필요"
```
