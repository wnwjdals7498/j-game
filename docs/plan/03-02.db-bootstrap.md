# 03-02. 첫 실행 부트스트랩 (네이티브 / 웹 분기)

담당: **AGENT**
선행: 03-01 · 다음: 03-03
상위: [03-data-layer.md](03-data-layer.md) B절 · [../REVIEW.md](../REVIEW.md) 4.2 (a)

## 목표

앱이 시작될 때 `assets/words.sqlite` 를 **쓰기 가능한 DB로 만든다.**
네이티브와 웹은 방식이 완전히 다르다 (REVIEW 4.2 (a)).

> "assets의 시드 DB를 앱 저장소로 복사"는 네이티브 전용. 웹(drift wasm)은 파일 시스템 복사가 없고,
> DB 바이트를 OPFS 또는 IndexedDB에 적재하는 방식이다.

## 왜 복사하는가

`assets/` 는 읽기 전용이다. `word_stat` 에 쓰려면 쓰기 가능한 위치에 있어야 한다.

## 산출물


## 조건부 import 패턴

```dart
// db_bootstrap.dart
import 'package:drift/drift.dart';
import 'open_stub.dart'
    if (dart.library.io) 'open_native.dart'
    if (dart.library.js_interop) 'open_web.dart';

class DbBootstrap {
  /// 앱 시작 시 1회. 시드 적재 → DB 오픈 → 스키마 버전 확인.
  static Future<AppDatabase> open() async {
    final executor = await openConnection();   // 플랫폼별 구현
    final db = AppDatabase(executor);
    await _verify(db);
    return db;
  }

  static Future<void> _verify(AppDatabase db) async {
    final v = await db.metaValue('schema_version');
    if (v != '${AppDatabase.expectedSchemaVersion}') {
      throw SchemaMismatch(expected: AppDatabase.expectedSchemaVersion,
                           actual: v);
    }
    final n = await db.wordCount;
    if (n <= 0) throw const EmptyDatabase();
  }
}
```

`open_stub.dart` 는 `UnsupportedError` 를 던지는 `openConnection()` 하나만 둔다.
이게 없으면 조건부 import가 컴파일되지 않는다.

## 네이티브 — `open_native.dart`

```dart
import 'dart:io';
import 'package:drift/drift.dart';
import 'package:drift/native.dart';
import 'package:flutter/services.dart' show rootBundle;
import 'package:path_provider/path_provider.dart';

const _dbFileName = 'words.sqlite';
const _asset = 'assets/words.sqlite';

Future<QueryExecutor> openConnection() async {
  final dir = await getApplicationDocumentsDirectory();
  final file = File('${dir.path}/$_dbFileName');

  if (!await file.exists()) {
    await _copySeed(file);
  }
  return NativeDatabase(file);
}

Future<void> _copySeed(File target) async {
  final bytes = await rootBundle.load(_asset);
  // 임시 파일에 쓴 뒤 rename → 복사 중 앱이 죽어도 반쪽 파일이 남지 않는다
  final tmp = File('${target.path}.tmp');
  await tmp.writeAsBytes(bytes.buffer.asUint8List(
      bytes.offsetInBytes, bytes.lengthInBytes), flush: true);
  await tmp.rename(target.path);
}
```

**`rename` 을 쓰는 이유**: 10MB 복사 중 앱이 종료되면 잘린 DB 파일이 남아
다음 실행에서 "파일이 있으니 복사 안 함" → 깨진 DB로 크래시한다.
`rename` 은 같은 파일시스템에서 원자적이다. 05-03의 DB 교체도 같은 패턴을 쓴다.

### 스키마 버전 불일치 정책 (v1은 한 가지만)

> 스키마 버전 불일치 시 정책: v1은 "시드로 덮어쓰기 + word_stat 보존" 한 가지만.

```dart
Future<void> reseedPreservingStats(File target) async {
  // 1. 기존 DB에서 word_stat을 메모리로 읽는다
  // 2. 시드를 임시 파일에 푼다
  // 3. 임시 DB에 word_stat을 다시 넣는다
  // 4. rename으로 교체
}
```

구현은 05-03의 `db_swapper` 와 거의 같다. **05-03에서 만들고 여기서 재사용**하는 편이 낫다.
3단계 시점에는 시드와 앱 버전이 항상 일치하므로, 지금은 `SchemaMismatch` 예외를 던지고
**05-03 완료 후 이 함수를 연결한다.** 그 TODO를 코드 주석에 남긴다.

## 웹 — `open_web.dart`

```dart
import 'package:drift/drift.dart';
import 'package:drift/wasm.dart';
import 'package:flutter/services.dart' show rootBundle;

Future<QueryExecutor> openConnection() async {
  final result = await WasmDatabase.open(
    databaseName: 'jgame',
    sqlite3Uri: Uri.parse('sqlite3.wasm'),
    driftWorkerUri: Uri.parse('drift_worker.js'),
    initializeDatabase: () async {
      final bytes = await rootBundle.load('assets/words.sqlite');
      return bytes.buffer.asUint8List(
          bytes.offsetInBytes, bytes.lengthInBytes);
    },
  );

  if (result.missingFeatures.isNotEmpty) {
    // OPFS 불가 → IndexedDB 폴백. 테스트 용도라 성능 무관 (03-data-layer B절)
    // ignore: avoid_print
    print('drift wasm 폴백: ${result.missingFeatures}');
  }
  return result.resolvedExecutor;
}
```

### 웹 자산 준비

`sqlite3.wasm` 과 `drift_worker.js` 를 `app/web/` 에 넣어야 한다.

```powershell
dart run drift_dev make-web-assets
```

이 명령이 없거나 버전이 다르면 drift 릴리스 페이지에서 `sqlite3.wasm` 을 받고,
`drift_worker.js` 는 `dart compile js` 로 만든다. **정확한 절차는 설치된 drift 버전 문서를 따른다.**
받은 파일과 버전을 `app/web/README.md` 에 기록한다.

`initializeDatabase` 는 **DB가 없을 때만** 호출된다. 재실행 시에는 저장된 것을 쓴다.

## 웹의 범위 한계

- 갱신(5단계)은 웹에서 1차 범위 제외 (REVIEW 4.2 (a))
- 10MB 자산 로딩이 느리다 → 테스트 용도이므로 허용 (03-data-layer 리스크)
- 웹은 **배포 대상이 아니다.** 같은 Dart 코드를 빠르게 돌려 보는 용도다

## 테스트

`app/test/data/bootstrap_test.dart` — 네이티브 경로만 (웹은 수동 확인)

| 테스트 | 기대 |
|---|---|
| 첫 실행 복사 | 대상 파일이 없으면 생성됨 |
| 재실행 | 이미 있으면 복사 안 함 (mtime 변화 없음) |
| 원자적 복사 | `.tmp` 파일이 남지 않음 |
| 스키마 버전 확인 | 일치하면 통과 |
| 스키마 불일치 | `SchemaMismatch` 예외 |
| 빈 DB | `EmptyDatabase` 예외 |
| 앱 삭제→재설치 | 디렉터리를 지운 뒤 open → 정상 복사 |

`rootBundle`, `getApplicationDocumentsDirectory` 는 테스트에서 모킹해야 한다.
`TestDefaultBinaryMessengerBinding` 으로 `path_provider` 채널을 가로채거나,
**복사 로직을 `File` 두 개를 받는 순수 함수로 분리**해 테스트한다. 후자가 간단하다.

## 수동 검증 (HUMAN)


2. 앱 종료 후 재실행 → 복사 안 함
3. 앱 삭제 → 재설치 → 다시 복사됨 (**DoD 5번**)

## 막히면

- **`rootBundle.load` 가 asset을 못 찾음** → `pubspec.yaml` 의 `assets: - assets/` 확인(00-05). `flutter clean` 후 재빌드.
- **웹에서 `missingFeatures` 가 가득** → 브라우저가 OPFS/SharedArrayBuffer를 막았다. `flutter run -d chrome` 은 개발 서버가 필요한 헤더를 안 붙일 수 있다. IndexedDB 폴백으로 동작하면 진행한다.
- **웹 첫 로딩이 30초 이상** → 10MB asset + wasm 다운로드다. 테스트 용도이므로 허용. 거슬리면 웹 전용으로 축소 DB(티어 1~3만)를 만들 수 있지만 1차 범위 밖이다.
- **`SchemaMismatch` 가 뜸** → 시드 DB(`assets/words.sqlite`)가 오래된 것이다. 02-09의 복사 명령을 다시 실행한다.
- **앱 문서 디렉터리를 못 찾음(데스크톱 테스트)** → `path_provider` 가 Windows 데스크톱을 지원하는지 확인. 측정용 데스크톱 실행(03-05)에서는 경로를 직접 지정하는 별도 진입점을 둔다.
