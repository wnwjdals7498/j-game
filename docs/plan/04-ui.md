# 4단계 — UI (Flutter)

규모: M~L · 선행: 3단계 · 다음: 5단계

## 목표

홈 → 퍼즐 → 결과의 **플레이 루프를 끝까지** 만든다. 화면 미학보다 입력 안정성(한국어 IME)과 격자 가독성이 우선. 출처 표기 화면은 라이선스 의무라 이 단계 필수 산출물.

## 화면

| 화면 | 내용 | 비고 |
|---|---|---|
| 홈 | 레벨 목록(잠금/해제), 간단 통계(누적 정답률) | 레벨 해제 규칙: 이전 레벨 1회 클리어(점수 기준은 규칙 절에 기록) |
| 퍼즐 | 격자, 힌트 패널, 입력, "제출" | 핵심 |
| 결과 | 단어별 정답/오답/빈칸, 뜻풀이 노출, "다시 풀기" / "다음 레벨" | 재제출은 통계 미반영 안내 |
| 설정·정보 | 힌트 모드(뜻풀이/연상어), 출처·라이선스 표기, DB 버전, 수동 갱신 버튼(5단계) | 라이선스 필수 |

## 퍼즐 화면 동작

- **격자**: 셀 크기는 화면 폭에 맞춰 자동. 코어 단어 셀은 시각적으로 구분(테두리 색). 검은 칸은 배경색. 8×8까지 폰 세로 화면에서 읽히는 크기 확보.
- **선택**: 셀 탭 → 그 셀을 지나는 단어 중 하나 선택(가로 우선, 다시 탭하면 세로). 선택 단어 전체가 하이라이트. 힌트 패널에 그 단어의 힌트 표시.
- **힌트**: 기본 뜻풀이. 설정에서 "연상어 모드"를 켜면 유의어 있는 단어는 유의어 노출, 없으면 뜻풀이로 폴백. 코어/채움 구분 없이 동일.
- **입력**: 단어 단위 입력. 선택 단어의 길이만큼 글자 수 제한된 텍스트 필드에 시스템 IME로 입력 → 확정된 음절을 격자 셀에 분배. 교차 셀에 이미 다른 단어가 넣은 글자가 있으면 덮어쓴다(마지막 입력 우선). **부분 입력 허용**(일부 셀만 채움 → 그 단어는 채점 시 오답).
- **제출**: 확인 다이얼로그(빈칸 N개 있음 안내) → 일괄 채점 → 결과 화면. 첫 제출만 통계 반영(3단계 stat_repository).
- **상태**: 앱이 백그라운드로 가도 입력 내용 유지(메모리 상태로 충분, 1차는 영구 저장 안 함).

## 기술 결정

- 상태 관리: **ChangeNotifier + Provider** 또는 Riverpod 중 하나. 화면 4개 규모라 어느 쪽이든 무방. 결정 후 이 문서에 기록.
- 격자 렌더링: `CustomPaint` 단일 위젯 (셀 수십 개를 위젯으로 만들면 무겁고 탭 처리도 복잡). 탭 좌표 → 셀 변환은 직접 계산.
- IME: 격자 셀에 직접 타이핑하는 방식은 **하지 않는다.** 조합 중 상태(ㄱ→가→각) 처리가 까다롭고 기기별 편차가 크다. 화면 하단 텍스트 필드 1개로 단어 전체를 받는 방식이 안전.
- 웹: 같은 코드. 키보드 입력이 IME 없이도 들어오면 그대로 처리.

## 테스트

- 위젯 테스트: 격자 탭 → 올바른 단어 선택, 입력 → 셀 반영, 제출 → 결과 화면 진입.
- 골든 테스트는 생략(1차).
- 수동: 삼성 키보드, Gboard 두 IME에서 입력 확인. 웹 Chrome 확인.

## 완료 기준 (DoD)

1. 실기기에서 홈→퍼즐→제출→결과→다음 레벨 루프가 끊김 없이 돈다.
2. 8×8 격자가 6인치대 폰에서 글자가 읽힌다.
3. 두 IME에서 입력 오류 없음.
4. 설정·정보 화면에 4개 자료 출처와 라이선스 문구(`docs/LICENSES.md`와 동일) 노출.
5. 힌트 모드 두 가지 동작.
6. 위젯 테스트 통과.

## 범위 밖 (v2 후보)

- 타이머, 힌트 사용 페널티, 애니메이션, 사운드, 다크 모드 세부 튜닝, 진행 상태 영구 저장.

## 리스크

- IME 조합 처리 → 위 기술 결정으로 회피. 그래도 텍스트 필드 `maxLength`가 조합 중 글자를 어떻게 세는지 기기별 확인 필요.
- 격자가 화면보다 크면 스크롤/줌 필요 → 1차 레벨을 8×8 이하로 제한해 회피.
