# 02-07. 표제어 기준 결합 (merge)

담당: **AGENT**
선행: 02-06 · 다음: 02-08
상위: [02-tools-etl.md](02-tools-etl.md) · [../DESIGN.md](../DESIGN.md) 4절

## 목표

표제어 문자열 하나에 **`word` 1행 + `sense` 여러 행**을 붙이고, 빈도·어휘 등급을 결합한다.
DESIGN 4절의 "게임이 쓰는 것과 사전이 주는 것을 분리" 를 여기서 실현한다.

## 결합 규칙

| 항목 | 규칙 | 근거 |
|---|---|---|
| 표제어 | 같은 문자열 = `word` 1행 | DESIGN 4절: `word` PK = 표제어 문자열 |
| 동음이의어 | `sense` 여러 행으로 갈라짐, `word` 는 하나 | DESIGN 4절 |
| 기초 vs 표준 | **기초 우선.** 표준은 기초에 없는 표제어만 보충 | DESIGN 2절 |
| 앱에 넣는 뜻풀이 | 단어당 **1개** (`config.SENSES_PER_WORD`) | DESIGN 6절 용량 |
| 뜻풀이 선택 | 기초사전 첫 뜻풀이 > 표준 첫 뜻풀이 | 02-tools-etl |
| 유의어 | 선택된 sense의 유의어. 없으면 같은 표제어의 다른 sense에서 보충 | 힌트 두 모드 확보 (DESIGN 2절) |
| `pos` | 선택된 sense의 품사 | |
| `source` 비트 | 기초=1, 표준=2. 둘 다면 3 | 02-tools-etl schema |
| 빈도 | `freq.jsonl` 의 `rank`. 없으면 `null` | 02-08이 `NO_FREQ_BASE` 로 처리 |
| 어휘 등급 | `vocab.jsonl` 의 `grade`. 없으면 `null` | |

## 출력 스키마

```json
{
  "headword": "사과",
  "len": 2,
  "syllables": ["사", "과"],
  "pos": "명사",
  "source": 3,
  "freq_rank": 1234,
  "vocab_grade": "A",
  "in_krdict": true,
  "senses": [
    {
      "sense_id": "krdict:12345",
      "definition": "사과나무의 열매.",
      "synonyms": ["능금"],
      "source": 1
    }
  ]
}
```

`senses` 는 `config.SENSES_PER_WORD` 개로 잘린 상태. 나머지는 버린다 (용량).
**버리기 전에 유의어만 모아 둔다** — 2번 뜻풀이에만 유의어가 있는 경우가 흔하다.

## 구현

```python
# tools/merge.py
from collections import defaultdict
from . import config, io_util

OUT = "merged.jsonl"

def _load_index(name: str, key: str, val: str) -> dict:
    p = config.BUILD / name
    if not p.exists():
        return {}
    return {r[key]: r[val] for r in io_util.read_jsonl(p)}

def run(use_fixtures: bool = False) -> int:
    freq = _load_index("freq.jsonl", "headword", "rank")
    vocab = _load_index("vocab.jsonl", "headword", "grade")

    by_word = defaultdict(list)
    for e in io_util.read_jsonl(config.BUILD / "normalized.jsonl"):
        by_word[e["headword"]].append(e)

    def rows():
        for hw, entries in sorted(by_word.items()):
            # 기초 우선 정렬. 같은 출처면 sense_id로 안정 정렬(재현성)
            entries.sort(key=lambda e: (0 if e["source"] == "krdict" else 1,
                                        e["sense_id"]))
            head = entries[0]

            src_bits = 0
            for e in entries:
                src_bits |= (config.SRC_KRDICT if e["source"] == "krdict"
                             else config.SRC_STDICT)

            # 유의어는 버려지는 sense에서도 긁어모은다
            syns, seen = [], set()
            for e in entries:
                for s in e.get("synonyms", []):
                    if s and s not in seen:
                        seen.add(s)
                        syns.append(s)

            kept = entries[: config.SENSES_PER_WORD]
            senses = [{
                "sense_id": e["sense_id"],
                "definition": e["definition"],
                "synonyms": syns if i == 0 else [],
                "source": (config.SRC_KRDICT if e["source"] == "krdict"
                           else config.SRC_STDICT),
            } for i, e in enumerate(kept)]

            yield {
                "headword": hw,
                "len": head["len"],
                "syllables": head["syllables"],
                "pos": head["pos"],
                "source": src_bits,
                "freq_rank": freq.get(hw),
                "vocab_grade": vocab.get(hw),
                "in_krdict": bool(src_bits & config.SRC_KRDICT),
                "senses": senses,
            }

    n = io_util.write_jsonl(config.BUILD / OUT, rows())
    print(f"    merge: {n:,} words "
          f"(빈도 매칭 {sum(1 for _ in [])}, 등급 매칭 ...)")
    return n
```

### 정렬을 `sorted(by_word.items())` 로 하는 이유

**재현성.** 같은 입력 → 같은 파일 바이트가 나와야 `words.sqlite` 의 sha256(05-01)이 안정적이다.
dict 순회 순서에 의존하면 파이썬 버전·삽입 순서에 따라 결과가 달라질 수 있다.

### 매칭률 로그

빈도·등급이 **얼마나 붙었는지** 반드시 찍는다:

```
    merge: 45,678 words
      빈도 매칭  32,100 (70.3%)
      등급 매칭   5,432 (11.9%)
      기초사전만 40,000 / 표준만 5,000 / 양쪽 678
```

빈도 매칭률이 30% 미만이면 표제어 형태가 안 맞는 것이다 (빈도 파일이 `사람/NNG` 형태 등).
02-05로 돌아가 빈도 쪽 표제어도 정규화해야 한다.

## 테스트

`tools/tests/test_merge.py`

| 테스트 | 기대 |
|---|---|
| 동음이의어 결합 | 같은 표제어 2 sense → `word` 1행 |
| 기초 우선 | 기초+표준 둘 다 있으면 `senses[0].source == 1` |
| 표준 보충 | 기초에 없는 표제어는 표준 것이 들어감 |
| `source` 비트 | 양쪽 있으면 3 |
| 뜻풀이 개수 컷 | `len(senses) <= SENSES_PER_WORD` |
| 유의어 수집 | 버려진 sense의 유의어도 `senses[0].synonyms` 에 포함 |
| 유의어 중복 제거 | 같은 유의어가 두 번 안 나옴 |
| 빈도 결합 | 매칭되면 `freq_rank`, 없으면 `null` |
| 등급 결합 | 매칭되면 `vocab_grade`, 없으면 `null` |
| **출력 순서 안정** | 두 번 실행 → 파일 바이트 동일 |
| 표준 파일 없음 | 기초만으로 정상 동작 |

## 막히면

- **빈도 매칭률이 30% 미만** → 빈도 파일 표제어에 품사 태그나 동형어 번호가 붙어 있다. 02-05의 `parse_freq` 에서 `normalize.normalize_headword` 를 적용한 뒤 다시 결합한다. (모듈 간 import는 `normalize` → `parse_freq` 방향이 되므로 순환을 피하려면 정규화 함수를 `tools/hangul.py` 로 분리한다.)
- **등급 매칭률이 5% 미만** → 학습용 어휘 5,965개 중 명사가 절반쯤이고 그중 표제어 형태가 맞는 것만 붙으므로 10% 안팎이면 정상이다. 1% 미만이면 파일이 잘못됐다.
- **메모리 부족** → `by_word` 가 전체를 메모리에 올린다. 5만 단어×뜻풀이면 수십 MB라 괜찮다. 표준 전체(수십만)가 들어와 문제면, `normalized.jsonl` 을 표제어로 정렬한 뒤 스트리밍 group-by로 바꾼다.
- **유의어가 거의 없음** → 기초사전 관계 정보 파싱(02-03)이 안 됐다. 유의어 없이도 힌트는 뜻풀이로 폴백하므로(04-03) 치명적이지 않다. README에 기록하고 진행한다.
