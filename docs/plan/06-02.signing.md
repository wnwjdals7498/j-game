# 06-02. 서명 (키스토어)

담당: **HUMAN** (키스토어 생성·보관은 사람이 직접. 에이전트는 비밀번호를 다루지 않는다)
선행: 06-01 · 다음: 06-03
상위: [06-release.md](06-release.md) B절

## 중요 — 먼저 읽을 것

**키스토어를 잃으면 앱 업데이트를 영원히 못 한다.** 같은 `applicationId` 로 새 앱을 올릴 수도 없다.
이 문서의 백업 단계를 건너뛰지 않는다.

**Play App Signing 을 반드시 사용한다.** 구글이 앱 서명 키를 보관하고, 우리는 업로드 키만 갖는다.
업로드 키를 잃어도 구글에 요청해 재발급받을 수 있다. 이게 유일한 복구 경로다.

키스토어 파일과 비밀번호는 **저장소에 절대 커밋하지 않는다.** 00-05의 `.gitignore` 가
`*.keystore`, `*.jks`, `key.properties` 를 제외하지만, 커밋 전 매번 확인한다.

## A. 업로드 키스토어 생성

`keytool` 은 JDK에 포함돼 있다 (00-02의 Android Studio 동봉 JDK).

```powershell
& "C:\Program Files\Android\Android Studio\jbr\bin\keytool.exe" `
  -genkeypair -v `
  -keystore "$env:USERPROFILE\keys\jgame-upload.jks" `
  -alias upload `
  -keyalg RSA -keysize 2048 -validity 10000 `
  -storetype JKS
```

| 인자 | 설명 |
|---|---|
| `-keystore` | **저장소 밖** 경로. 홈 디렉터리 아래 `keys/` 권장 |
| `-alias` | 키 별칭. `upload` |
| `-validity 10000` | 약 27년. Play는 2033-10-22 이후까지 유효할 것을 요구 |
| `-keysize 2048` | RSA 2048 이상 |

입력 항목:

- 키스토어 비밀번호 (강한 것, 20자 이상)
- 이름/조직/도시/국가 (`KR`) — 사용자에게 안 보이지만 인증서에 남는다
- 키 비밀번호 (키스토어 비밀번호와 같게 해도 된다)

**비밀번호는 비밀번호 관리자에 저장한다.** 텍스트 파일이나 메모에 두지 않는다.

## B. 백업 — 2곳 이상

> 키스토어 분실 = 앱 업데이트 불가 (06-release 리스크)

| 위치 | 예 |
|---|---|
| 1 | 암호화된 클라우드 저장소 (개인 계정) |
| 2 | 오프라인 매체 (USB, 외장 디스크) |

백업 대상: **키스토어 파일 + 비밀번호 2개 + alias**. 파일만 있고 비밀번호가 없으면 쓸 수 없다.

백업 후 복구 테스트를 한다:

```powershell
& keytool -list -v -keystore <백업본 경로> -alias upload
```

비밀번호를 넣어 인증서 정보가 나오면 정상이다.

## C. `key.properties`

```properties
# app/android/key.properties  ← 커밋 금지
storePassword=<키스토어 비밀번호>
keyPassword=<키 비밀번호>
keyAlias=upload
storeFile=C:/Users/<사용자>/keys/jgame-upload.jks
```

경로에 역슬래시 대신 **슬래시**를 쓴다. Gradle이 역슬래시를 이스케이프로 해석한다.

`.gitignore` 확인:

```powershell
git check-ignore -v app/android/key.properties
```

출력이 있으면 제외되고 있다. **출력이 없으면 커밋 위험** — `.gitignore` 를 고친다.

## D. Gradle 연결

`app/android/app/build.gradle`:

```groovy
def keystoreProperties = new Properties()
def keystorePropertiesFile = rootProject.file('key.properties')
if (keystorePropertiesFile.exists()) {
    keystoreProperties.load(new FileInputStream(keystorePropertiesFile))
}

android {
    signingConfigs {
        release {
            keyAlias keystoreProperties['keyAlias']
            keyPassword keystoreProperties['keyPassword']
            storeFile keystoreProperties['storeFile']
                ? file(keystoreProperties['storeFile']) : null
            storePassword keystoreProperties['storePassword']
        }
    }
    buildTypes {
        release {
            signingConfig signingConfigs.release
            minifyEnabled true
            shrinkResources true
            proguardFiles getDefaultProguardFile('proguard-android-optimize.txt'),
                          'proguard-rules.pro'
        }
    }
}
```

`key.properties` 가 없어도 빌드가 깨지지 않게 `exists()` 로 감싼다.
(CI에서 디버그 빌드만 돌릴 때 필요 — 06-06)

### `minifyEnabled true` 주의

난독화·tree-shaking이 켜진다. **릴리스 빌드에서만 깨지는 문제**가 생길 수 있다.
06-03에서 릴리스 APK를 실기기에서 반드시 테스트하는 이유다.

drift·sqlite3는 리플렉션을 쓰지 않아 대체로 안전하지만, 문제가 나면
`app/android/app/proguard-rules.pro` 에 keep 규칙을 추가한다.

## E. Play App Signing

Play Console에서 앱을 처음 만들 때 선택한다 (06-04).

```
Play Console → 앱 만들기 → 설정 → 앱 서명
  → "Play 앱 서명 사용" (신규 앱은 기본값이자 필수)
```

동작:

1. 우리가 **업로드 키**로 서명한 AAB를 올린다
2. 구글이 그것을 검증하고, **앱 서명 키**로 다시 서명해 배포한다
3. 앱 서명 키는 구글이 보관한다

업로드 키를 잃으면 Play Console에서 재설정을 요청할 수 있다. 앱 서명 키는 잃을 일이 없다.

## 검증

```powershell
flutter build apk --release
```

성공하면 서명 설정이 맞다.

```powershell
# 서명 확인
& "$env:ANDROID_HOME\build-tools\<버전>\apksigner.bat" verify --print-certs `
  app/build/app/outputs/flutter-apk/app-release.apk
```

인증서 주체가 C절에서 입력한 값과 같은지 확인한다.

### 저장소에 비밀이 없는지 확인 — DoD 2번

```powershell
git log -p --all | Select-String -Pattern "storePassword|keyPassword|BEGIN PRIVATE KEY|\.jks"
git ls-files | Select-String -Pattern "\.jks|\.keystore|key\.properties"
```

**둘 다 결과가 없어야 한다.** 하나라도 나오면 이미 커밋된 것이다.

이미 커밋했다면:

1. **키스토어를 폐기하고 새로 만든다.** 히스토리에서 지워도 유출된 것으로 간주한다.
2. 아직 Play에 올리기 전이면 새 키로 다시 시작하면 된다.
3. 이미 올렸다면 Play Console에서 업로드 키 재설정을 요청한다.

히스토리 정리(`git filter-repo` 등)는 **키 교체를 대신하지 않는다.**

## 막히면

- **`keytool` 을 못 찾음** → Android Studio 동봉 JDK 경로를 확인한다 (00-02에서 기록). `where.exe keytool` 로도 찾아본다.
- **Gradle이 `storeFile` 을 못 찾음** → 경로에 역슬래시가 있거나 상대경로다. 절대경로 + 슬래시로 쓴다.
- **`key.properties` 가 `.gitignore` 에 안 걸림** → 경로가 `app/android/key.properties` 인데 `.gitignore` 에는 `android/key.properties` 라고 적혀 있을 수 있다. 00-05의 패턴을 확인한다.
- **릴리스 빌드만 크래시** → `minifyEnabled` 때문이다. `--no-shrink` 로 빌드해 원인을 좁힌 뒤 keep 규칙을 추가한다. 06-03에서 다룬다.
- **비밀번호를 잊음** → 복구 방법이 없다. Play에 아직 안 올렸으면 새 키스토어를 만든다. 올렸으면 Play Console에서 업로드 키 재설정을 요청한다.
