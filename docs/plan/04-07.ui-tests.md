## A. 통합 위젯 테스트

04-02~04-06은 각자 단위 테스트를 가진다. 여기서는 **루프 전체**를 한 번에 돈다.

`app/test/ui/play_loop_test.dart`

```dart
testWidgets('홈 → 퍼즐 → 제출 → 결과 → 다음 레벨', (tester) async {
  await tester.pumpWidget(testApp(scope: fakeScope));
  await tester.pumpAndSettle();

  // 1. 홈에서 레벨 1 탭
  await tester.tap(find.text('첫걸음'));
  await tester.pumpAndSettle();
  expect(find.byType(GridView2), findsOneWidget);   // 격자 위젯

  // 2. 셀 탭 → 단어 선택 → 힌트 표시
  await tester.tapAt(cellCenter(row: 2, col: 0));
  await tester.pumpAndSettle();
  expect(find.byType(HintPanel), findsOneWidget);

  // 3. 입력
  await tester.enterText(find.byType(TextField), '사과');
  await tester.pumpAndSettle();

  // 4. 제출 → 다이얼로그 → 확인
  await tester.tap(find.text('제출'));
  await tester.pumpAndSettle();
  expect(find.textContaining('빈 칸'), findsOneWidget);
  await tester.tap(find.text('제출').last);
  await tester.pumpAndSettle();

  // 5. 결과 화면
  expect(find.byType(ResultPage), findsOneWidget);

  // 6. 다음 레벨
  await tester.tap(find.text('다음 레벨'));
  await tester.pumpAndSettle();
  expect(find.byType(PuzzlePage), findsOneWidget);
});
```

### 테스트용 `AppScope`

실 DB를 쓰면 느리고 환경 의존적이다. 가짜를 주입한다:

```dart
AppScope fakeScope() {
  final repo = InMemoryWordRepository(buildDummyDictionary(seed: 1));
  return AppScope(
    db: inMemoryDb(),                      // drift NativeDatabase.memory()
    words: repo,
    stats: StatRepository(inMemoryDb()),
    generator: GridGenerator(repo),
  );
}
```

힌트는 `sense` 가 비어 있으면 `(힌트 없음)` 이 나온다(04-03). 테스트 fixture에
몇 개 심어 두면 힌트 표시도 검증할 수 있다.

### 목록

| 테스트 | 기대 |
|---|---|
| 루프 전체 | 위 시나리오 통과 |
| 격자 탭 → 올바른 단어 선택 | 힌트 패널이 그 단어 |
| 입력 → 셀 반영 | 격자에 글자 |
| 제출 → 결과 화면 | 진입 |
| 다시 풀기 | 같은 퍼즐, 입력 초기화 |
| 잠긴 레벨 | 진입 불가 |
| 설정 → 라이선스 | 4개 자료명 표시 |
| 힌트 모드 전환 | 힌트 텍스트 변화 |
| 생성 실패 | `GenerationFailed` → 에러 화면, 크래시 없음 |

**생성 실패 테스트**를 빠뜨리지 않는다. 실패율 1% 미만이어도 100판에 1번은 난다.

## B. IME 수동 검증 (HUMAN) — 4단계 DoD 3번

> 수동: 삼성 키보드, Gboard 두 IME에서 입력 확인. 웹 Chrome 확인.

### 준비

실기기에 두 IME를 모두 설치하고 전환할 수 있게 한다.
(설정 → 일반 → 키보드 목록 및 기본값)

### 체크리스트 — **각 IME마다 전부 수행**

| # | 동작 | 기대 |
|---|---|---|
| 1 | 2글자 단어에 `사과` 입력 | 격자 두 칸에 `사`, `과` |
| 2 | 입력 중 조합 상태 관찰 | `ㅅ` 은 격자에 안 나옴, `사` 부터 나옴 |
| 3 | 3글자 단어에 4글자 입력 시도 | 4번째가 안 들어감 |
| 4 | 백스페이스로 마지막 글자 삭제 | 격자 칸이 비워짐 |
| 5 | 백스페이스로 전부 삭제 | 격자 전부 비워짐 |
| 6 | 받침 있는 글자 (`각`, `닭`) | 정상 입력 |
| 7 | 겹받침 (`읽`, `닭`) | 정상 입력 |
| 8 | 이중모음 (`과`, `웨`) | 정상 입력 |
| 9 | 입력 중 다른 단어 선택 | 조합이 확정되고 필드가 교체됨 |
| 10 | 교차 단어를 오가며 입력 | 마지막 입력이 이김, 글자 유실 없음 |
| 11 | 한/영 전환 후 영문 입력 | 격자에 안 들어감 |
| 12 | 숫자·특수문자 입력 | 격자에 안 들어감 |
| 13 | 길게 눌러 붙여넣기 (`사과나무`) | 길이만큼만 들어감 |
| 14 | 키보드 내리고 다시 올리기 | 입력 유지 |
| 15 | 앱 백그라운드 → 복귀 | 입력 유지 |

## 막히면

- **특정 IME에서 조합이 깨짐** → 04-04의 `_committed` 가 완성형만 남기므로 대부분 흡수된다. 그래도 깨지면 재현 조건(어떤 글자, 어떤 순서)을 리포트에 정확히 적고, `onChanged` 대신 컨트롤러 리스너로 바꿔 본다.
- **Gboard 예측 변환이 단어를 통째로 바꿈** → 길이 제한이 걸리므로 잘린다. 사용자 혼란이 있으면 `TextField` 에 `enableSuggestions: false`, `autocorrect: false` 를 준다.
- **붙여넣기로 길이 초과** → `_handle` 의 자르기가 동작해야 한다. 안 되면 `onChanged` 가 아니라 `inputFormatters` 로 처리한다.
- **위젯 테스트에서 `tapAt` 좌표가 안 맞음** → 격자 위젯의 실제 렌더 크기를 `tester.getRect` 로 구해 계산한다. 고정 좌표를 쓰지 않는다.
- **`pumpAndSettle` 타임아웃** → 퍼즐 생성이 Future라 끝나지 않는 경우다. 가짜 repository가 즉시 완료되는지 확인.
