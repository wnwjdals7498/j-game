## 목표

갱신의 **계약**인 `manifest.json` 형식을 확정하고, 그것을 만드는 스크립트를 쓴다.
앱(05-02)과 릴리스 절차(06-05)가 이 형식에 의존한다 (PLAN.md 3절).

## 배포처 — GitHub Releases

> 무료, 정적 URL, 파일당 2GB 한도 (REVIEW 4.2 (g), DESIGN 6절 미정 → 확정)

릴리스마다:

```
릴리스 태그: db-v{db_version}
자산:
  words-v{db_version}.sqlite
  manifest.json
```

앱이 아는 URL은 **하나**다:

```
https://github.com/<owner>/<repo>/releases/latest/download/manifest.json
```

`releases/latest/download/` 는 GitHub이 최신 릴리스로 리다이렉트해 준다.

**주의**: 앱 릴리스(`v1.0.0`)와 DB 릴리스(`db-v3`)가 같은 저장소에 섞이면
`latest` 가 앱 릴리스를 가리킬 수 있다. 두 방법:

1. DB 전용 저장소를 따로 판다 (`j-game-data`)
2. 앱 릴리스는 pre-release로 표시하지 않고, DB 릴리스만 `latest` 로 유지

**1번을 권고한다.** 분리가 명확하고 `latest` 가 꼬이지 않는다.
결정을 이 문서와 `docs/DESIGN.md` 6절에 기록한다.

## `manifest.json` 형식 (계약)

```json
{
  "db_version": 3,
  "schema_version": 1,
  "url": "https://github.com/<owner>/<repo>/releases/download/db-v3/words-v3.sqlite",
  "sha256": "a1b2c3...",
  "size_bytes": 9800000,
  "min_app_version": "1.0.0",
  "published_at": "2027-03-01",
  "word_count": 45678,
  "notes": "2027년 3월 사전 갱신"
}
```

| 필드 | 타입 | 필수 | 용도 |
|---|---|---|---|
| `db_version` | int | ✓ | 현재 DB보다 큰지 비교 (05-02) |
| `schema_version` | int | ✓ | 앱이 다룰 수 있는 스키마인지 |
| `url` | string | ✓ | DB 파일 절대 URL |
| `sha256` | string | ✓ | 무결성 검증 |
| `size_bytes` | int | ✓ | 다운로드 전 용량 안내, 검증 |
| `min_app_version` | string | ✓ | 이 DB를 쓰려면 필요한 최소 앱 버전 |
| `published_at` | string | ✓ | ISO 날짜. 표시용 |
| `word_count` | int | | sanity check (05-02) |
| `notes` | string | | 사용자 안내 문구 |

**필드를 추가할 수는 있어도 제거·의미 변경은 안 된다.** 구 앱이 파싱을 못 하게 된다.
앱은 **모르는 필드를 무시**해야 한다(05-02).

## `tools/release_db.py`

```python
"""words.sqlite -> manifest.json 생성 (+ 선택: GitHub 릴리스 업로드).

사용법:
  python tools/release_db.py --db tools/build/words.sqlite --out tools/build/release
  python tools/release_db.py ... --upload        # gh CLI로 릴리스 생성·업로드
"""
import argparse
import hashlib
import json
import shutil
import sqlite3
import subprocess
import sys
from datetime import date
from pathlib import Path

REPO = "<owner>/<repo>"          # DB 전용 저장소
MIN_APP_VERSION = "1.0.0"

def sha256_of(path: Path) -> str:
    h = hashlib.sha256()
    with path.open("rb") as f:
        for chunk in iter(lambda: f.read(1 << 20), b""):
            h.update(chunk)
    return h.hexdigest()

def read_meta(db: Path) -> dict:
    con = sqlite3.connect(f"file:{db}?mode=ro", uri=True)
    try:
        return dict(con.execute("SELECT key, value FROM meta").fetchall())
    finally:
        con.close()

def build_manifest(db: Path, out_dir: Path, notes: str = "") -> dict:
    meta = read_meta(db)
    db_version = int(meta["db_version"])
    schema_version = int(meta["schema_version"])

    out_dir.mkdir(parents=True, exist_ok=True)
    asset_name = f"words-v{db_version}.sqlite"
    asset_path = out_dir / asset_name
    shutil.copy(db, asset_path)

    manifest = {
        "db_version": db_version,
        "schema_version": schema_version,
        "url": f"https://github.com/{REPO}/releases/download/"
               f"db-v{db_version}/{asset_name}",
        "sha256": sha256_of(asset_path),
        "size_bytes": asset_path.stat().st_size,
        "min_app_version": MIN_APP_VERSION,
        "published_at": date.today().isoformat(),
        "word_count": int(meta.get("word_count", 0)),
        "notes": notes,
    }
    (out_dir / "manifest.json").write_text(
        json.dumps(manifest, ensure_ascii=False, indent=2) + "\n",
        encoding="utf-8")
    return manifest

def upload(manifest: dict, out_dir: Path) -> None:
    tag = f"db-v{manifest['db_version']}"
    subprocess.run([
        "gh", "release", "create", tag,
        str(out_dir / f"words-v{manifest['db_version']}.sqlite"),
        str(out_dir / "manifest.json"),
        "--repo", REPO,
        "--title", f"단어 DB v{manifest['db_version']}",
        "--notes", manifest["notes"] or f"db_version {manifest['db_version']}",
    ], check=True)
```

### 검증 (업로드 전)

스크립트가 릴리스를 만들기 전에 스스로 확인한다:

```python
def verify(db: Path, manifest: dict) -> list[str]:
    errors = []
    if manifest["word_count"] < 1000:
        errors.append(f"단어 수가 너무 적음: {manifest['word_count']}")
    if manifest["size_bytes"] > 50 * 1024 * 1024:
        errors.append(f"파일이 너무 큼: {manifest['size_bytes']}")
    con = sqlite3.connect(f"file:{db}?mode=ro", uri=True)
    try:
        tables = {r[0] for r in con.execute(
            "SELECT name FROM sqlite_master WHERE type='table'")}
        for t in ("word", "sense", "word_char", "word_stat", "meta"):
            if t not in tables:
                errors.append(f"테이블 없음: {t}")
        n = con.execute("SELECT COUNT(*) FROM word_stat").fetchone()[0]
        if n != 0:
            errors.append(f"word_stat이 비어 있지 않음: {n}행")
    finally:
        con.close()
    return errors
```

**`word_stat` 이 비어 있는지 확인**이 중요하다. 개발 중 쓰던 DB를 실수로 배포하면
전 사용자에게 개발자의 통계가 덮어씌워진다. 실제로는 05-03이 보존하므로 덮이진 않지만,
시드 DB에 남은 값은 오염이다.

### `db_version` 올리기

`config.DB_VERSION`(02-02)을 갱신마다 +1 한다. 릴리스 스크립트가 아니라 **ETL이 소유**한다.
`release_db.py` 는 DB의 `meta` 에서 읽기만 한다.

`db_version` 을 안 올리고 릴리스하면 앱이 "이미 최신" 이라 판단해 받지 않는다.
스크립트가 경고한다:

```python
if db_version == previous_released_version:
    print("⚠ db_version이 이전 릴리스와 같습니다. config.DB_VERSION을 올리세요.")
```
