## 목표

코어 배치(01-04) + 채움(01-06)을 묶어 `Puzzle` 하나를 만든다. 실패 시 seed를 바꿔 재시도하고,
`maxAttempts` 를 넘으면 `GenerationFailed` 를 던진다. **결정성**을 이 파일이 최종 보증한다.

```dart
import 'dart:math';
import '../model/level_spec.dart';
import '../model/puzzle.dart';
import '../repository/word_repository.dart';
import 'core_placer.dart';
import 'filler.dart';
import 'grid.dart';
import 'grid_rules.dart';

/// 생성 1회의 계측치. 01-10 하네스와 03-05가 쓴다.
class GenerationStats {
  final int attempts;
  final int totalBacktracks;
  final int totalQueries;
  final Duration elapsed;
  final bool success;
  final String? failReason;

  const GenerationStats({
    required this.attempts,
    required this.totalBacktracks,
    required this.totalQueries,
    required this.elapsed,
    required this.success,
    this.failReason,
  });
}

class GenerationOutcome {
  final Puzzle? puzzle;
  final GenerationStats stats;
  const GenerationOutcome(this.puzzle, this.stats);
}

class GridGenerator {
  final WordRepository repo;
  const GridGenerator(this.repo);

  /// 실패 시 [GenerationFailed] 를 던진다. 게임 코드가 쓰는 API.
  Future<Puzzle> generate(LevelSpec spec, int seed) async {
    final o = await tryGenerate(spec, seed);
    final p = o.puzzle;
    if (p == null) {
      throw GenerationFailed(spec.id, o.stats.attempts,
          o.stats.failReason ?? 'unknown');
    }
    return p;
  }

  /// 예외 없이 결과+계측을 돌려준다. 하네스(01-10, 03-05)가 쓰는 API.
  Future<GenerationOutcome> tryGenerate(LevelSpec spec, int seed) async {
    final sw = Stopwatch()..start();
    var backtracks = 0;
    var queries = 0;
    String? lastFail;

    for (var attempt = 1; attempt <= spec.maxAttempts; attempt++) {
      final attemptSeed = seed + attempt - 1;
      final rnd = Random(attemptSeed);

      final g = MutableGrid(spec.width, spec.height);

      final cands = await repo.coreCandidates(
        tier: spec.coreTier,
        count: spec.coreCount,
        seed: attemptSeed,
      );

      final core = CorePlacer.place(g, spec, cands, rnd);
      if (core == null) { lastFail = 'core placement failed'; continue; }

      final filler = Filler(g, spec, repo, rnd);
      final fs = await filler.run();
      backtracks += fs.backtracks;
      queries += fs.queries;
      if (!fs.success) { lastFail = 'fill failed (quota unmet)'; continue; }

      final errors = GridRules.validate(g, allowIsolated: spec.allowIsolated);
      if (errors.isNotEmpty) {
        // 여기 걸리면 생성기 버그다. 조용히 재시도하지 말고 남긴다.
        assert(false, 'validate failed: ${errors.join("; ")}');
        lastFail = 'validate: ${errors.first}';
        continue;
      }

      sw.stop();
      return GenerationOutcome(
        g.toPuzzle(levelId: spec.id, seed: attemptSeed, attempts: attempt),
        GenerationStats(
          attempts: attempt,
          totalBacktracks: backtracks,
          totalQueries: queries,
          elapsed: sw.elapsed,
          success: true,
        ),
      );
    }

    sw.stop();
    return GenerationOutcome(
      null,
      GenerationStats(
        attempts: spec.maxAttempts,
        totalBacktracks: backtracks,
        totalQueries: queries,
        elapsed: sw.elapsed,
        success: false,
        failReason: lastFail,
      ),
    );
  }
}
```

### 설계 결정

- **매 시도마다 새 `MutableGrid`.** 01-06의 복원이 완벽해도, 새로 만드는 쪽이 재시도 간 오염 가능성이 0이다. 비용은 작다.
- **`attemptSeed = seed + attempt - 1`.** 첫 시도 seed가 입력 seed와 같아야 `generate(spec, 7)` 이 예측 가능하다.
- **`Random` 인스턴스 1개를 코어·채움이 공유.** 새로 만들면 두 단계의 랜덤이 상관되어 다양성이 떨어진다.
- **`validate` 실패는 버그.** `assert` 로 디버그 빌드에서 터뜨린다. release에서는 재시도로 넘어간다.
- **`Puzzle.seed` 는 `attemptSeed`.** 이 값으로 재생성하면 1회 시도에 같은 퍼즐이 나온다.

## 테스트

`app/test/domain/grid_generator_test.dart`

| 테스트 | 기대 |
|---|---|
| 기본 생성 성공 | `Puzzle` 반환, `words.length >= spec.minWordCount` |
| 결정성 | `generate(spec, 7)` 두 번 → 격자 셀·단어 리스트 완전 동일 |
| seed가 다르면 결과가 다름 | 10개 seed 중 최소 8개가 서로 다른 격자 |
| `validate` 통과 | 생성된 모든 퍼즐에 대해 errors 비어 있음 |
| 코어 개수 | `puzzle.cores.length == spec.coreCount` |
| 코어 티어 | 모든 코어가 `spec.coreTier` |
| 채움 할당량 | 티어별 개수가 `[min, max]` 안 |
| `Puzzle.seed` 재현 | `generate(spec, p.seed)` → 같은 퍼즐 |
| 실패 시 예외 | 불가능한 스펙(3×3에 코어 5개) → `GenerationFailed` |
| `tryGenerate` 는 예외 없음 | 같은 스펙에 `puzzle == null`, `stats.success == false` |
| `wordsAt` 동작 | 교차 셀에서 단어 2개 반환 |

String fingerprint(Puzzle p) {
  final grid = p.cells
      .map((row) => row.map((c) => c.solution ?? '.').join())
      .join('/');
  final words = (p.words
        .map((w) => '${w.headword}@${w.row},${w.col},${w.dir.name},${w.isCore}')
        .toList()
        ..sort())
      .join('|');
  return '$grid#$words';
}

## 막히면

- **결정성 깨짐** → 원인은 거의 항상 셋 중 하나다. (a) `Set`/`Map` 순회 순서에 의존, (b) 어딘가 `Random()` 무인자 생성, (c) `List.shuffle()` 을 인자 없이 호출. `Select-String -Pattern "Random\(\)|shuffle\(\)"` 로 전수 확인.
- **`assert(false, validate failed)` 가 터짐** → 01-03으로 돌아간다. **`validate` 를 끄지 않는다.** 이 assert가 1단계 전체의 안전망이다.
- **성공은 하는데 느림** → 01-10에서 측정한 뒤 판단한다. 여기서 추측 최적화하지 않는다.
- **`maxAttempts` 를 늘리면 통과함** → 실패율을 숫자로 가린 것뿐이다. 01-09/01-10에서 스펙을 고쳐 근본 해결한다. `maxAttempts` 는 20을 상한으로 둔다.
