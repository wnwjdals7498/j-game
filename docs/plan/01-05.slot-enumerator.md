# 01-05. 채움 슬롯 열거 (slot_enumerator)

담당: **AGENT**
선행: 01-04 · 다음: 01-06
상위: [01-domain-map-generator.md](01-domain-map-generator.md) 알고리즘 2번 앞부분

## 목표

코어가 놓인 격자에서 **채움 단어를 넣을 수 있는 자리(슬롯)** 를 전부 찾아낸다.
채움 로직(01-06)과 분리하는 이유: 슬롯 계산은 순수 기하 문제라 단독 테스트가 쉽고,
백트래킹 중 반복 호출되므로 성능 튜닝 지점이 여기로 모인다.

## 슬롯이란

`Slot` = (시작 좌표, 방향, 길이) + 그 구간에 **이미 채워진 칸의 음절 제약**.
슬롯의 제약이 `findByPattern` 의 `fixed` 인자가 된다.

조건:

1. 길이 2~5.
2. 구간 전체가 격자 안.
3. 진행 방향 앞뒤 끝막음 칸이 비었거나 격자 밖. (01-03 규칙 2)
4. 구간 안에 **채워진 칸이 1개 이상** 있어야 한다.
   → 채움 단어는 항상 기존 단어와 교차한다. 고립 슬롯은 코어 단계에서만 쓴다(01-04).
5. 구간 안 **빈 칸**들은 각각 수직 이웃이 비어 있어야 한다. (규칙 2 — 새 연속 방지)
6. 구간 안에 **완전히 채워진 상태**(빈 칸 0개)면 슬롯이 아니다. 넣을 게 없다.

조건 3·5·6은 `GridRules.canPlace` 가 최종적으로 다시 검사하므로 여기서는 **후보를 줄이는 필터**다.
빠뜨려도 정답은 나오지만 백트래킹이 늘어난다. 조건 4는 여기서만 강제한다.

import '../model/puzzle.dart';
import 'grid.dart';
import 'grid_rules.dart';

class Slot {
  final int row;
  final int col;
  final Direction dir;
  final int length;
  final Map<int, String> fixed;   // 자리 index -> 이미 채워진 음절
  final int crossings;            // fixed.length. 정렬 키로 씀

  Slot({
    required this.row,
    required this.col,
    required this.dir,
    required this.length,
    required this.fixed,
  }) : crossings = fixed.length;

  int get emptyCount => length - crossings;

  String get key => '${dir.name}:$row:$col:$length';

  @override
  bool operator ==(Object other) => other is Slot && other.key == key;
  @override
  int get hashCode => key.hashCode;
}

class SlotEnumerator {
  /// [g]에서 채울 수 있는 슬롯 전부.
  /// 반환 순서는 **결정적**이어야 한다: (dir, row, col, length) 오름차순.
  static List<Slot> enumerate(MutableGrid g) { ... }
}

### `enumerate` 구현

```dart
final out = <Slot>[];
for (final dir in Direction.values) {
  final maxR = g.height, maxC = g.width;
  for (var r = 0; r < maxR; r++) {
    for (var c = 0; c < maxC; c++) {
      for (var len = 2; len <= 5; len++) {
        final dr = dir == Direction.down ? 1 : 0;
        final dc = dir == Direction.across ? 1 : 0;
        final rEnd = r + dr * (len - 1);
        final cEnd = c + dc * (len - 1);
        if (!g.inBounds(rEnd, cEnd)) continue;

        // 끝막음 (조건 3)
        if (!_emptyOrOutside(g, r - dr, c - dc)) continue;
        if (!_emptyOrOutside(g, rEnd + dr, cEnd + dc)) continue;

        final fixed = <int, String>{};
        var ok = true;
        for (var i = 0; i < len; i++) {
          final rr = r + dr * i, cc = c + dc * i;
          final s = g.at(rr, cc);
          if (s != null) {
            fixed[i] = s;
          } else {
            // 빈 칸의 수직 이웃 (조건 5)
            if (!_emptyOrOutside(g, rr - dc, cc - dr) ||
                !_emptyOrOutside(g, rr + dc, cc + dr)) { ok = false; break; }
          }
        }
        if (!ok) continue;
        if (fixed.isEmpty) continue;          // 조건 4
        if (fixed.length == len) continue;    // 조건 6

        out.add(Slot(row: r, col: c, dir: dir, length: len, fixed: fixed));
      }
    }
  }
}
return out;  // 루프 순서가 이미 (dir, row, col, length) 오름차순
```

### 슬롯 우선순위 — 01-06이 쓰는 정렬

백트래킹 효율은 **"제약이 많은 슬롯부터"** 채울 때 가장 좋다 (MRV 휴리스틱).

```dart
  /// 제약 강한 순: 교차 많은 것 → 짧은 것 → 안정적 key 순
  static int compareByConstraint(Slot a, Slot b) {
    if (a.crossings != b.crossings) return b.crossings.compareTo(a.crossings);
    if (a.length != b.length) return a.length.compareTo(b.length);
    return a.key.compareTo(b.key);
  }
```

이 정렬은 **결정적**이다. 랜덤은 슬롯 선택이 아니라 **단어 선택**에서만 쓴다(01-06).

| 테스트 | 시나리오 | 기대 |
|---|---|---|
| 빈 격자 | 5×5, 배치 0 | 슬롯 0개 (조건 4) |
| 단어 1개 | `사과` across (2,0) | 각 코어 셀을 지나는 세로 슬롯들이 나옴 |
| 모든 슬롯이 배치 가능 | 각 슬롯에 대해 길이 맞는 더미 단어를 찾아 `canPlace` | 전부 true |
| 꽉 찬 구간 제외 | 교차로 완전히 채워진 2칸 구간 | 슬롯에 없음 |
| 끝막음 위반 제외 | 끝에 인접 글자가 있는 구간 | 슬롯에 없음 |
| 결정성 | 두 번 호출 | 같은 순서의 같은 리스트 |
| 정렬 | `compareByConstraint` 적용 | 교차 많은 것이 앞 |
| fixed 내용 | 교차 셀 index/음절 | 격자 값과 일치 |

## 막히면

- **슬롯은 났는데 `canPlace` 가 거부** → 조건 3 또는 5 구현이 `canPlace` 와 어긋났다. 두 코드의 이웃 좌표식을 나란히 놓고 비교한다. 같은 헬퍼(`_emptyOrOutside`)를 `GridRules` 에서 `static` 공개해 공유하는 게 안전하다.
- **8×8에서 열거가 느림** → 8×8×2방향×4길이 = 512회 루프. 느릴 수 없다. 느리면 루프 안에서 `g.placedWords` 같은 O(n) 연산을 부르고 있다.
- **슬롯이 너무 많아 백트래킹이 폭발** → 열거 문제가 아니라 할당량 문제(01-09). 여기서 슬롯을 임의로 줄이지 않는다.
