# 04-03. 단어 선택 · 힌트 패널

담당: **AGENT**
선행: 04-02 · 다음: 04-04
상위: [04-ui.md](04-ui.md) "선택", "힌트"

## 목표

셀을 탭하면 그 셀을 지나는 단어 하나를 고르고, 그 단어의 힌트를 보여준다.

## 선택 규칙

> 셀 탭 → 그 셀을 지나는 단어 중 하나 선택(가로 우선, 다시 탭하면 세로).
> 선택 단어 전체가 하이라이트. 힌트 패널에 그 단어의 힌트 표시.

```dart
void selectCell(int r, int c) {
  final here = puzzle!.wordsAt(r, c);      // 01-01 Puzzle.wordsAt
  if (here.isEmpty) return;

  if (here.length == 1) {
    selected = here.first;
  } else {
    // 교차 셀. 현재 선택이 이 셀의 단어 중 하나면 다음 것으로 토글
    final i = here.indexWhere((w) => _same(w, selected));
    if (i >= 0) {
      selected = here[(i + 1) % here.length];
    } else {
      // 가로 우선
      selected = here.firstWhere((w) => w.dir == Direction.across,
          orElse: () => here.first);
    }
  }
  focusedCell = (r, c);
  notifyListeners();
}

bool _same(PlacedWord a, PlacedWord? b) =>
    b != null && a.row == b.row && a.col == b.col && a.dir == b.dir;
```

**`PlacedWord` 는 `==` 를 재정의하지 않았다**(01-01). 위치+방향으로 비교하는 `_same` 헬퍼를 쓴다.
같은 표제어가 한 격자에 두 번 안 나오므로(01-03 규칙 6) `headword` 비교도 되지만,
위치 비교가 더 명시적이다.

`focusedCell` 은 04-04의 입력 커서 위치 표시에 쓴다.

## 힌트

> 기본 뜻풀이. 설정에서 "연상어 모드"를 켜면 유의어 있는 단어는 유의어 노출, 없으면 뜻풀이로 폴백.
> 코어/채움 구분 없이 동일.

### 힌트 데이터 조회

`sense` 테이블에서 읽는다. **퍼즐 생성 직후 한 번에 다 읽어 캐시한다** — 탭할 때마다 DB를 치면 느리다.

```dart
// app/lib/data/hint_repository.dart
class HintRepository {
  final AppDatabase _db;

  /// 퍼즐의 모든 단어 힌트를 한 번에.
  Future<Map<String, Hint>> forWords(List<String> headwords) async {
    final placeholders = List.filled(headwords.length, '?').join(',');
    final rows = await _db.customSelect(
      'SELECT headword, definition, synonyms FROM sense '
      'WHERE headword IN ($placeholders)',
      variables: headwords.map(Variable.withString).toList(),
    ).get();
    return { for (final r in rows) r.read<String>('headword'): Hint(...) };
  }
}

class Hint {
  final String definition;
  final List<String> synonyms;

  const Hint(this.definition, this.synonyms);

  bool get hasSynonyms => synonyms.isNotEmpty;
}
```

단어가 20~30개라 `IN (...)` 목록이 짧다. 문제없다.

### 힌트 선택

```dart
String hintTextFor(PlacedWord w, HintMode mode) {
  final h = hints[w.headword];
  if (h == null) return '(힌트 없음)';
  if (mode == HintMode.association && h.hasSynonyms) {
    return h.synonyms.join(', ');
  }
  return h.definition;
}
```

`HintMode` 는 `SettingsModel`(04-01)에 있다.

### 힌트에 답이 새면 안 된다

뜻풀이에 표제어 자체가 들어 있는 경우가 흔하다 (`사과: 사과나무의 열매`).
**표제어를 마스킹한다:**

```dart
String _mask(String definition, String headword) =>
    definition.replaceAll(headword, '○' * headword.length);
```

02단계에서 미리 마스킹하지 않는 이유: DB는 원본을 보존하고, 표시할 때 가린다.
나중에 규칙이 바뀌어도 DB 재빌드가 필요 없다.

## 힌트 패널 UI

퍼즐 화면 하단, 입력 필드 위.

```
┌────────────────────────────┐
│ 가로 3   ● 코어   3글자      │   ← 방향/번호/코어 여부/길이
│ 사과나무의 열매.             │   ← 힌트 본문
└────────────────────────────┘
```

| 요소 | 내용 |
|---|---|
| 방향 | `가로` / `세로` |
| 번호 | 격자에서 시작 위치 기준 번호 (신문 낱말퍼즐처럼). 없어도 되지만 있으면 읽기 쉽다 |
| 코어 표시 | 코어면 점·배지. 유저에게 "이건 복습 단어" 를 알릴 필요는 없으니 **생략 가능** |
| 길이 | `3글자` |
| 힌트 본문 | 위 규칙대로. 2~3줄까지, 넘으면 스크롤 |

미선택 상태: "칸을 눌러 단어를 고르세요".

**코어 표시를 넣을지 결정한다.** 넣으면 유저가 코어에 집중하지만, "이건 네가 틀렸던 단어" 라는
정보가 노출된다. 1차는 **넣지 않는다** 로 하고 이 문서에 기록한다.

## 단어 번호 매기기

낱말퍼즐 관례: 격자를 위→아래, 왼→오른쪽으로 훑으며 **단어가 시작하는 셀**에 번호를 매긴다.
같은 셀에서 가로·세로가 동시에 시작하면 같은 번호를 공유한다.

```dart
Map<(int, int), int> numberCells(Puzzle p) {
  final starts = <(int, int)>{ for (final w in p.words) (w.row, w.col) };
  final sorted = starts.toList()
    ..sort((a, b) => a.$1 != b.$1 ? a.$1.compareTo(b.$1) : a.$2.compareTo(b.$2));
  return { for (var i = 0; i < sorted.length; i++) sorted[i]: i + 1 };
}
```

번호를 격자 셀 좌상단에 작게 그린다 (04-02의 `GridPainter` 에 추가).

## 막히면

- **교차 셀 토글이 안 됨** → `_same` 이 `==` 로 비교하고 있다. `PlacedWord` 는 `==` 재정의가 없어 항상 false다.
- **힌트가 비어 있음** → `sense` 테이블에 해당 표제어가 없다. 02-07의 merge에서 senses가 잘렸을 수 있다. `word` 에는 있는데 `sense` 에 없는 단어 수를 세어 본다 — 0이어야 한다(02-09 FK 테스트).
- **마스킹 후 힌트가 `○○의 ○○`** → 뜻풀이가 표제어로만 이루어진 경우다. 드물지만 생긴다. 그런 단어는 힌트가 무의미하므로 02-10 눈 검수에 항목을 추가한다.
- **번호가 너무 작아 안 보임** → 셀 크기의 22% 정도. 그래도 안 보이면 번호를 격자에서 빼고 힌트 패널에만 표시한다.
- **연상어 모드에서 유의어가 거의 없음** → 02-07 "막히면" 절 참고. 기초사전 관계 정보 파싱이 안 됐을 수 있다. 폴백이 동작하면 기능상 문제는 없다.
